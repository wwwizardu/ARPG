# 방어구와 장신구의 성장 구간 설계

> 상태: 현행 목록·부위별 역할·기존 장비 배치와 보강 후보, 방어구·보조 장비·장신구 기본 성능표·전체 옵션 예산·대표 구성 성장 비교 초안, 구현 전
> 정리일: 2026-10-05
> 갱신일: 2026-10-06 — 비무기 성장 시나리오·교체/옵션 연결 점검
> 근거: 사용자는 무기 설계에 이어 방어구·장신구의 목록·역할·성장 구간 배치, 방어구·보조 장비·목걸이·반지의 기본 성능과 전체 옵션 합산 비교 설계를 요청했다. 구현과 상세 골드 비용·수급은 이후 단계로 남겨둔다.

무기와 같은 DropLevel 1·10·20을 비교 기준으로 삼아 방어구·장신구의 교체 흐름을 정리한다. 현재 무기 외 장비 32종을 보존하면서 부위별 역할·성장 기본값·장착 구성과 전체 옵션 예산을 비교하는 초안이다. 코드·게임 테이블·아이템 ID·저장 데이터·드랍·상점을 변경한 결과가 아니다.

## 부위별 역할 초안

초기에는 공용 방어구 성장 라인을 사용하고 공격·주문 빌드 모두 착용하도록 제안한다. 직업 제한이나 중갑·경갑·로브별 독립적인 성장 라인을 새로 만들지 않는다. 기존 마법사 장비와 강화가죽 장비는 같은 구간의 선택지로 남기고, 기본 방어력·체력과 선택 옵션의 예산을 함께 비교한다. 같은 성능 예산은 모든 아이템의 실제 능력이 같다는 뜻이 아니며 교환되는 능력의 가치 비교가 필요하다.

| 부위·계열 | 주된 성장 역할 | 선택 옵션 방향 | 초기 구분 |
| --- | --- | --- | --- |
| 투구 | 방어력과 체력으로 기본 생존 보조 | 최대 마나·마나 재생·저항 | 갑옷보다 작은 방어 예산 |
| 갑옷 | 가장 큰 기본 방어력·체력 예산 | 체력 재생·마나·저항 | 장비 교체의 핵심 생존 성장 |
| 장갑 | 작은 기본 생존과 공격·주문 운용 보조 | 치명타 피해 또는 시전 속도 | 빌드에 맞는 옵션 선택 |
| 장화 | 기본 생존과 기동성 | 이동 속도·저항 | 신속 계열의 속도 특성은 고정 옵션 도입 여부를 별도 검토 |
| 허리띠 | 체력 중심의 생존·회복 보조 | 체력 재생·마나 재생·저항 | 코드 분류는 방어구 유지 |
| 목걸이 | 작은 기본 체력과 자원·주문 운용 보조 | 최대 마나·재생·시전 속도·저항 | 공격 빌드도 사용할 수 있는 자원 역할 |
| 반지 | 작은 기본 체력과 빌드 보정 | 치명타 피해·시전 속도·재생·저항 | 두 슬롯으로 다른 부족한 능력을 채움 |
| 방패 | 추가 방어력과 막기 특성 유지 | 체력·저항 | 한손 무기와 함께 사용하는 방어 선택 |
| 마법서 | 마나·재생과 주문 운용 보조 | 작은 고정 시전 속도, 추가 주문 피해 없는 초안 | 한손 완드와 함께 사용하는 주문 선택 |

이 역할은 전체 방향의 제안이며 모든 부위에 모든 옵션을 고정으로 넣는 결정은 아니다. 현행 옵션 자격에서 최대 마나 1200·체력 재생 1201·마나 재생 1202·저항 1203~1206은 AllArmor·AllJewelry에 허용된다. 치명타 피해 1207은 Weapon·Gloves·AllJewelry, 시전 속도 1208은 Shield·Gloves·AllJewelry, 이동 속도 1004는 Boots에 허용된다. 현재 장착 가능한 랜덤 옵션을 먼저 사용하고 고정 Implicit을 도입할 경우 별도 Mod·ItemImplicit 행과 예산을 설계한다. 기존 Prefix/Postfix 행의 슬롯을 임의로 바꿔 고정 옵션으로 사용하는 계획은 아니다. [src: Assets/_BinaryData/TableData/ModTable.bytes, Assets/Scripts/Item/ItemEnchantmentService.cs]

방패와 마법서는 현행 Shield 분류를 공유하지만 용도는 별개로 설계한다. 마법서가 방패 분류라는 이유로 막기 확률을 기본 제공하지 않으며, 하위 유형·옵션 후보 표현은 구현 전 후속 결정이다. 지팡이는 양손이므로 마법서와 동시에 사용할 수 없다. 아래에서 마법서의 마나 지속·시전 효율을 완드 쌍수·지팡이와 비교해 피해·자원·생존의 선택을 제안한다.

귀걸이는 현행 아이템이 없어 초기 설계의 필수 보강 목록에서 제외한다. 도입할 때는 역할과 성장 라인을 함께 마련하고, 반지 두 슬롯과 귀걸이 두 슬롯의 옵션 합산을 고려해 예산을 정한다.

### 기본 능력과 옵션의 계산 경계

무기 Base와 달리 방어구·장신구의 Base는 현행 장착 경로에서 캐릭터 Modifier로 적용된다. 비무기 장비의 치명타 Base도 글로벌 고정 치명타 추가분이고 무기 기본 치명타 평균의 대상이 아니다. Implicit·Prefix·Postfix의 글로벌 합산 책임은 유지한다. 반지 두 개·장갑·목걸이 등의 옵션을 쌍수 피해 계수 0.7로 줄이거나 두 슬롯의 평균으로 처리하지 않는다. [src: Assets/Scripts/Common/Utility/EquipHelper.cs ApplyEquipmentModifiers·ApplyPassiveMod, Assets/Scripts/Skill/Combat/SkillOffensiveStatResolver.cs, Docs/combat/combatSystem.md §장비 옵션 책임 경계]

부위의 생존 기본값은 Base, 이름에 따른 고정 특성은 도입 시 Implicit, 랜덤 선택지는 Prefix/Postfix로 구분하는 방향을 제안한다. 목걸이·반지는 아래 초안으로 고정 특성을 정리하고, 장갑·기존 변형의 치명타 유지·이동은 후속 설계에서 정한다. 방패·마법서는 비무기 보조 장비이므로 무기 도달거리 평균에 1.0짜리 무기로 끼워 넣지 않고 장착한 한손 무기의 배율을 사용한다. [src: Docs/combat/WEAPON_PROGRESSION_DESIGN.md §쌍수 계산 초기안·§무기별 스킬 호환과 범위 적용 설계]

## 현행 교체 흐름의 문제

- 목재 방패 18에는 막기 +20%p·방어도 10이 있지만 철 방패 34와 강철 대방패 57에는 막기 기본값이 없다. 방패 성능을 방어도만 높여 배치하면 상위 교체 때 막기 특성을 잃는다. 세 구간 모두 막기 특성을 유지하도록 재설계하는 안이다. 현행 막기는 성공 시 피해 일부를 줄이며 감소율이 0이면 50%를 사용한다. - 강화가죽 갑옷 28은 철 갑옷 27과 체력 15가 같지만 방어도가 4와 8로 다르다. 마법사 로브 48도 강철 판금갑옷 47과 체력 30이 같고 방어도가 8과 14다. 이 Base만 보면 낮은 방어 쪽이 손해이고 주문 자원·시전 특성은 없다. 외형·랜덤 옵션 차이만으로 충분한지, 고정 특성으로 교환 예산을 줄지 검토한다. [src: Assets/_BinaryData/TableData/EquipmentBaseStatTable.bytes, Assets/_BinaryData/TableData/ItemImplicitTable.bytes]
- 신속의 부츠 52는 체력 30·방어도 8이며 고정 이동 속도가 없다. 이동 속도는 랜덤 Postfix 1004 또는 BasicItem 523에서 제공될 수 있지만 일반 장화에도 같은 옵션이 가능하다. 따라서 현재 이름만으로 신속 계열의 고유 성능이 보장되지는 않는다. [src: Assets/_BinaryData/TableData/EquipmentBaseStatTable.bytes, Assets/_BinaryData/TableData/ModTable.bytes, Assets/_BinaryData/TableData/BasicItemTable.bytes]
- 마법사 두건 46·마력 장갑 50·마력 허리띠 54·상급 마법서 58은 체력·치명타 Base가 중심이다. 최대 마나·마나 재생·고정 시전 속도 같은 주문 운용 특성은 Base·Implicit에 없다. 이름과 역할을 연결할 고정 특성 도입 여부를 별도로 정한다. [src: Assets/_BinaryData/TableData/EquipmentBaseStatTable.bytes, Assets/_BinaryData/TableData/ItemImplicitTable.bytes]
- 목걸이는 구리 단계에서 체력, 은 단계에서 체력·치명타, 금 단계에서 체력·방어도로 구성이 바뀐다. 반지도 구리의 치명타가 은 단계에서 방어도로 바뀌었다가 후반에 돌아온다. 특정 능력을 사용하는 빌드가 교체 때 그 능력을 잃지 않도록 공통 기본값과 선택 특성을 나누는 안이다. [src: Assets/_BinaryData/TableData/EquipmentBaseStatTable.bytes]

위 문제는 현행 고정 능력과 역할의 대조이며 실제 랜덤 옵션까지 포함한 모든 아이템이 열등하다는 판정은 아니다. 이번 작업은 문제를 기록하고 설계 방향을 제안하는 범위이며 데이터를 수정하지 않았다.

## 성장 구간과 기존 아이템 배치 초안

사용자 결정으로 기본 교체점은 DropLevel 1·10·20만 사용한다. Tier 1·2·3을 각각 대응하고 구간 사이는 강화로 보완한다. DropLevel은 몬스터 레벨에 따른 드랍 후보 진입 조건이며 플레이어 장착 요구 레벨이나 게임 전체의 마지막 성장 구간이 아니다. 이번에는 기존 32종의 Tier·DropLevel과 이름을 옮기지 않고 같은 구간에 유지하는 안이다. [src: Docs/combat/WEAPON_PROGRESSION_DESIGN.md §구간 기준과 배치 원칙, Assets/Scripts/Common/Utility/DropPoolBuilder.cs]

### 부위별 기본 교체 순서

괄호는 기존 ItemId다. 신규는 이번 추가 대상으로 정한 낡은 보조 마법서 1종이며 실제 ItemId·아트·테이블 반영은 이후에 진행한다. 초급 마법서 44는 기본 능력 보강이 필요한 기존 행이다.

| 성장 라인 | DropLevel 1 / Tier 1 | DropLevel 10 / Tier 2 | DropLevel 20 / Tier 3 |
| --- | --- | --- | --- |
| 투구 | 가죽 두건(11) | 철 투구(26) | 강철 전투 투구(45) |
| 갑옷 | 가죽 조끼(12) | 철 갑옷(27) | 강철 판금갑옷(47) |
| 장갑 | 가죽 장갑(13) | 철 건틀릿(29) | 미스릴 건틀릿(49) |
| 장화 | 가죽 장화(14) | 강화가죽 부츠(30) | 미스릴 부츠(51) |
| 허리띠 | 천 허리띠(15) | 가죽 전투벨트(31) | 전투 허리띠(53) |
| 목걸이 | 구리 목걸이(16) | 은 목걸이(32) | 금 목걸이(55) |
| 반지 | 구리 반지(17) | 은 반지(33) | 마력석 반지(56) |
| 방패 | 목재 방패(18) | 철 방패(34) | 강철 대방패(57) |

9라인×3구간의 기본 장비 27칸은 기존 26종+신규 1종으로 채운다. 기존 변형 6종은 별도 선택지로 보존해 비무기는 33종의 지원 계획이다. 중간 교체점용 후보 18종은 추가 목록에서 제외한다.

### 기존 변형의 유지

| ItemId | 아이템 | 기존 Tier / DropLevel | 비교할 대표 장비 | 제안 용도 |
| --- | --- | --- | --- | --- |
| 28 | 강화가죽 갑옷 | 2 / 10 | 철 갑옷 27 | 같은 구간의 방어·체력 분배 또는 고정 특성 선택 |
| 46 | 마법사 두건 | 3 / 20 | 강철 전투 투구 45 | 주문 운용 선택지 후보 |
| 48 | 마법사 로브 | 3 / 20 | 강철 판금갑옷 47 | 주문 운용 선택지 후보 |
| 50 | 마력 장갑 | 3 / 20 | 미스릴 건틀릿 49 | 주문 운용 선택지 후보 |
| 52 | 신속의 부츠 | 3 / 20 | 미스릴 부츠 51 | 기동성 선택지 후보 |
| 54 | 마력 허리띠 | 3 / 20 | 전투 허리띠 53 | 자원·회복 선택지 후보 |

변형을 특정 빌드의 필수 계열로 만들지는 않는 초기안이다. 캐스터도 공용 기본 방어구와 해당 부위의 허용 옵션으로 성장할 수 있어야 한다. 추후 로브·신속 장비 등을 독립 성장 계열로 확정하면 해당 계열의 하위 구간 장비도 함께 설계한다. 같은 구간 변형의 드랍은 행마다 대표 장비와 같은 가중치를 중복 부여하기보다 해당 부위·구간 예산을 나누는 방향으로 제안한다. 실제 DropRate는 공급 설계에서 정한다.

### 보강 우선순위

추가 비무기는 시작 구간의 **낡은 보조 마법서 1종**으로 정한다. 스킬북이 아닌 왼손 보조 장비이며 최대 마나 +50·초당 마나 재생 +2·고정 시전 속도 +5%의 기존 초안을 사용한다. 기본 체력·방어도·막기·주문 피해 증가는 이 대표 마법서 안에 추가하지 않는다.

초급 마법서(44)는 기존 ItemId를 유지하고 중반 목표인 최대 마나 +100·재생 +4/초·시전 속도 +8%와 BasicItem 연결을 보강하는 대상이다. 별도의 새 중반 아이템을 추가하는 작업은 아니다. 세 구간의 다른 방어구·장신구·방패·상급 마법서는 기존 장비를 사용한다.

신규 방어구·장신구·방패·귀걸이를 이번에 추가하지 않는다. 기존 방어구 변형 6종의 고정 특성과 공용 장갑 치명타는 계속 보류한다. 전체 추가 장비 5종과 구현 순서는 [추가할 장비 목록](WEAPON_PROGRESSION_DESIGN.md#세-구간-장비-구성과-추가할-장비)을 따른다.

## 기본 성능과 옵션 설계의 기준

아래에서 방어구 5부위의 Base 방어력·체력 배분, 방패의 생존·막기, 보조 마법서와 목걸이의 마나, 반지의 치명타와 전체 옵션 합산을 1·10·20에서 비교한다. 갑옷을 5부위 중 가장 큰 생존 예산으로 두고 다른 부위는 역할에 맞는 비중으로 배치한다. 기존 방어구 변형과 장갑 치명타의 최종 배분은 후속 작업에서 정한다. 새 수치는 구현 전에 비교할 초안이다.

현행 물리 감소는 방어도 / (방어도 + 10×받는 물리 피해)이며 저항은 속성별 상한을 적용한다. 방어구 EHP 기여의 DropLevel당 1.10은 기존 밸런스 문서의 목표값이지 방어도·체력·모든 확률 값을 각각 1.10배 하면 EHP가 같은 배율로 늘어난다는 규칙이 아니다. 대표 피격 피해와 캐릭터 기본 체력·성장, 장비 전체 합계를 정한 뒤 작은 물리 타격·큰 물리 타격·원소 피해를 따로 비교한다. 무기 피해용 1.13 곡선을 그대로 복사하지 않는다. [src: Docs/combat/BALANCE_DESIGN.md §3.2·§4.2·§4.3, Assets/Scripts/Common/BalanceConstants.cs, Assets/Scripts/Skill/Combat/DamageCalculator.cs GetArmorReduction·GetResistanceReduction]

체력·방어도 같은 고정값과 치명타·막기·시전·이동·저항 같은 확률·비율은 다른 성장 예산을 사용한다. 특히 반지 두 개와 다른 부위의 글로벌 치명타·시전 속도를 합산하고, 저항 상한·막기 피해 감소와 옵션의 고정/증가 구분을 반영한다. 장신구의 공격용 추가 피해와 주문용 옵션을 같은 피해 항으로 처리하지 않는다. 현행 추가 속성 피해 옵션의 Attack 태그와 무기 성장 문서의 주문 계산 경계를 유지한다. [src: Assets/_BinaryData/TableData/ModTable.bytes, Assets/Scripts/Common/Utility/EquipHelper.cs, Assets/Scripts/Skill/Combat/SkillOffensiveStatResolver.cs, Docs/combat/WEAPON_PROGRESSION_DESIGN.md §주문 무기 성장 확정 설계]

장갑·장화·장신구의 선호 옵션은 기존 BasicItem·NPC 상점 장비와 연결된다. 실제 반영 단계에서는 BasicItem의 저장 ID와 NPC 장비 평가·상점 후보·드랍을 함께 검증한다. 기존 BasicItem ID를 재사용하거나 저장 중인 장비를 이번 문서 작업에서 변환하지 않는다. [src: Docs/npc/NPC_SHOP_EQUIPMENT_DESIGN.md §3·§5·§7, Assets/_BinaryData/TableData/BasicItemTable.bytes]

## 방어구 5부위 기본 성능표 초안

### 비교 범위와 시작점

공용 대표 장비인 투구·갑옷·장갑·장화·허리띠만 비교한다. 앞의 교체 순서표에서 이 5개 라인×3구간의 기존 15종에 적용할 생존 기본값이다. 새 중간 장비를 추가하지 않으며 실제 수치 변경은 이후 구현 과제다. 방패·마법서·목걸이·반지, 강화, 고정 특성, 랜덤 옵션과 회복 효과는 이 기본 성능표에 포함하지 않는다.

플레이어 Knight의 기본 최대 체력은 200, 기본 방어도는 20이다. 조사한 플레이어 생성과 능력치 계산 경로에서는 장비 기여분을 제외한 이 기본값에 몬스터 DropLevel별 성장 배율을 적용하지 않는다. 이번 계산에서도 기본 체력 200·방어도 20을 고정한다. 이 비교 구간은 플레이어 레벨을 뜻하지 않는다. [src: Assets/_BinaryData/TableData/CreatureTable.bytes Id 1, Assets/_BinaryData/TableData/StatTable.bytes Id 1, Assets/Scripts/Factory/EntityFactory.cs CreatePlayer·AddCreatureComponents, Assets/Scripts/Common/Component/StatComponent.cs InitializeFromTable, Assets/Scripts/Common/System/System_StatCalculation.cs]

현행 시작 장비 11·12·13·14·15의 합계는 방어도 20·최대 체력 추가 14다. 따라서 시작 비교점은 캐릭터 총 체력 214·총 방어도 40으로 둔다. 이 합계는 보존하면서 부위별 분배를 재설계한다. 개별 시작 아이템의 현행 수치가 모두 유지되거나 증가하는 안은 아니다. [src: Assets/_BinaryData/TableData/EquipmentBaseStatTable.bytes ItemId 11~15, Assets/_BinaryData/TableData/ModTable.bytes]

| 부위 | 5부위 장비 방어도에서 차지하는 비중 | 5부위 장비 추가 체력에서 차지하는 비중 | 배분 의도 |
| --- | --- | --- | --- |
| 투구 | 20% | 15% | 갑옷을 보조하는 기본 생존 |
| 갑옷 | 40% | 40% | 교체 효과가 가장 큰 핵심 부위 |

| 장화 | 20% | 10% | 위치를 바꿀 때 물리 생존 보조, 이동 속도는 별도 예산 |

방어도와 추가 체력의 비중은 각각 합계 100%다. 이 비중은 방패·장신구까지 포함한 모든 장비 예산의 비율이 아니다. 한 부위의 비중만으로 방어도와 체력의 교환 가치를 동일하게 평가하지도 않는다.

### 성장식과 정수화

몬스터의 레벨별 피해 배율 1.10을 사용해, 같은 구간 적의 타격이 차지하는 체력 비율을 유지하는 방향으로 제안한다. 장비의 작은 시작 체력 14만 1.10배씩 늘리면 고정 기본 체력 200 때문에 총 체력의 성장이 적 피해를 따라가지 못한다. 캐릭터 총 체력·총 방어도 목표를 먼저 정한 뒤 기본값을 빼서 장비 기여분을 구한다. [src: Assets/Scripts/Common/BalanceConstants.cs DmgPerLevel, Assets/Scripts/Factory/EntityFactory.cs ApplyMonsterArchetypeScaling, Docs/combat/BALANCE_DESIGN.md §3.2]

```text
L = 비교할 장비의 DropLevel
성장 배율 g(L) = 1.10^(L - 1)

캐릭터 총 체력 목표 = 반올림(214 × g(L))
캐릭터 총 방어도 목표 = 반올림(40 × g(L))

5부위 장비 추가 체력 예산 = 캐릭터 총 체력 목표 - 200
5부위 장비 방어도 예산 = 캐릭터 총 방어도 목표 - 20

부위별 추가 체력 = 반올림(장비 추가 체력 예산 × 해당 부위 체력 비중)
부위별 방어도 = 반올림(장비 방어도 예산 × 해당 부위 방어도 비중)

비교용 실제 총 체력 = 200 + 5부위 추가 체력의 합
비교용 실제 총 방어도 = 20 + 5부위 방어도의 합
```

초안의 반올림은 가장 가까운 정수, 정확히 0.5이면 올림으로 통일한다. 목표 합계와 각 부위를 별도로 반올림하므로 최종 합계가 목표와 조금 다를 수 있다. 세 기준점에서 총 체력 오차는 최대 약 0.20%, 총 방어도 오차는 최대 약 0.41%다. 아래 표의 정수값을 실제 반영 후보로 사용하며, 기본값이나 배분 비중이 바뀌면 다시 계산한다.

이 식은 물리 방어 감소율이 받는 피해 크기에 따라 달라지는 현행 공식에서, 적 피해와 총 방어도를 함께 성장시키는 비교안이다. 고정된 절대 피해를 상대로 측정한 모든 EHP가 정확히 구간당 1.10배가 된다는 뜻은 아니다. 공격 성장용 1.13 배율이나 쌍수 피해 계수 0.7을 방어구에 적용하지 않는다.

### 성장 구간별 기본값

부위별 칸은 **방어도 / 최대 체력 추가량**이다. 마지막 두 열만 캐릭터 기본값을 포함한 5부위 착용 결과이며, 다른 장비·옵션의 기여분은 제외한다.

| DropLevel | 투구 | 갑옷 | 장갑 | 장화 | 허리띠 | 캐릭터 총 체력 | 캐릭터 총 방어도 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 4 / 2 | 8 / 6 | 2 / 1 | 4 / 1 | 2 / 4 | 214 | 40 |
| 10 | 15 / 46 | 30 / 122 | 7 / 31 | 15 / 31 | 7 / 76 | 506 | 94 |
| 20 | 45 / 166 | 90 / 444 | 23 / 111 | 45 / 111 | 23 / 277 | 1309 | 246 |

추가 체력은 시작점 대비 큰 배율로 늘어난다. 고정 기본 체력 200을 포함한 총 체력이 적 피해 곡선을 따라가도록 역산했기 때문이다. 예를 들어 구간 20의 장비 추가 체력 합계는 1109이며 캐릭터 총 체력은 1309다. 개별 방어구에 체력 1309를 붙이는 안이 아니다. 방패·장신구·강화·옵션을 더한 전체 착용 결과는 후속 예산 검증에서 별도로 비교한다.

### 대표 타격 비교

아래는 실제 특정 몬스터의 모든 타격을 재현한 결과가 아니라, 성장식과 방어 공식이 맞물리는지 확인하는 계산용 입력이다. 작은 물리 타격은 10×g(L), 큰 물리 타격은 40×g(L), 원소 타격은 20×g(L)로 둔다. 원소 저항은 플레이어 기본값 5%로 고정한다. 치명타·회피·막기·피해 난수·회복·최소 피해 보정은 이 비교에서 제외한다. [src: Assets/_BinaryData/TableData/StatTable.bytes Id 1, Assets/Scripts/Skill/Combat/DamageCalculator.cs GetArmorReduction·GetResistanceReduction]

```text
물리 적용 피해 = 입력 피해 × (1 - 총 방어도 / (총 방어도 + 10 × 입력 피해))
원소 적용 피해 = 입력 피해 × (1 - 0.05)
체력 대비 피해 비율 = 적용 피해 / 총 체력 × 100%
```

| DropLevel | 작은 물리 타격의 체력 대비 피해 | 큰 물리 타격의 체력 대비 피해 | 원소 타격의 체력 대비 피해 |
| --- | --- | --- | --- |
| 1 | 3.338% | 16.992% | 8.879% |
| 10 | 3.332% | 16.951% | 8.854% |
| 20 | 3.332% | 16.981% | 8.877% |

세 입력 모두 구간이 올라가도 체력 대비 피해가 거의 유지된다. 이는 현재 전체 전투의 생존 시간 목표를 달성했다는 검증이 아니다. 방어도는 원소 피해에 작용하지 않으므로 후속 저항·체력·회복 옵션의 가치도 따로 비교한다.

현행 데이터의 예로 Monster 1001은 Stat 1001의 공격 피해 1~2와 AI 1의 Skill 2 물리 피해 3~5를 사용하며, Normal의 DmgMul은 1.30이다. 장비와 추가 옵션이 없는 조건에서 두 피해 범위의 중간값 합계 5.5에 현행 SkillDamage 성장·정수화를 적용하면, 제안한 5부위 착용 시 체력 대비 피해는 세 기준점에서 약 2.1%다. 중간값을 방어 공식에 넣은 계산이므로 난수를 포함한 평균 피해와 같지는 않다. [src: Assets/_BinaryData/TableData/MonsterTable.bytes Id 1001, Assets/_BinaryData/TableData/StatTable.bytes Id 1001, Assets/_BinaryData/TableData/AiTable.bytes Id 1, Assets/_BinaryData/TableData/SkillTable.bytes Id 2, Assets/_BinaryData/TableData/MonsterArchetypeTable.bytes Normal, Assets/Scripts/Factory/EntityFactory.cs ApplyMonsterArchetypeScaling, Assets/Scripts/Common/System/System_SkillAttackProfileCalculation.cs, Assets/Scripts/Common/Utility/WeaponHelper.cs, Assets/Scripts/Skill/Combat/DamageCalculator.cs]

이 값은 밸런스 문서의 일반 몬스터 단일 타격 목표 5~10%보다 낮다. 제안 곡선은 시작 생존 기준을 유지하는 초안이며, 일반 몬스터의 실제 공격 피해와 목표 난이도 조정은 별도 밸런스 작업으로 남긴다. 현행 구간 20 대표 5부위는 캐릭터 총 체력 275·총 방어도 90이라 같은 중간값 입력 43.725에 약 13.19% 피해를 받지만, 제안한 구간 20 값은 약 2.14%다. 현재의 후반 생존 약화를 줄이는 대신 전체 전투 난이도를 다시 검토할 필요가 있다. [src: Docs/combat/BALANCE_DESIGN.md §1.2, Assets/_BinaryData/TableData/EquipmentBaseStatTable.bytes ItemId 45·47·49·51·53]

### 한 부위씩 교체하는 효과

구간 20의 비교용 물리 입력 20×g(20), 약 122.318을 동일하게 가한다. 아래의 구간 10·20 장비는 모두 제안한 기본값이며 현행 장비 성능과 구분한다. 고정 타격 여유는 총 체력 / 적용 피해의 소수 비율이다. 실제로 버티는 정수 타격 횟수나 회복·회피를 포함한 전투 시간은 아니다.

| 제안 방어구 조합 | 총 체력 | 총 방어도 | 타격당 적용 피해 | 고정 타격 여유 |
| --- | --- | --- | --- | --- |
| 5부위 모두 구간 10 | 506 | 94 | 113.589 | 4.455 |
| 갑옷만 구간 20, 나머지 구간 10 | 828 | 154 | 108.640 | 7.621 |
| 5부위 모두 구간 20 | 1309 | 246 | 101.837 | 12.854 |

세트를 한 번에 완성하기 전에도 한 부위 교체로 생존이 늘어난다. 갑옷의 비중이 가장 크므로 교체 효과도 가장 크며, 다른 부위는 예산에 맞는 작은 증가를 제공한다. 별도의 중간 교체점 없이 구간 사이는 강화·옵션 개선으로 보완한다. 추가 MOD의 방향은 아래 [비무기 MOD 성장](#mod-옵션을-추가한-비무기-장비-성장)을 따르며 실제 옵션 구성으로 생존 성능을 다시 비교한다.

### 남은 옵션·변형 결정

이번 표는 방어도와 추가 체력만 제안한다. 기존 철 건틀릿 29·미스릴 건틀릿 49의 치명타 Base를 제거하거나 새 생존값에 무조건 추가하기로 결정한 것은 아니다. 유지·Implicit 이동·수치 조정은 다른 장비의 글로벌 치명타와 함께 비교한다. 표를 기존 Base 행 전체의 최종 대체값으로 해석하지 않는다.

강화가죽 갑옷 28·마법사 두건 46·마법사 로브 48·마력 장갑 50·신속의 부츠 52·마력 허리띠 54의 새 수치는 아직 배정하지 않는다. 같은 구간 대표 장비의 생존값을 모두 제공하면서 시전·이동·자원 특성을 추가로 주는 방식은 비교 없이 채택하지 않는다. 후속 고정 특성 설계에서 방어·체력·운용 성능의 교환을 비교한다. 확률·속도·저항을 이 체력·방어도 성장식으로 자동 증가시키지 않는다.

## 방패와 보조 마법서 기본 성능표 초안

### 장착 구성과 비교 경계

방패와 마법서는 같은 Shield 분류의 왼손 보조 장비이지만 고정 성능을 다르게 제안한다. 방패는 체력·방어도·막기로 생존을 높이고, 마법서는 마나 용량·재생과 작은 시전 속도로 주문 운용을 돕는다. 마법서가 Shield 분류라는 이유로 방패의 막기를 받는 안은 아니다. 모든 새 수치는 초안이며 현행 아이템·Mod·Implicit·BasicItem 행을 변경하지 않았다.

한손 무기+방패 또는 한손 무기+마법서는 보조 슬롯을 소비한다. 따라서 쌍수의 두 번째 무기와 동시에 사용하지 못하며, 양손 대검·활·석궁·지팡이에는 보조 장비를 장착하지 못한다. 마법서는 한손 완드와 함께 쓰는 대표 주문 선택지로 비교하되 별도의 직업·완드 전용 착용 제한을 추가하는 결정은 하지 않는다. 보조 장비는 무기 피해·APS·치명타·도달거리 평균에 들어가지 않고 한손 무기의 값을 유지한다. [src: Docs/combat/WEAPON_PROGRESSION_DESIGN.md §지원 계열과 장착 규칙·§쌍수 계산 초기안]

여기서 마법서는 ItemType=Equipment·Category=Shield인 보조 장비다. 스킬을 장착하고 책 안의 스킬 레벨을 올리는 ItemType=SkillBook과 구분한다. 보조 마법서의 교체가 스킬북 레벨·페이지·책 등급을 바꾸지는 않는다. [src: Assets/_BinaryData/TableData/ItemTable.bytes ItemId 44·58, Assets/Scripts/Common/GlobalEnum.cs ItemType, Docs/combat/WEAPON_PROGRESSION_DESIGN.md §스킬북 내부 스킬 레벨 성장 계획]

### 방패의 성장값

현행 목재 방패의 방어도 10·막기 +20%p를 출발점으로 유지하고 추가 체력 2를 제안한다. 상위 방패에도 막기를 제공해 교체하면서 특성을 잃지 않게 한다. 방어도는 적 피해와 같은 1.10 곡선, 추가 체력은 앞의 5부위 장비 체력 예산의 15%, 막기는 구간 1~20에서 +20~30%p로 완만하게 늘린다. 확률에는 지수 성장식을 적용하지 않는다. [src: Assets/_BinaryData/TableData/EquipmentBaseStatTable.bytes ItemId 18·34·57]

```text
g(L) = 1.10^(L - 1)
방패 방어도 = 반올림(10 × g(L))
방패 추가 체력 = 반올림((반올림(214 × g(L)) - 200) × 0.15)
방패 막기 추가분 = 반올림(20 + 10 × (L - 1) / 19) %p
```

막기 식은 이번 비교 범위 1~20에만 사용한다. 그 이후 구간에도 계속 확률을 높이는 규칙이나 모든 옵션을 포함한 최종 막기 상한을 정한 것은 아니다. 반올림은 앞의 방어구와 같은 0.5 올림이다.

| DropLevel | 장비 | 방어도 | 최대 체력 추가 | 막기 확률 추가 |
| --- | --- | --- | --- | --- |
| 1 | 목재 방패(18) | 10 | 2 | +20%p |
| 10 | 철 방패(34) | 24 | 46 | +25%p |
| 20 | 강철 대방패(57) | 61 | 166 | +30%p |

이 표는 대표 방패의 고정 기본값 전체에 대한 제안이다. 현행 철 방패 체력 7·강철 대방패 체력 30 등을 표의 체력에 추가로 중복 합산하지 않는다. 추가 체력 비중은 캐릭터 총 체력이 아니라 5부위 장비 체력 예산 기준이므로, 같은 구간 갑옷보다 작은 체력을 제공한다.

막기 성공 시 피해 감소는 현행 캐릭터 기본값 50%를 비교에 사용한다. 방패가 막기 감소율 +50%p를 별도로 추가하거나 피해를 완전히 무효화하는 안이 아니다. 현행 DamageCalculator는 물리·원소 방어 적용 후 타격 피해를 합산해 막기를 판정하므로 이 경로의 원소 타격도 막기에 포함된다. 지속 피해 등 다른 피해 경로에 같은 효과가 있다고 가정하지 않는다. [src: Assets/_BinaryData/TableData/StatTable.bytes Id 1, Assets/Scripts/Common/System/System_StatCalculation.cs BuildDefenseCache, Assets/Scripts/Skill/Combat/DamageCalculator.cs]

### 방패의 생존 비교

앞의 공용 5부위를 같은 구간으로 착용하고, 방패가 없는 상태의 생존 지수를 1.000으로 둔다. 작은 물리 입력 10×g(L), 큰 물리 입력 40×g(L), 원소 입력 20×g(L)과 원소 저항 5%는 앞의 방어구 비교와 같다. 기본 막기 0%, 방패의 막기 추가분, 막기 성공 시 피해 감소 50%를 사용하고 다른 옵션·회복·회피·치명타는 제외한다.

```text
막기 기대 피해 배율 = 1 - 막기 확률 / 100 × 0.50
방패 착용 평균 물리 피해
    = 입력 피해 × (1 - 착용 총 방어도 / (착용 총 방어도 + 10 × 입력 피해))
      × 막기 기대 피해 배율
방패 착용 평균 원소 피해 = 입력 피해 × 0.95 × 막기 기대 피해 배율
평균 피해 기준 생존 지수
    = (방패 착용 총 체력 / 착용 평균 피해)
      / (방패 미착용 총 체력 / 미착용 피해)
```

| DropLevel | 5부위+방패 총 체력 | 5부위+방패 총 방어도 | 작은 물리 생존 지수 | 큰 물리 생존 지수 | 원소 생존 지수 |
| --- | --- | --- | --- | --- | --- |
| 1 | 216 | 50 | 1.202 | 1.147 | 1.121 |
| 10 | 552 | 118 | 1.337 | 1.276 | 1.247 |
| 20 | 1475 | 307 | 1.420 | 1.356 | 1.326 |

구간 20에서 작은 물리 타격 기준 약 42%, 큰 물리 기준 약 36%, 원소 기준 약 33%의 평균 피해 대비 생존 여유를 제공한다. 막기는 확률 효과라 이 수치만큼 모든 타격을 확정적으로 버티는 것은 아니다. 예를 들어 구간 20의 큰 물리 입력 약 244.636은 방패가 있어도 막기에 실패하면 약 217.359, 성공하면 약 108.680의 피해를 준다. 평균 적용 피해 약 184.755와 구분해 큰 한 번의 타격도 따로 확인해야 한다.

같은 구간 한손검+방패의 무기 피해 DPS 지수는 100, 한손검 쌍수는 140, 대검은 150이다. 방패는 추가 피해를 제공하지 않고 생존을 제공하며, 한손검의 도달거리 1.00·대검의 1.30 차이도 유지한다. 이는 무기 피해만의 공격 지수와 특정 입력의 생존 지수를 병렬 비교한 것이며 서로 곱해서 총 전투 효율이 같다고 판정하지 않는다. 단검·도끼·투창도 한손 성능을 유지하면서 방패를 선택하고, 완드+방패는 주문 피해·시전보다 생존을 우선하는 구성이 된다. ### 보조 마법서의 성장값

마법서에는 기본 방어도·체력·막기·주문 피해 증가를 제공하지 않는 초안을 제안한다. 최대 마나와 초당 마나 재생을 주요 성장값으로 두고 시전 속도를 +5~10%로 제한해, 두 번째 완드의 높은 주문 피해와 구분한다. 이 수치는 대표 마법서의 새 고정 성능 제안이며 현행 상급 마법서 58의 체력 30·치명타 +8%p를 그대로 더하는 안은 아니다.

| DropLevel | 장비 | 최대 마나 추가 | 마나 재생 추가 | 고정 시전 속도 증가 |
| --- | --- | --- | --- | --- |
| 1 | 낡은 보조 마법서(신규) | +50 | +2/초 | +5% |
| 10 | 초급 마법서(44) | +100 | +4/초 | +8% |
| 20 | 상급 마법서(58) | +150 | +6/초 | +10% |

세 교체점의 최대 마나는 +50·+100·+150, 재생은 +2·+4·+6/초, 시전 속도는 +5·+8·+10%를 사용한다. 마나 비용은 현행 SkillTable.Mana를 사용하고, 현재 책별 스킬 레벨 성장 계획도 피해 성장을 대상으로 한다. 따라서 마법서의 마나를 적 피해·방어구의 1.10 곡선이나 공격 무기의 1.13 곡선으로 증가시키지 않는다. 향후 스킬 레벨에 따른 마나 비용을 도입하면 용량·재생·지속 비교를 다시 설계한다. [src: Assets/Scripts/Common/System/System_Skill.cs 마나 가드·소비, Assets/_BinaryData/TableData/SkillTable.bytes, Docs/combat/WEAPON_PROGRESSION_DESIGN.md §스킬북 내부 스킬 레벨 성장 계획]

마나 재생 +2는 초당 2 MP의 고정 추가분이고 +2% 증가가 아니다. 현재 재생 시스템은 FinalMpGeneration×경과 시간을 누적해 정수 MP를 회복한다. 마법서의 최대 마나·재생은 캐릭터 전체에 적용되므로 비용이 있는 공격 스킬도 자원 이점을 받을 수 있다. 시전 속도는 기존 Spell 소비 경로를 따르며 Attack의 무기 APS를 올리지 않는다. [src: Assets/_BinaryData/TableData/ModTable.bytes Id 1200·1202·1208, Assets/Scripts/Common/System/System_Regen.cs, Assets/Scripts/Common/System/System_Skill.cs GetSkillSpeedMultiplier]

### 주문 구성의 마나 제약 없는 피해 비교

무기 성장 문서와 같은 주문 DPS 지수를 사용한다. 장비 보너스 없는 기본 피해·시전 시간의 주문을 100으로 두며 스킬 레벨·마나·쿨타임·치명타·다른 옵션·대상 방어는 제외한다. 이 표에서는 캐릭터 기본 시전 속도 1도 제외해 기존 무기 지수와 비교 조건을 맞춘다. 마법서의 시전 속도는 완드 +10%와 글로벌 합산하고 피해 증가나 쌍수 계수로 처리하지 않는다. [src: Docs/combat/WEAPON_PROGRESSION_DESIGN.md §지팡이와 완드의 아이템별 고정 주문 옵션, Assets/Scripts/Common/System/System_StatCalculation.cs ApplyIncreaseBucket, Assets/Scripts/Common/System/System_Skill.cs GetSkillSpeedMultiplier]

```text
완드+마법서 주문 DPS 지수
    = 100 × (1 + 완드 주문 피해 증가 / 100)
      × (1 + (10 + 마법서 시전 속도 증가) / 100)
```

| DropLevel | 완드+방패 | 완드+마법서 | 동일 완드 쌍수 | 지팡이 |
| --- | --- | --- | --- | --- |
| 1 | 132.0 | 138.0 | 168.0 | 160.0 |
| 10 | 170.5 | 182.9 | 252.0 | 240.0 |
| 20 | 209.0 | 228.0 | 336.0 | 320.0 |

마나를 충분히 공급하는 전투에서는 지팡이·완드 쌍수의 피해가 높다. 마법서는 두 번째 완드만큼의 피해 증가를 제공하지 않으며, 구간 20에서 완드+마법서 228은 완드 쌍수 336의 약 68%다. 지팡이의 1.30 범위와 완드 구성의 1.00도 유지한다. 짧은 전투·마나 물약·높은 공통 재생·다른 자원 공급이 있으면 이 피해 차이를 감수할 이유가 작아질 수 있다.

### 마나가 부족한 긴 전투의 비교

자원 비교를 위해 기본 1회 피해 100·전체 기본 시전 시간 1초·시전당 비용 20 MP·쿨타임 0인 가상의 단일 타격 주문을 사용한다. 실제 SkillTable 행을 수정하거나 이 조건을 특정 스킬의 실전 성능이라고 주장하지 않는다. 플레이어 기본 최대 마나 100·재생 4 MP/초·시전 속도 1을 포함하며, 책 레벨 피해 성장·다른 옵션·물약·회복 발동은 제외한다. 실제로 ChainLightning 202는 비용 20 MP이지만 시전 시간과 쿨타임이 이 가정과 다르므로 아래 숫자를 그대로 적용하지 않는다. 마나 비용 0인 스킬은 이 자원 이점이 없고, 쿨타임이 긴 주문은 실제 소비 속도가 낮아질 수 있다. 시전 속도가 쿨타임까지 줄인다고 가정하지 않는다. [src: Assets/_BinaryData/TableData/StatTable.bytes Id 1, Assets/_BinaryData/TableData/SkillTable.bytes Id 202, Assets/Scripts/Common/System/System_Skill.cs 마나 가드·소비·GetSkillSpeedMultiplier·OnSkillComplete, Assets/Scripts/Common/System/System_Regen.cs]

```text
s = 초당 시전 가능 횟수 = (100 + 기본 시전 1 + 장비 시전 증가 합계) / 100
M = 최대 마나
R = 초당 마나 재생
C = 시전당 마나 비용 20

연속 소비 모델의 소진 시간 = M / (C × s - R), 단 C × s > R
장기 평균 시전 횟수 = Min(s, R / C)
장기 평균 DPS = 주문 1회 피해 × 장기 평균 시전 횟수
```

소진 시간은 연속 모델의 추정치다. 실제 마나 소비는 시전 시작 때 정수 비용을 차감하고 부족하면 다음 시전을 거절하므로 실제 중단 시점·정수 시전 횟수는 이 값과 다를 수 있다. 장기 평균은 초기 마나 용량의 효과가 사라질 만큼 긴 시간에서, 부족할 때 재생을 기다렸다가 다시 시전하는 모델이다. 모든 표에서 C×s가 R보다 크며 무한 연속 시전을 보장하는 설계가 아니다.

| DropLevel | 완드+마법서 총 마나 | 총 재생 | 초당 시전 가능 횟수 | 마법서 소진 추정 | 쌍수 소진 추정 | 지팡이 소진 추정 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 150 | 6/초 | 1.16 | 8.72초 | 4.95초 | 6.17초 |
| 10 | 200 | 8/초 | 1.19 | 12.66초 | 4.95초 | 6.17초 |
| 20 | 250 | 10/초 | 1.21 | 17.61초 | 4.95초 | 6.17초 |

| DropLevel | 완드+마법서 장기 평균 DPS | 완드 쌍수 장기 평균 DPS | 지팡이 장기 평균 DPS |
| --- | --- | --- | --- |
| 1 | 36.00 | 28.00 | 32.00 |
| 10 | 62.00 | 42.00 | 48.00 |
| 20 | 95.00 | 56.00 | 64.00 |

기본 재생 4만 사용하는 이 조건에서는 마법서가 마나 부족 중의 평균 피해에서 유리하다. 최대 마나는 초기 연속 사용 시간을 늘리고, 재생은 고갈 이후의 지속 운용을 개선한다. 반대로 공통 재생이 16 MP/초인 구간 20 예시에서는 마법서가 총 재생 22를 제공해 장기 평균 DPS 209, 쌍수는 224, 지팡이는 256이 된다. 추가 자원이 충분해질수록 높은 1회 피해를 주는 구성이 유리해지므로 마법서가 모든 전투에서 최선인 것은 아니다. 이 예시의 공통 재생 16은 가정이며 현행 특정 장비 조합에서 확보된 수치라는 뜻은 아니다.

### 기본값과 고정 옵션의 적용 계획

방패의 방어도·체력·막기 추가분은 Base로 제안하며 기존 Base Mod 4·7·6의 책임을 유지한다. 막기 피해 감소 50%는 캐릭터 기본값이므로 별도 방패 Mod를 추가하지 않는다. 마법서의 최대 마나·재생은 새 Base 전용 Mod, 고정 시전 속도는 별도 Implicit용 Mod와 ItemImplicit 행으로 배치하는 안이다. 기존 Prefix 1200·1202와 Postfix 1208의 슬롯을 바꾸거나 같은 ID를 다른 의미로 재정의하지 않는다. [src: Assets/_BinaryData/TableData/ModTable.bytes, Assets/Scripts/Common/Utility/EquipHelper.cs ApplyEquipmentModifiers·ApplyPassiveMod, Assets/Scripts/Manager/ItemManager.cs CreateBaseEquipment]

현행 Shield는 AllArmor에 포함되어 최대 마나·재생 랜덤 옵션의 자격이 있고, 시전 속도 1208도 Shield에 허용된다. 따라서 방패에 자원·시전 랜덤 옵션이 붙을 가능성은 유지하며 두 종류의 역할은 이번 고정 성능으로 구분한다. 동일 종류의 Base·Implicit·랜덤 추가분은 캐릭터 글로벌 경로에서 합산하고, 보조 장비 옵션에 쌍수 피해 계수 0.7이나 평균을 적용하지 않는다. 최종 고정 옵션과 랜덤 옵션 전체 예산은 목걸이·반지까지 함께 설계한 뒤 검증한다. [src: Assets/Scripts/Common/GlobalEnum.cs EquipmentTypeMask, Assets/_BinaryData/TableData/ModTable.bytes Id 1200·1202·1208, Assets/Scripts/Common/Utility/EquipHelper.cs]

초급 마법서 44는 기존 ID를 보존하고 위 Base 성능을 추가하는 반영 후보로 둔다. 시작 낡은 보조 마법서는 이번 추가 대상으로 정하고 5·15 전용 마법서는 추가하지 않는다. 이번 표에 새 ItemId·ModId를 배정하거나 테이블 행을 생성하지 않았다. 기본 수치가 확정되면 BasicItem·상점·NPC 장비 평가와 저장 중 장비의 처리까지 연결해야 한다.

## 목걸이와 반지 기본 성능표 초안

### 기본 성장과 고정 특성

목걸이는 추가 체력과 최대 마나, 반지는 추가 체력과 글로벌 고정 치명타를 유지하는 공용 성장 라인으로 제안한다. 공격·주문용 반지를 별도 필수 계열로 늘리지 않고 기존 성장 라인의 랜덤 옵션으로 빌드를 보완한다. 목걸이의 마나는 비용이 있는 공격에도 적용되며 반지의 글로벌 치명타는 Attack·Spell 모두에 적용된다. 현재 비무기 Base 치명타가 무기 기본 치명타 평균의 대상이 아니라는 계산 경계를 유지한다. [src: Assets/Scripts/Common/Utility/EquipHelper.cs ApplyEquipmentModifiers·ApplyPassiveMod, Assets/Scripts/Skill/Combat/SkillOffensiveStatResolver.cs, Assets/Scripts/Common/System/System_SkillAttackProfileCalculation.cs]

현행 시작 목걸이와 반지의 체력 7을 보존하고, 같은 구간 캐릭터 체력에서 작은 비중을 유지하도록 각 장신구에 7×g(L)의 체력을 제안한다. 목걸이·반지 각각의 체력을 앞의 5부위 장비 체력 예산에서 추가로 나누어 빼지는 않는다. 이 구간별 합계는 앞의 방어구 표에 장신구를 더한 별도 비교다. [src: Assets/_BinaryData/TableData/EquipmentBaseStatTable.bytes ItemId 16·17]

```text
g(L) = 1.10^(L - 1)
목걸이 또는 반지 하나의 추가 체력 = 반올림(7 × g(L))
목걸이 하나 + 반지 두 개의 추가 체력 = 부위별 정수 체력 × 3
```

반올림은 기존 초안과 같은 0.5 올림이다. 목걸이의 마나와 반지의 치명타는 표의 완만한 단계로 배정하며 지수 증가시키지 않는다. 체력은 Base, 목걸이 최대 마나와 반지 고정 치명타는 부위별 전용 Implicit으로 정리하는 안이다. 귀걸이 도입·주문 피해 증가·Attack 추가 피해·최대 저항 증가를 이 고정 성능에 추가하지 않는다.

마지막 두 열은 캐릭터 기본 체력 200을 포함하며 랜덤 옵션·강화·회복을 제외한다. 마법서에는 기본 체력이 없으므로 마법서 구성의 고정 총 체력은 방패 없는 열과 같다. 기존 방어구·방패 비교는 장신구를 제외했던 조건이며 위 표가 그 결과를 소급 변경하지 않는다. 장신구의 추가 체력 합계는 방패 없는 5부위 총 체력 대비 약 10%로 유지된다.

### 랜덤 옵션의 성장 예산

현행 Prefix/Postfix 자격과 부여 시 슬롯별 최대 3개·같은 슬롯의 Group 중복 금지를 유지하는 안이다. 목걸이·반지의 Prefix 후보는 최대 마나 1200·체력 재생 1201·마나 재생 1202이며, 현행 추가 체력 Prefix 1000은 AllArmor에만 허용되어 장신구에는 롤하지 않는다. 장신구에서 랜덤 추가 피해나 치명타 확률 증가 1003을 롤할 수 있다고 가정하지 않는다. 주요 Postfix 선택은 4속성 저항·치명타 피해 1207·시전 1208이다. 세 Prefix를 모두 채우면 현재 후보 세 종류가 들어가므로 장신구의 주요 옵션 선택과 교환은 Postfix에서 발생한다. [src: Assets/_BinaryData/TableData/ModTable.bytes, Assets/Scripts/Item/ItemEnchantmentService.cs ItemEnchantmentRules·HasGroupCollision]

마나 재생 Mod 1202만 중·상위 범위를 낮추는 이유는 합산 가능한 부위 수다. 현행 Tier 3 최대 9를 장신구 세 부위에 붙이면 +27/초이고 캐릭터 기본 4를 더해 31/초가 된다. 아래 비용 20·기본 시간 1초의 자원 예시에서 이는 다른 부위의 재생 없이도 지팡이의 소비를 넘는다. 제안한 최대 4는 세 부위에서 +12/초로 제한하여 마법서와 추가 재생 투자의 가치를 더 오래 남긴다. 재생 1202는 AllArmor에도 허용되므로 이 조정은 장신구 전용 수치가 아니라 해당 Mod의 전 장비 공통 초안이다. 장비 전체를 재생에 투자하면 후반에 마나 부족을 해결할 수 있는 가능성까지 금지하지는 않는다.

### 전체 장비의 치명타와 시전 합계

```text
최종 치명타 = Clamp(
    (Attack의 고유 강화 반영 무기 기본 치명타 또는 Spell의 스킬 기본 치명타
     + 캐릭터 기본 치명타 5 + 고정 장신구 치명타
     + 기타 글로벌 고정 치명타 + OnHit 보너스)
    × (1 + 태그에 맞는 글로벌 치명타 증가 합계 / 100), 0, 100)

치명타 피해 배율 = 1.5 + (캐릭터 기본 치명타 피해 10 + 글로벌 가산 합계) / 100
주문 시전 배율 = Max(0.1, (100 + 캐릭터 기본 시전 1 + 글로벌 시전 증가 합계) / 100)
```

Attack과 Spell의 기본 치명타 항은 다르고 반지의 추가분은 공통이다. 무기 두 개의 기본 치명타는 평균하지만 일반 치명타 증가 1003·시전·치명타 피해는 글로벌 합산한다. 새 양손 예산안에서는 해당 일반 공격 옵션만 한손 값의 2배로 계산한다. 이 한 번의 옵션 예산 반영을 무기 기본 치명타·APS 평균이나 피해 0.7 합성에 다시 넣지 않는다. [src: Assets/Scripts/Common/System/System_SkillAttackProfileCalculation.cs, Docs/combat/WEAPON_PROGRESSION_DESIGN.md §무기 옵션 Tier와 수치 초안]

아래는 **새 무기 후보 확대·양손 옵션 예산을 포함한** 구간 20 이론 상한이다. 무기 최대 마나 1200·시전 1208 확대가 미구현임을 전제로 구분한다. 마나/재생은 기존 5부위·세 장신구에 가능하고 보조에 한 곳 더 가능하다. 최대 마나는 무기에서도 단일/쌍수에 1/2곳 추가되며 이 유틸리티는 양손이라고 두 배가 되지 않는다. 일반 시전·치명타 피해는 양손 한 자루와 쌍수 두 자루가 각각 2개분 공격 예산을 사용한다. [src: Assets/_BinaryData/TableData/ModTable.bytes, Docs/combat/WEAPON_PROGRESSION_DESIGN.md §장비별 유효 추가 후보]

스킬 기본 치명타 0·캐릭터 5%·반지 합계 +16%p·일반 무기 치명타 증가 한손 최대 8% 조건이다. 장갑 고정 치명타는 미정이므로 추가분 0과 기존 +8%p 조건을 병기한다. 최대치 조합은 좋은 랜덤 장비 등으로 각 옵션을 확보한 한계 입력이며 고정 Tier 1 옵션 하나로 시작하는 기본 상품의 AddAffix만으로 모든 최대값에 도달하는 보장이 아니다. 상한 표의 체력/방어도·4속성 저항까지동시에 최대라고 가정하지 않는다. 예를 들어 5부위 Prefix를 마나/체력 재생/마나 재생으로 채우면 핵심 체력/방어도 MOD를 넣을 자리가 없다. 고정 목걸이 마나와 마법서 자원을 위 합계에 한 번만 더했다.

가상 비용 20·기본 시간 1초·쿨타임 0에서 최대 시전의 소비는 지팡이 38.2/초·완드 쌍수 42.2/초·마법서 42.2/초다. 재생 36/36/46과 비교하면 앞의 두 구성은 여전히 고갈하고 마법서 구성은 고갈하지 않는다. 실제 ChainLightning은 별도 쿨타임이 있어 아래 실제 스킬 표를 사용해야 한다.

Attack의 예로 무기 기본 치명타 한손검·대검 5%, 단검 12%, 반지 16%p, 장갑 8%p를 유지하면 한손검+방패는 34×1.08=36.72%, 한손검 쌍수·새 양손 예산의 대검은 34×1.16=39.44%, 단검 쌍수는 41×1.16=47.56%다. 현행 100% Clamp 아래의 합산 예시이고 장갑 +8%p의 채택 결정은 아니다.

### 저항 배분과 옵션 교환

각 속성의 기본 저항 5%, 기본 최대 저항 75%, 하드 캡 90%를 유지한다. 이번 장신구는 최대 저항 증가를 제공하지 않으므로 실제 상한은 75%다. 저항은 네 종류를 각각 계산하고 화염 옵션을 냉기·번개·독에 공유하지 않는다. 상한을 넘는 값은 해당 현재 타격의 감소율을 더 높이지 않는다. [src: Assets/_BinaryData/TableData/StatTable.bytes Id 1, Assets/Scripts/Skill/Combat/DamageCalculator.cs GetResistanceReduction, Assets/Scripts/Common/BalanceConstants.cs MaxResistanceHardCap]

| 비교 옵션 Tier | 저항 옵션 하나 최대 | 기본 5를 포함한 세 장신구의 한 속성 저항 | 실제 한 속성 저항 | 75% 도달에 필요한 최대값 옵션 수 | 4속성 모두 75%에 필요한 최소 Postfix 수 |

| 1 | 10 | 35 | 35% | 7 | 28 |

세 장신구의 Postfix는 최대 9개라 구간 20에서도 장신구만으로 4속성을 모두 75%로 만들 수 없다. 방어구와 보조 장비에 나누어 확보해야 한다. Tier 1 옵션 예산은 방패 없는 8개 비무기 장비의 최대 24개, 보조 장비 포함 27개 Postfix를 모두 저항에 써도 필요한 28개보다 적어 4속성 동시 상한이 불가능하다. 이는 같은 Tier 1 최대값만 사용한 예산의 결과이며 현행 생성 경로가 그 Tier를 강제한다는 주장은 아니다.

Postfix 교환은 슬롯에서 실제로 일어난다. 구간 20 목걸이·두 반지에 각각 시전 +15%·치명타 피해 가산 +15%·저항 한 속성 +25%를 넣으면, 세 장신구가 시전 +45%·치명타 피해 +45%·총 세 개의 저항 옵션을 제공한다. 세 저항을 화염·냉기·번개에 나누면 캐릭터 기본 포함 각각 30%, 독 5%이고, 하나의 속성에 몰면 해당 속성은 원시값 80에서 75%로 제한된다. 같은 장신구의 다른 저항을 추가하려면 시전 또는 치명타 피해를 포기해야 한다. 장갑·보조 장비·다른 방어구의 옵션으로 부족한 능력을 보완한다.

### 세 장신구를 포함한 주문 운용 예시

앞의 가상 주문인 피해 100·시간 1초·비용 20·쿨타임 0을 구간 20에서 다시 비교한다. 이번에는 목걸이·두 반지의 고정 성능과 세 장신구의 최대 마나 +55·제안 마나 재생 +4·체력 재생 +6 Prefix, 시전 +15·치명타 피해 +15·저항 한 종류 +25 Postfix를 포함한다. 다른 장비의 랜덤 옵션, 장갑의 미정 치명타, 스킬 레벨·페이지·물약·대상 방어는 제외한다. 슬롯별 3개와 Group 조건을 만족하는 하나의 비교 조합이며 플레이어 레벨 자격과 실제 획득은 앞의 구현 경계를 따른다.

### 비교 결과와 후속 설계

현재 초안에서 방패는 생존, 마법서는 자원 유지, 대검·지팡이는 한 타격과 범위, 쌍수는 단기 피해와 옵션 선택의 역할을 가진다. 사용자의 무기 중심 요청에 맞춰 Strike 고정 피해 0·피해 계수 200%안을 적용하니 초반 단검 편중이 줄고 공격·주문의 성장률도 가까워졌다. 혼합 쌍수와 범위의 차이, 고정 마나 비용이 공속 이점을 장기 운용에서 뒤집는 조건은 남는다. 실제 전투나 모든 공격 스킬의 보정이 완료된 것은 아니다.

Whirlwind·Lacerate·QuickHop의 계수·반복 간격·채널 비용은 [공격 스킬별 피해 계수 초안](WEAPON_PROGRESSION_DESIGN.md#공격-스킬별-피해-계수-초안)에 별도로 비교했다. 이 문서의 대표 공격 표는 Strike 고정 피해 0·피해 계수 200%의 비교이며 무기 표·공격/주문 레벨 배율·Strike 비용·재생 수치는 유지한다. 장비·책 공급과 추가 목록은 아래 연결하는 세 구간 공급안을 따른다. 강화는 아래 MOD 추가 성장 방향을 따른다. 아래에 MOD 후보·개수·Tier 수치와 구간 말 성능 비교를 작성했다. 데이터·공급 연결표와 MOD 후보·선택 비중을 정리했다. 구현 범위·적용 순서·완료 조건과 대표 성장 시나리오 점검을 정리했다. 원거리 전용 무기 연결과 실제 코드·테이블 반영, 방어구 변형 6종·공용 장갑 치명타와 상세 골드 비용·수급은 이후 단계로 남긴다.

### 구간 말 생존과 상위 기본 장비 비교

방어구 5부위 각각 체력 P와 방어도 P를 붙여 총 10개의 핵심 옵션을 사용한다. 시작 Postfix·나머지 옵션·회복·막기·방패·보조 마법서 효과는 제외하고, 같은 구간 목걸이·반지의 고정 체력을 포함한다. 따라서 5부위 자체 체력과 캐릭터 총 체력을 혼동하지 않는다. 최저/중점/최고는 실제 옵션 수치 범위의 비교이며 중점 소수 값은 참고 입력이다.

| --- | --- | --- | --- | --- | --- | --- | --- |
| 9 | 구간 1 / Tier 1 | 235 / 40 | 435 / 70 | 472.5 / 80 | 510 / 90 | 557 / 94 | 34.86 → 16.60 / 13.87 |
| 19 | 구간 10 / Tier 2 | 557 / 94 | 1157 / 194 | 1257 / 214 | 1357 / 234 | 1438 / 246 | 38.31 → 16.14 / 13.93 |

큰 물리 입력은 상대 레벨에 맞춘 40×1.10^(L−1), 감소식은 기존 `d × 10d / (방어도 + 10d)`다. 같은 상대 입력으로 기존 MOD 제외·기존 MOD 추가·다음 기본 세트를 비교했다. 다음 기본 열은 5부위와 목걸이·반지도 다음 구간으로 바꾼 **일반 MOD 없는 세트**이고 선택 구매 상품의 시작 옵션은 제외한 기준이다. 무기 비교에서 다른 장비를 고정한 조건과 구분한다. [src: Docs/combat/ARMOR_ACCESSORY_PROGRESSION_DESIGN.md §공용 방어구 5부위 성장 설계·§목걸이와 반지 성장 설계, Assets/Scripts/Skill/Combat/DamageCalculator.cs]

기존 구간 장비의 큰 물리 타격 부담은 중점 조합에서 체력의 약 16%로 낮아지고 다음 기본 세트는 약 14%로 더 안전하다. 낮은 롤도 약 18%라 최고값만 맞춰야 다음 교체점까지 버티는 구조는 피했지만, 여러 타격·회복·원소 조합의 실제 생존은 추가 검증이 필요하다. 저항을 제외한 보수적 비교이며 저항 MOD의 합계·75% 상한은 앞의 저항 배분 규칙을 따른다. 교체 시 기존 MOD를 옮기는 기능은 없고 좋은 옵션이 붙은 부위부터 천천히 교체해도 된다. [src: Docs/combat/ARMOR_ACCESSORY_PROGRESSION_DESIGN.md §저항 배분과 옵션 교환]

### 마나 옵션을 추가한 지속 운용

아래는 무기 MOD 구간 말 조합을 사용하고 다른 장비는 기존 구간 Base로 유지한다. 지팡이/완드의 최대 마나 Prefix, 기본 상품 시전 +4%와 양손 공격 옵션 예산을 반영한다. 마법서는 기존 구간의 고정 자원 능력만 사용하고 일반 MOD는 제외한다. 비교 오른쪽은 목걸이·두 반지에 각각 최대 마나 P와 마나 재생 P를 추가한 경우다. 장신구의 추가 시전·몸통 재생·물약을 넣지 않아 자원 두 옵션의 효과를 분리한다.

### 자격·획득·구현 경계

구간 10/20 성능표는 MOD Tier 2/3의 옵션을 확보한 비교 입력이며 플레이어 요구 레벨·장비 상한·재화별 Tier 지급을 확정한 규칙이 아니다. MOD Tier 정책은 구현 때 사용자에게 다시 질문한다. 새 MOD 종류는 계속 랜덤이고 저항·재생을 먼저 뽑아 핵심 Prefix 자리가 찰 수 있다. 아래 종류 확보 확률은 모든 후보가 유효하다는 조건이며 재화 정책이 자격을 바꾸면 다시 계산한다. Gold/재화 수급 검토는 남아 있고 목표 개수를 즉시 확보하는 규칙도 두지 않는다. [src: Docs/combat/WEAPON_PROGRESSION_DESIGN.md §적용 항과 Tier 접근 정책]

이 성능 비교는 **옵션을 확보했을 때의 예산**을 다룬다. 아래 비무기 연결표에서 시작 변형·핵심 후보·신규 생성과 기존 저장의 차이·NPC 공유 장비 영향을 구체화했다. 코드·테이블·새 ID·상점 UI·골드 비용은 이후 단계이며 방어구 변형 6종·장갑 고정 치명타는 보류한다.

## 비무기 MOD 후보와 선택 비중 초안

> 상태: 2026-10-06 성장용 랜덤 추가 후보·가중치 제안. 기본 상품의 Postfix 시작과 빈 Prefix를 전제로 계산했으며 실제 테이블·코드·골드 금액을 변경하지 않았다.

### 핵심 생존·자원 옵션의 확보 확률

한 장비에 권장 시작 S 한 개가 있고 P가 비어 있으며 모든 후보가 자격을 만족할 때의 계산이다. '3회까지'는 시작 옵션을 포함해 총 4개, '5회 후'는 총 6개다. 핵심 두 옵션의 확보는 정확한 중간 조합·수치 최고값·모든 부위 확보와 구분한다. 재화에 따른 Tier와 수치 확보 확률은 미정이며 유효 후보가 달라지면 이 종류 확률도 다시 검토한다.

| 대상 / 시작 옵션 | 첫 추가로 체력 또는 마나 확보 | 3회 추가까지 핵심 두 P 확보 | 5회 추가 후 핵심 두 P 확보 |
| --- | --- | --- | --- |
| 투구·갑옷·허리띠 / 저항 | 체력 52.63% | 체력+방어도 91.62% | 체력+방어도 98.46% |
| 장갑 / 치명타 피해 | 체력 50.85% | 체력+방어도 88.17% | 체력+방어도 98.46% |
| 장화 / 이동 | 체력 52.63% | 체력+방어도 91.62% | 체력+방어도 98.46% |
| 방패 / 저항 | 체력 50.85% | 체력+방어도 88.17% | 체력+방어도 98.46% |
| 마법서 / 저항 | 마나 37.88% | 마나+마나 재생 53.68% | 마나+마나 재생 96.56% |
| 목걸이·반지 / 치명타 피해 | 마나 40.00% | 마나+마나 재생 58.06% | 마나+마나 재생 100% |
| 목걸이·반지 / 저항 | 마나 35.71% | 마나+마나 재생 47.44% | 마나+마나 재생 100% |

비교용 새 후보를 행 균등으로 선택하면 방어구·방패·마법서의 핵심 두 P는 최종 **30%**다. 이 값은 다섯 P 중 세 개를 균등하게 선택할 때 원하는 둘을 모두 포함하는 비율이며 현행 모든 아이템의 드랍 확률이 아니다. 제안 비중으로 방어구 한 부위의 체력·방어도 누락 위험은 **1.54%**까지 줄지만 0이 되지는 않는다.

방어구 5부위 각각 최대 5회, 총 25회의 성공한 추가를 독립적으로 완료하면 체력·방어도를 **5부위 모두** 얻을 확률은 **92.55%**다. 한 부위의 98.46%를 전체 세트의 확률로 쓰지 않는다. 같은 비교용 행 균등은 0.30의 5제곱인 **0.243%**다. 골드 금액·획득 속도가 미정이므로 실제 플레이의 구간 말까지 25회 실행할 수 있는지는 아직 판정하지 않는다. 기존 생존표는 5부위 핵심 옵션을 확보했을 때의 성능 예산으로 유지한다.

3회 추가 후 체력/방어도 P와 저항 S 두 종류의 정확한 중간 조합은 투구·갑옷·허리띠 **52.12%**다. 장갑의 체력/방어도 P + 시작 치명타 피해/저항 S는 **38.83%**, 장화의 체력/방어도 P + 시작 이동/저항 S는 **52.12%**, 방패의 체력/방어도 P + 저항 두 종류 S는 **38.83%**다. 핵심 두 P를 이미 얻었어도 나머지 추가가 자원 P이면 아직 P3/S1일 수 있다.

마법서는 끝까지 추가해도 자원 3P를 모두 얻는 확률이 **81.49%**, 시전 S를 얻는 확률이 **75.00%**이며 둘을 함께 갖추는 비율은 **61.12%**다. 마나/마나 재생 확보 96.56%를 추천 3P/3S 전체의 완성률로 읽지 않는다. 장신구는 P 후보가 세 계열뿐이라 빈 P에서 시작해 끝까지 채우면 자원 3P를 모두 얻지만, 치명타 피해·시전·특정 저항의 S 조합은 보장하지 않는다.

### 슬롯 누락과 후속 경계

체력 +10·방어도 +5 같은 기존 시작 Prefix는 같은 Group을 점유한다. 이를 새 Tier 체력·방어도 확보로 세지 않으며 값·Tier를 자동 상승시키지 않는다. 세 Prefix가 이미 찼거나 기존 옵션 수가 다른 장비에는 위 확률을 적용하지 않는다. 시전으로 시작한 마법서·장신구와 일반 드랍 장비도 현재 옵션별로 다시 계산해야 한다.

운이 나쁘면 핵심 P가 빠진 채 세 Prefix가 찰 수 있다. 기존 랜덤 교체는 다른 옵션도 바꿀 수 있고 같은 MOD 수치 재롤도 아니므로 복구 횟수·비용을 보장하지 않는다. 이번 안은 핵심 확보 비중을 높이는 수준으로 두며 선택 교체·슬롯 삭제·확정 핵심 옵션 지급은 추가하지 않는다. [src: Assets/Scripts/Item/ItemEnchantmentService.cs BuildReplacementTargets·HasGroupCollision]

확률은 상태별 후보 전이의 전수 합산과 세 Prefix를 뽑는 별도 순열 계산으로 확인했다. 가중치만으로 역할에 맞는 최종 조합이 항상 나오는 것으로 처리하지 않고, 기존 체력·피해·지속 운용 표의 조건부 입력과 구분한다. 무기 문서의 [공통 구현 계획](WEAPON_PROGRESSION_DESIGN.md#구현-범위와-적용-순서)으로 범위·완료 조건을 연결했다. 대표 구성의 흐름은 아래 [비무기 성장 시나리오 점검](#비무기-성장-시나리오-점검)에 연결했다. 방어구 변형 6종·공용 장갑 치명타·상세 골드 비용·수급·스킬 레벨업 시점은 계속 보류한다.

전체 의존 순서는 [공통 구현 계획](WEAPON_PROGRESSION_DESIGN.md#구현-범위와-적용-순서)을 따른다. 비무기는 기존 32종+신규 마법서 1종의 33종을 보존 계획으로 두고 대표 27칸을 먼저 연결한다. 방어구 변형 6종의 고정 특성과 공용 장갑 고정 치명타는 보류하며 기존 소유 장비를 지우지 않는다.

MOD 추가의 Tier 결정·장비/레벨 제한·적용 작업은 사용자 재확인 전 확정하지 않는다. 임시 골드 방향을 재화 소모와 어떻게 연결할지도 구현 때 확인하고 상세 금액·수급은 계속 보류한다. Base/고정 Implicit의 장비별 값과 일반 MOD의 재화 Tier 정책을 혼동하지 않는다.

검증에는 약한 HP/방어도 시작 Prefix, 같은 저항 Group, 세 Prefix/세 Postfix 만석, 양손 장착 시 보조 해제와 인벤토리 공간 부족, 기존 마법서/반지의 기본 성능 이관, 같은 반지 두 개, BasicItem과 일반 저장 장비·NPC 사이의 차이를 포함한다. 자원 옵션으로 지속 시간이 늘어나도 실제 소비 증가·저항 상한을 빼고 기본 무한 시전이나 생존 보장으로 판정하지 않는다.

기존 BasicItemDiagnostics·ItemEnchantmentDiagnostics·NpcEquipmentSetDiagnostics를 확장하고 현재 Unity 프로젝트의 Runtime/Editor 컴파일·저장/전투 확인으로 완료를 판단한다. 이번 문서 정리에서는 그 실행 결과를 구현 완료로 제시하지 않는다. [src: Assets/Scripts/Editor/BasicItemDiagnostics.cs, Assets/Scripts/Editor/ItemEnchantmentDiagnostics.cs, Assets/Scripts/Editor/NpcEquipmentSetDiagnostics.cs]

구매·장착 비교·MOD 작업 전후·책 레벨업 흐름은 [공통 화면 설계](WEAPON_PROGRESSION_DESIGN.md#플레이어-성장-화면과-이용-흐름)를 따른다. 대표 성장 시나리오의 설계 연결을 점검했으며 재화별 Tier·비용·보류 특성은 계속 남긴다.

## 비무기 장착 비교와 성장 화면

> 상태: 2026-10-06 비무기 화면 초안. 재화별 MOD Tier·상세 비용과 보류한 변형 특성은 구현 전 재확인 대상으로 유지한다.

전체 구매·비교·제련소·책 성장 흐름은 [플레이어 성장 화면](WEAPON_PROGRESSION_DESIGN.md#플레이어-성장-화면과-이용-흐름)을 따른다. 기본 장비 구매는 새 장비를 가방에 넣고 현재 장비를 자동 교체하지 않는다. 신규/복구 마법서와 기본 변형이 실제로 생성 가능한 뒤 구매 후보에 연결한다.

| 부위 | 상품/옵션 상세 | 장착 비교에서 함께 표시할 값 |
| --- | --- | --- |
| 투구·갑옷·허리띠 | 기본 체력·방어도, 시작 저항과 일반 옵션 자리 | 전체 체력·방어도·각 저항·재생/마나의 증감 |
| 장갑 | 위 생존값과 일반 치명타 피해/시전 | 선택 스킬의 실제 치명타 피해·시전과 생존 변화. 미정 고정 치명타를 새로 가정하지 않음 |
| 장화 | 생존값과 실제 이동 옵션 | 이동·체력·방어도·저항 증감, 기존 이동 +1% 시작값은 그대로 표시 |
| 방패 | 체력·방어도·막기와 일반 옵션 | 전체 막기/생존 변화와 오른손 무기/선택 스킬 유지 |
| 보조 마법서 | 마나·재생·고정 시전과 일반 옵션 | 전체 마나/재생·시전·예상 주문 효과. 방패와 교체하면 사라지는 막기/생존도 포함 |
| 목걸이·반지 | 기본/고정/일반 능력의 구분 | 전체 생존·자원·치명타/시전과 저항, 반지는 선택한 한 슬롯만 교체 |

반지 두 개를 이름만으로 합쳐 선택하지 않는다. 상품은 같은 변형을 두 번 구매할 수 있고 비교는 반지 슬롯을 명시한다. 방패·마법서는 왼손 보조, 쌍수와 양손은 보조가 빠지는 전체 조합으로 비교하며 가방 공간 부족 시 장착 상태를 보존한다. [src: Docs/combat/ARMOR_ACCESSORY_PROGRESSION_DESIGN.md §부위별 기본 교체 순서·§비무기 구현 범위와 완료 조건]

제련소에는 실제 접두/접미 사용 수·현재 옵션·허용 후보를 표시한다. 약한 체력/방어도 시작 Prefix도 자리를 차지하며 같은 종류를 추가해 자동 승급할 수 있다고 안내하지 않는다. 마법서의 생존 후보와 자원 후보는 모두 실제 후보 비중으로 보여주고 장신구에 없는 체력/방어도 옵션을 목록에 넣지 않는다.

저항은 현재 전체 값과 실제 적용 상한을 반영한 값의 변화를 구분한다. 한 속성 저항을 모든 저항 증가처럼 표시하지 않는다. 마나·재생·시전은 각각 보여주고 시전이 빨라졌다는 이유로 자원 지속 시간도 좋아졌다고 단정하지 않는다. 부위 하나의 예산이나 5부위 확보 확률을 현재 한 번의 추가 확률로 표시하지 않는다.

변형 6종은 기존 저장/현행 특성을 보여주되 미정 고정 특성이나 공용 장갑 치명타를 빈 값을 0으로 채워 완료 표시하지 않는다. 장비 구간/Tier와 일반 MOD Tier를 별도 항목으로 구분하고 재화별 Tier 보장·비용은 사용자 답변 전 확정 문구를 붙이지 않는다.

화면 확인에는 동일 반지 두 개의 다른 옵션, 양손/쌍수로 보조 해제, 방패↔마법서 교체, 일반 옵션이 좋은 기존 장비, 약한 시작 Prefix와 가방/재화 부족을 포함한다. 전체 능력과 선택 스킬은 실제 장착 비교·툴팁과 같은 계산을 사용한다.

## 비무기 성장 시나리오 점검

> 상태: 2026-10-06 설계 연결 점검. 실제 비용·획득 시간·생존 검증 완료를 의미하지 않는다.

무기별 7개 대표 구성과 공통 획득→비교→MOD→책 성장→장비 교체는 [대표 성장 시나리오](WEAPON_PROGRESSION_DESIGN.md#대표-성장-시나리오와-설계-점검)를 따른다. 방어구·장신구는 한 부위씩 교체할 수 있고 무기나 책의 성장 완료를 기다릴 필요가 없다.

| 플레이 사례 | 설계 점검 결과 |
| --- | --- |
| 방어구 한 부위 교체 | 현재 다른 부위·책·무기를 유지해 총 체력/방어도/저항을 비교. MOD가 좋은 기존 장비가 우세하면 유지하고 새 장비는 별도로 작업 |
| 방패 → 보조 마법서 | 막기·체력·방어도가 줄고 마나·재생·시전이 바뀌는 전체 결과 표시. 마법서를 무기 평균에 넣거나 생존 유지로 처리하지 않음 |
| 보조 구성 → 쌍수/양손 | 실제로 빠지는 보조의 모든 옵션을 반영. 가방 공간이 부족하면 원래 장착 상태 유지 |
| 동일 반지 두 개 | 각각 별도 인스턴스로 구매·장착·MOD 작업. 두 반지의 고정/일반 옵션은 합산하고 Group 중복 제한은 각 아이템의 같은 슬롯에 적용 |
| 약한 HP/방어도 시작 Prefix | 같은 Group의 큰 옵션을 Add로 다시 붙이지 못함. 새 추천 변형·새 장비·현행 랜덤 교체가 선택지이며 자동 승급/선택 재롤 없음 |
| 시전과 마나 투자 | 최대 마나·재생·시전의 증감을 별도로 표시. 빠른 시전의 소비 증가까지 고려하기 전 지속 운용 개선으로 확정하지 않음 |

MOD를 전부 채운 뒤에만 교체하거나 두 반지/5부위를 동시에 성장시키는 조건은 추가하지 않는다. 새 장비에 기존 일반 MOD를 자동 이전하지 않으며 기존 장비의 옵션·소유 인스턴스는 남는다. 자원 보조 마법서는 장비이고 스킬을 보관하는 스킬북과 다른 대상이다. 장비 마법서는 제련소, 스킬북은 별도 스킬 레벨 성장 화면을 사용한다. [src: Docs/combat/ARMOR_ACCESSORY_PROGRESSION_DESIGN.md §부위별 기본 교체 순서·§MOD 옵션을 추가한 비무기 장비 성장·§비무기 장착 비교와 성장 화면, Assets/Scripts/Item/ItemEnchantmentService.cs HasGroupCollision]

재화에 따른 일반 MOD Tier는 구현 때 사용자에게 다시 질문한다. HP/방어도 확보 확률과 조건부 생존 표는 비용·수급·현재 후보 정책이 연결되기 전 실제 성장 시간이나 완성 보장으로 사용하지 않는다. 변형 6종·공용 장갑 치명타·상세 비용·책 레벨업 시점은 계속 보류한다.

## 이번 작업 결과와 다음 작업

교체점은 사용자 결정으로 1·10·20만 사용하고 중간 5·15를 제외한다. 비무기 추가 대상은 낡은 보조 마법서 1종이며 초급 마법서 44는 기존 데이터 보강 대상이다. 기존 32종+신규 1종의 비무기 33종을 계획하고 기본 방어구·목걸이·반지·방패의 새 중간 장비를 추가하지 않는다.

2026-10-05 사용자 정정으로 강화는 장비에 MOD 옵션을 추가하는 방식임을 명확히 했다. 단계 강화의 고정 능력 상승과 그에 기반한 생존·자원·교체 성능 표는 제거했다. 기존 기본 성능·대표 장비 비교를 유지하고 MOD 조합·수치로 구간 말 생존·자원을 다시 비교했다. 글로벌 상한 예산은 새 무기 후보 확대·양손 옵션 예산을 반영한 미래 초안으로 구분했다.

기존 방어구 변형 6종의 고정 특성과 공용 장갑 치명타 배분, 상세 골드 금액·수급·스킬 레벨업 가능 시점은 계속 보류한다. 실제 코드·테이블·아이템 ID·저장·드랍·상점은 이번 정정에서 바꾸지 않았다.

### 장비와 스킬북 공급 초안의 연결

공급은 [무기·스킬북 공급 설계](WEAPON_PROGRESSION_DESIGN.md#성장-구간별-장비와-스킬북-공급-초안)를 따른다. 세 교체점의 기본 장비를 선택 구매하고 동일 반지 두 개도 확보할 수 있도록 제안한다. 랜덤 장비 예산은 방어구 35%·보조 10%·장신구 15%·무기 40%, 현재/직전 구간은 10에서 10/1, 20에서 20/10을 80:20으로 둔다.

시작 마법서와 초급 마법서 44의 능력·BasicItem 연결 및 선택 목록·책 후보·드랍 분배는 미구현이다. MOD 추가 기능의 현행 소비·저장 경로와 성장 설계의 비용 방향을 구분하며 신규 5종 목록을 유지한다.

비무기 33종과 무기 37종의 데이터 연결표에 이어 MOD 후보 풀·효과 계열 가중치·핵심 Prefix와 전체 방어구 세트의 확보 확률을 정리했다. 구현 범위·완료 조건·성장 화면과 대표 성장 시나리오 점검까지 초기 설계 흐름을 마무리했다. 다음 실제 작업은 구현 시작을 요청받았을 때 [장비 분류·손 사용·도달거리 데이터 연결](WEAPON_PROGRESSION_DESIGN.md#다음-작업-순서)이다. 현재는 설계 단계이며 실제 코드·테이블·ID 생성은 구현 때 진행한다.
