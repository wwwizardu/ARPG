# 밸런스 디자인 (Balance Design)

## 개요

ARPG 전투 밸런스 기준 문서. **Path of Exile 2 톤(methodical combat)**을 목표로 하며, 캐릭터/몬스터 스탯 곡선, 방어 공식, TTK/TTD 목표값을 정의한다.

본 문서는 **설계 기준**이며, 실제 코드/테이블 마이그레이션은 별도 작업 항목으로 진행한다.

---

## 1. 핵심 디자인 결정

### 1.1 게임 톤
- **PoE2식 methodical combat**: 일반몹도 1~2타 견디며, 회피/포지셔닝/포션이 항상 의미 있음
- 디아3 시즌식 "0.1초 컷" 폭발 플레이 ❌
- "큰 한 방은 회피 강제, 작은 다타는 방어로 막음" 디자인

### 1.2 캐릭터/몬스터 레벨 모델
| 대상 | 레벨 보유 | 비고 |
|---|---|---|
| **캐릭터(플레이어)** | **없음** | 장비 + 스탯 mod로만 성장 |
| **몬스터** | **있음 (1~95)** | 청크 거리 기반 결정 |
| **장비(아이템)** | DropLevel | 몬스터 레벨과 동급 매칭 |

> 캐릭터 레벨이 없으므로, 데미지 공식의 K 상수는 공격자/방어자 레벨에 의존하지 않는다.

### 1.3 진행 구조
- **캠페인**: 청크 1~~70 (난이도 점진 증가)
- **엔드게임**: 청크 70~~95+ (빌드 완성도 보상, 보스 사이클 등)

## 2. TTK / TTD 목표값

### 2.1 TTK (몬스터 처치 시간) — 동급 레벨 장비 기준

| 카테고리 | 캠페인 | 엔드게임 (잘 빌드한 상태) |
|---|---|---|
| 일반몹 (white) | **1.5~3초** | 0.5~1.5초 |
| 마법몹 (blue) | 3~6초 | 1.5~3초 |
| 희귀/엘리트 (yellow) | 6~15초 | 3~8초 |
| 액트 보스 | 30~60초 | — |
| 엔드게임 보스 (Pinnacle) | — | 60~180초 |

### 2.2 TTD (플레이어 사망 시간) — HP 대비 한 방 데미지

| 적 유형 | 한 방 데미지 (플레이어 HP %) | 의미 |
|---|---|---|
| 일반몹 평타 | 5~10% | 10~20방 견딤 |
| 엘리트 평타 | 15~25% | 4~6방 |
| 보스 평타 | 20~35% | 3~5방 |
| **보스 텔레그래프 스킬** | **50~100%** | **회피 강제, 1~2방** |

## 3. 레벨별 곡선

### 3.1 몬스터 스탯 곡선 (Level N 기준)

| 항목 | 레벨당 배율 | 의미 |
|---|---|---|
| MaxHp | **×1.12** | ≈6레벨마다 2배 |
| AttackMin/Max | **×1.10** | ≈7레벨마다 2배 |

산식 예시:
```
MonsterHpAtLevel(N)    = BaseHp    × 1.12^(N-1) × ArchetypeHpMul
MonsterDmgAtLevel(N)   = BaseDmg   × 1.10^(N-1) × ArchetypeDmgMul
```

### 3.2 장비 곡선 (DropLevel N 기준)

| 항목 | DropLevel당 배율 | 의미 |
|---|---|---|
| 무기 DPS | **×1.13** | HP 곡선보다 살짝 가파름 → 장비 교체 압박 |
| 방어구 EHP 기여 | ×1.10 (목표) | 적 데미지 곡선과 일치 |

> **5~10 DropLevel 안 바꾸면 명백히 약해진다**는 텍스처를 유지.

### 3.3 Archetype 배율 (예시)

| Archetype | HP Mul | Damage Mul | 비고 |
|---|---|---|---|
| Normal | 1.0 | 1.0 | 기본 잡몹 |
| Magic (Blue) | 2.0 | 1.2 | 약간 강한 잡몹 |
| Rare/Elite (Yellow) | 5.0 | 1.5 | 미니 보스 |
| Boss | 30~50 | 2.0 | 액트/엔드게임 보스 |

> 배율 자체는 시뮬 시트에서 튜닝.

## 4. 방어 시스템 (핵심)

### 4.1 데미지 적용 순서 (PoE2식)

```
1. 공중 무적 / 무적 시간 → 0
2. 회피 체크 (Evasion%) → 회피 시 0
3. 속성별 데미지 산출 (Phys / Fire / Ice / Lightning / Poison)
4. 치명타 판정 → 모든 속성에 곱연산
5. 속성별 방어 적용:
   - Phys → Armor 공식
   - Fire/Ice/Lightning/Poison → 각 저항
6. 합산
7. 블록 판정 → 블록 시 BlockReduction% 차감
8. 최소 데미지 보장 (max(1, ...))
```

### 4.2 아머 (물리 방어)

**공식 (PoE 원본)**:
```
물리 감소율 = Armor / (Armor + 10 × IncomingDamage)
최종 물리 데미지 = IncomingDamage × (1 - 물리 감소율)
```

특성:
- **작은 다타 공격**: Armor가 잘 막아줌 (잡몹 떼)
- **큰 한 방**: Armor 거의 무용지물 (보스 강타) → 회피/저항으로 대응
- 공격자/방어자 레벨 정보 **불필요** ✅

예시 (Armor 500):
| 들어온 데미지 | 감소율 | 최종 데미지 |
|---|---|---|
| 100 | 33% | 67 |
| 500 | 9% | 455 |
| 1000 | 4.8% | 952 |

### 4.3 원소 저항 (Fire / Ice / Lightning / Poison)

**공식 (PoE 원본 단순 %)**:
```
저항 감소율 = min(Resist, MaxResist, 90) / 100
최종 원소 데미지 = IncomingDamage × (1 - 저항 감소율)
```

특성:
- 수치 그대로 % (FireResist 65 = 65% 감소)
- Max Resistance에서 캡

| FireResist 수치 | 감소율 (Max 75 기준) |
|---|---|
| 0 | 0% |
| 50 | 50% |
| **75** | **75% (캡 도달)** |
| 100 | 75% (캡) |
| 1000 | 75% (캡) |

### 4.4 Max Resistance

| 항목 | 값 |
|---|---|
| **Base Max Resistance** | **75%** |
| **Hard Cap (절대 한계)** | **90%** |
| 신설 스탯 | `MaxFireResist`, `MaxIceResist`, `MaxLightningResist`, `MaxPoisonResist` (4종) |
| 기본값 | 각 75 |
| 증가 수단 | **현 단계 없음** (향후 패시브/장비/드랍으로 추가) |

> 캡 증가가 희소한 디자인은 PoE2 톤과 일치 (실질 상한 80% 안팎).

### 4.5 회피 / 블록
- **Evasion**: 합산 후 판정 (현행 유지). 회피 성공 시 데미지 0
- **Block**: 합산 후 판정. 블록 성공 시 `BlockReduction%` 차감

## 5. 장비 시스템 (현 단계)

| 항목 | 현 단계 결정 | 향후 |
|---|---|---|
| **착용 제한** | **없음** (아무거나 끼움) | 스탯 요구치 또는 청크 진행도 기준 도입 예정 |
| **DropLevel 매칭** | 몬스터 레벨 ≈ DropLevel | — |
| **장기 성장축** | 장비 + 스킬북 | 별도 메커니즘 추가 예정 (패시브 트리 등) |

## 7. 구현 로드맵

### Phase 1 — 공식 마이그레이션 (코드)
1. `StatComponent` 에 4종 `MaxXxxResist` 필드 추가, 기본 75
2. `DamageDefenseCacheComponent` 캐시 구조 갱신 (저항은 단순 %, 캡 적용)
3. `System_StatCalculation.BuildDefenseCache` 공식 변경
4. `DamageCalculator` 아머 공식을 `Armor / (Armor + 10 × Damage)`로 변경
5. `GE.Stat` enum에 `MaxFireResist` 등 추가, `ApplyModifier` 분기 추가

### Phase 2 — 데이터 마이그레이션 (테이블)
1. `StatTable`의 `FireResist` 등 기존 값 → 새 단위 변환 (필요시)
2. `ModTable`의 저항 prefix/postfix 값 검토
3. `MonsterTable` 레벨/Archetype 컬럼 검토 (이미 `Level` 있음)
4. 무기/방어구 base stat 곡선 정비 (DropLevel당 ×1.13)

### Phase 3 — 시뮬 시트 (구글 시트)
1. 레벨 1~95 × Archetype × HP/DMG 표
2. 동급 장비(DropLevel = MonsterLevel) DPS/EHP 표
3. TTK / TTD 자동 계산, 목표값 비교
4. 곡선 상수(1.12 / 1.10 / 1.13) 튜닝

### Phase 4 — 컨텐츠 튜닝
- 보스/엘리트 개별 튜닝
- 청크 진행도와 난이도 곡선 매칭
