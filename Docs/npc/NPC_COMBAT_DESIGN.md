# NPC 실전투 · 동행 · 결투 런타임 설계
_초안 작성: 2026-09-24 — [NPC_AMBITION_DESIGN.md](NPC_AMBITION_DESIGN.md) §8.0·§8.8에서 분리_

> **한 줄**: 지금은 전투 부품만 있고 싸우지 않는 NPC가, **동행 중이거나 결투 중일 때만** 화면 안에서 실제로 싸우게 만든다.
>
> **상태**: 🟩 B 단계 구현 완료 — B1~B5 완료(2026-09-27). 동행은 던전 전용이 최종 설계(D97, 2026-10-01). 도주(§5)는 보류[D25], NPC 간 결투의 화면 안 장면(§7.5)은 나중에 구현[D24], 화면 밖 판정은 AMBITION P3. 구현 위치는 §4.6(동행), §6.1(드랍 줍기), §7.6(결투).
>
> **책임**: NPC 실전투의 **런타임 메커니즘**을 정의한다. 진영, 인식, 추종, 순간이동, 던전 동반, 임시 동행 요청(던전 전용), 도주, 드랍 줍기, 결투 진행, 무릎 꿇기, 전투 사망 처리가 여기에 속한다.
>
> **책임이 아닌 것**: *언제, 왜* 싸우는지와 *그 결과가 사회에 주는 영향*은 [NPC_AMBITION_DESIGN.md](NPC_AMBITION_DESIGN.md)가 소유한다. 동행 제안·분배 약속·정산(§8.1), 배신 판정(§8.3~8.7), 결투의 명분·응답·드랍·관계 파장(§8.8), 플레이어의 배신(§8.9)이 거기에 있다. 본 문서는 그 규칙이 끼워질 **자리(훅)** 만 제공한다.

## 3. 전투 허용 상태와 진영

### 3.1 원칙

- 실전투는 **동행 중이거나 결투 중인 NPC**에게만 켠다. 그 외 NPC는 지금처럼 싸우지 않는 중립 상태를 유지한다.
- **`NpcActivityPausedTag`가 붙은 NPC(화면 안에서 사냥 중)는 전투 허용 대상에서 제외한다.** 사냥 결과는 계산 판정이 소유한다(NPC_SIMULATION 계약).
  - **예외 — 플레이어와의 결투** [D19]: 원정 중 화면 안에서 대기하는 NPC에게도 결투를 신청할 수 있다. 결투 동안만 태그를 떼고 전투를 허용하며, 그동안 활동·파티 판정은 보류한다. 결투가 끝났을 때 활동이 남아 있으면 다시 대기시킨다. 사냥 결과 계산 로직은 바꾸지 않는다(§9). (2026-09-27 확정)
- 한 번에 실전투를 하는 NPC는 몇 명에 불과하므로 성능 부담은 작다.

### 3.2 진영 명시 (요소 1)

- 모든 NPC에 `FactionComponent { Neutral }`을 **명시적으로** 붙인다. "컴포넌트 없음 = 중립"이라는 암묵 규칙에 기대지 않는다.
- 동행을 시작하면 `Player`로 바꾸고, 끝나면 `Neutral`로 되돌린다.

### 3.3 결투 상대 한정 적대 (요소 2)

- 현재 진영은 `Neutral`/`Player`/`Hostile` 3개뿐이라 "**두 참가자만** 서로 적대"를 표현할 수 없다. NPC를 `Hostile`로 바꾸면 몬스터와 한편이 되기 때문이다.
- 결투 컴포넌트(예: `DuelComponent { OpponentId }`)를 두 참가자에게 붙인다.
- 적대 판정의 단일 지점에서 **결투 쌍이면 적대**로 덮어쓴다.
  - `FactionHelper.IsHostileTo` / `IsFactionHostile`
  - `FactionHelper.FindNearestEnemy`
  - 스킬 피격 판정 경로
- 결투 쌍 예외는 진영 판정보다 **우선**한다. 동행 중인 NPC와 결투하게 되더라도(유형 6, D19) 결투 쌍 규칙이 이긴다.
- **몬스터는 끼어든다** [D21]. 1:1 격리는 두지 않는다.
  - 결투 중인 NPC 참가자는 진영이 `Neutral`이어도 **몬스터의 적대 대상**이 된다(평소에는 몬스터가 NPC를 무시한다).
  - 몬스터는 어그로 시스템이 없으므로, 근처의 결투 참가자(플레이어·NPC) 중 **무작위로** 타겟을 고른다. 결투와 무관한 몬스터의 타겟 규칙(가장 가까운 적)은 바꾸지 않는다.
  - 제3자 NPC(결투와 무관한 NPC)는 끼어들지 않는다.
- 결투 중 NPC 참가자는 결투 상대만 노린다(Q10 확정). 인식뿐 아니라 피격 판정에도 적용해서 광역 스킬로도 몬스터를 맞히지 않는다. 몬스터에게 피해는 받는다.

### 3.4 조건부 인식 (요소 3)

- `System_AI_Perception`의 "NPC면 건너뛰기"를 "**전투 허용 상태가 아닌 NPC면 건너뛰기**"로 좁힌다.
- 전투 허용 여부는 태그로 게이트한다(예: `NpcCombatEnabledTag`). 동행 시작·결투 시작 때 붙이고 끝날 때 뗀다. `NpcActivityPausedTag`가 있으면 붙이지 않는다. 단, 결투 시작 때는 `NpcActivityPausedTag`를 먼저 떼고 붙인다(§3.1 예외).
- 결투 중에는 인식 대상을 결투 상대로 고정한다(Q10). 결투 영역이 없으므로(D20) 거리와 무관하다.
- 몬스터는 감지 범위 안의 결투 참가자 중 무작위로 타겟을 고른다. 이미 참가자를 쫓고 있으면 놓침 범위 안에서는 타겟을 유지한다(B4).

## 4. 동행 런타임

> 동행의 **시작 조건·분배 약속·정산**은 AMBITION §8.1(C1 단계) 소관이다. 본 문서는 동행이 **진행되는 동안의 움직임**을 다룬다.
>
> **던전 전용 동행** [D15, D97]: 동행은 **던전 안에서만** 한다. 대화로 동행을 요청하면, 플레이어가 그 뒤 처음 들어가는 던전에서 NPC가 소환되고, 던전에서 나오면 NPC는 원래 마을로 돌아간다(§4.5). B 단계에서 시험용으로 만든 형태였으나 2026-10-01 **최종 설계로 확정**했다(D97). 필드에서 따라다니는 동행은 만들지 않는다. 동행 수락 조건과 전리품 분배·정산은 C1(미정)에서 이 위에 얹는다.

### 4.1 아군 피해 없음 [D13]

- 동행 NPC는 `Player` 진영이므로 플레이어의 스킬(광역 포함)에 맞지 않는다. 기존 진영 판정이 그대로 처리하므로 별도 예외 코드는 필요 없다.
- 결투가 시작되면 §3.3의 결투 쌍 예외가 우선한다.

### 4.2 추종 상태 (요소 4)

- 새 AI 상태(예: `AIState.Follow`)를 추가한다. 플레이어와 일정 거리(예: 2~4타일)를 유지하며 따라간다.
- 적을 인식하면 기존 Chase/Attack(근접·원거리 핸들러)으로 전환하고, 적이 없어지면 Follow로 돌아온다.
- 플레이어에게서 너무 멀리 떨어진 적은 쫓지 않는다(추종 반경 밖이면 Follow 우선).

### 4.3 순간이동 [D14]

- 플레이어와 일정 거리(예: 화면 밖, 약 15타일) 이상 떨어지거나 길찾기가 일정 시간 실패하면, 플레이어 근처의 **통행 가능한 타일**로 순간이동한다.
- **던전 안**(§4.5)에서는 B2부터 적용한다. 방과 통로 구조에서 NPC가 끼거나 뒤처지는 것을 막는다.
- 동행 NPC는 `System_AI_Behavior`의 "비활성 청크에서는 AI를 돌리지 않는다" 규칙에서 **예외**다. 뒤처져 비활성 청크에 남은 NPC도 Follow가 돌아야 순간이동할 수 있기 때문이다. 순간이동 거리(15타일) 안쪽에서 경로가 비활성 청크를 지나면 길찾기가 실패하고, 실패가 3초 이어지면 순간이동한다. [확정: B2]
- **필드**에는 적용하지 않는다. 동행은 던전 전용이다(D97).

### 4.4 던전 동반 [D14, D97]

- **최종 형태는 §4.5의 던전 전용 동행이다**(D97, 2026-10-01). 원안의 "필드에서 함께 다니던 동행 NPC가 던전 입구에서 함께 들어가고 나온다"는 폐기했다.
- 입장·퇴장·저장·재접속 복원에 동행 NPC를 포함하는 처리는 §4.5·§4.6에 구현돼 있다.
- 던전 컨텍스트 전환에 동행 NPC를 포함하는 것은 [DUNGEON_RUNTIME_DESIGN](../map/DUNGEON_RUNTIME_DESIGN.md) §5.3의 **추가 계약**이다.

### 4.5 동행 요청 — 던전 전용 [D15, D97]

**흐름**

```
마을에서 NPC와 대화 → "동행 요청" → 동행 예약 (NPC는 마을에서 평소대로 지냄)
  → 플레이어가 아무 던전에 입장 (예약 후 첫 던전)
  → 던전 입장 지점 옆에 NPC 소환: 진영 Player + 전투 허용 태그 + Follow 상태
  → 던전 안에서 함께 이동·전투
  → 던전에서 나옴 (ESC 퇴장 / 플레이어 사망 퇴장 모두)
  → 동행 종료, NPC는 원래 마을로 귀환
```

**요청**
- 대화 메뉴에 **"동행 요청"** 이 뜬다. 지금은 호감도 조건 없이 **항상 수락**한다(수락 조건은 C1, 미정).
- 요청할 수 없는 상태: NPC가 부상(Wounded) 중이거나 원정 중(Venturing)이다. 이미 다른 NPC와 동행 예약이 있다(한 번에 1명).
- 예약한 NPC와 다시 대화하면 **"동행 취소"** 가 뜬다. 예약은 시간이 지나도 **만료되지 않는다** [D17].
- 예약만 한 상태에서는 NPC가 평소처럼 마을에서 지낸다. 필드에서 따라다니지 않는다.
- 요청·취소는 **던전 밖에서만** 한다. 던전 안에서는 대화 메뉴에 동행 버튼을 띄우지 않고, 던전 안 동행은 퇴장으로만 끝난다.

**소환 (던전 입장 시)**
- 던전 입장(`DungeonManager.EnterAsync`)이 끝나고 내부가 활성화된 뒤, 예약된 NPC를 **플레이어 옆 통행 가능한 타일**에 실체화한다.
- 같은 NPC가 두 곳에 동시에 존재하면 안 된다. 월드 쪽 엔티티는 입장 시 월드 맵이 비워질 때 함께 비실체화되고, 던전에서는 **같은 EntityId**로 실체화한다(`EntityFactory.CreateNpc`의 `savedEntityId` 재사용). 구현 시 월드 엔티티가 확실히 제거되는지 검증한다.
- 소환 시점에 NPC가 죽었거나 부상 중이면 예약을 취소하고 소환하지 않는다(알림 표시). 원정 중(Venturing·파티 소속)인 경우도 방어적으로 같이 취소한다. 정상 흐름에서는 아래 제외 조건 때문에 생기지 않는다.
- 검증은 입장 저장 **직전**에 하고, 통과하면 던전 안 동행 여부를 입장 커밋에 함께 저장한다. 소환 자체가 실패해도 입장은 실패시키지 않는다(퇴장 때 마을로 되돌린다).

**던전 안**
- §4.1 아군 피해 없음, §4.2 추종, §4.3 던전 안 순간이동을 적용한다.
- 던전 보스를 잡아 완료해도 동행은 **퇴장할 때까지** 유지한다.
- NPC는 전리품을 줍지 않고, 던전 보상(상자·완료 보상)은 모두 플레이어가 갖는다 [D16]. 분배·정산은 C1.
- 던전 안에서 NPC가 죽으면 §8 전투 사망 연결로 영구 사망 처리하고 동행을 **즉시** 종료한다. 이후 저장·재접속은 죽은 NPC를 소환하지 않는다(B3).

**퇴장 → 원래 마을로 귀환**
- 던전 퇴장(`ExitAsync`) 시 동행을 종료한다. ESC 퇴장과 플레이어 사망으로 인한 퇴장(`death = true`) 모두 같다.
- 진영을 `Neutral`로, 전투 허용 태그를 제거하고, 던전 쪽 엔티티를 비실체화한다.
- NPC의 위치를 **소속 마을**(`NpcSaveData.VillageId`)의 NPC 배치 위치로 되돌린다. 위치는 기존 NPC 스폰·배치 규칙을 재사용한다 [D18]. 해당 청크가 활성이면 그 자리에 실체화하고, 아니면 저장 위치만 바꾼다(다음에 청크가 로드될 때 마을에 나타난다).
- **소속 마을이 없는 NPC**(`VillageId = -1`)는 플레이어의 던전 입구 복귀 지점으로 돌아간다. D18이 가리킬 배치 위치가 없기 때문이다. [확정: B2]
- NPC의 활동 상태는 Idle로 돌려 다음 활동 선택을 기존 시뮬레이션에 맡긴다.

**저장 · 재접속**
- 동행 예약·진행 상태(예약 NPC EntityId, 던전 안 동행 여부)는 **World 파티션**에 저장한다. 던전 입장·퇴장 커밋이 이미 World 범위를 포함한다. `NpcSaveData`에는 필드를 추가하지 않는다(§9).
- 던전 안에서 저장 후 재접속하면(`RestoreSessionAsync`) 동행 NPC를 플레이어 옆에 다시 소환한다.
- 예약만 한 상태에서 저장·재접속하면 예약이 유지된다.
- 동행 중에는 NPC의 **던전 좌표를 월드 저장 위치·청크 인덱스에 쓰지 않는다.** 저장 위치는 입장 전 월드 위치로 유지되고 퇴장 시 마을 위치로 바뀐다. 던전 안에서 전체 저장을 해도 재접속 때 월드 청크 인덱스가 오염되지 않는다(B3).
- 동행 NPC의 HP는 저장하지 않는다. 재접속하면 최대 HP로 소환된다.
- 던전 체크포인트 저장은 NPC 파티션을 포함하지 않으므로, 던전 안 사망 기록은 다음 전체 저장 때 파일에 남는다(필드 사망과 같다). 그 사이 비정상 종료되면 NPC는 생존 상태로 복원되고 동행만 끝난 상태가 된다.

**화면 밖 시뮬레이션과의 관계**
- 동행 중(던전 안)인 NPC는 `System_NpcSim`의 활동 선택·판정 대상에서 **제외**해야 한다. 그렇지 않으면 던전에 있는 NPC가 동시에 사냥을 떠나는 상태가 된다. 이것이 A 갈래 코드에 대한 **유일한 추가 접점**이다(§9).
  - 참고: 2026-10-19부터 `System_NpcSim`과 `System_Time`은 던전 안에서도 돈다(`IWorldSimSystem`, [DUNGEON_WORLD_SIM_DESIGN §3.5](../map/DUNGEON_WORLD_SIM_DESIGN.md)). 처음에는 구조가 바뀔 때를 대비한 방어선이던 이 제외 조건이, 이제 던전 안 동행 NPC가 판정되지 않게 막는 실제 규칙이다.
- 예약만 한 상태에서는 제외하지 않는다. 다만 예약 중에 원정(Hunt)을 떠나지 않도록, 예약 NPC는 활동 선택에서 Rest만 고른다. [확정: B2]
- 예약 NPC는 **다른 NPC의 사냥 파티 모집에서도 제외**한다. Rest 고정만으로는 다른 리더가 만드는 파티(`NpcManager.TryCreateHuntParty`)에 뽑혀 원정을 떠나는 경로가 남기 때문이다. [확정: B2]

## 6. 드랍 줍기 (요소 7)

- NPC가 바닥의 월드 드랍을 집어 **자기 인벤토리**(`NpcSaveData.Inventory`)로 옮기는 동작을 만든다. 현재는 플레이어 입력 경로만 있다.
- 드랍 위치로 이동 → 줍기 → 인벤토리 반영의 짧은 시퀀스다. 인벤토리가 가득 차면 줍지 않는다.
- **플레이어 인벤토리·장비의 아이템은 대상이 아니다**(AMBITION §8.2). 바닥의 드랍만 대상이다.
- 사용처: 배신 유형 1(전리품 가로채기). B 단계에서는 디버그 명령으로 줍기만 검증한다.
- 평소 동행 중에는 줍지 않는다(D16 유지). 줍기는 디버그 명령과 이후 C1 배신 규칙만 호출한다.
- 기본값: NPC 주변 8타일 안의 가장 가까운 드랍 1개를 대상으로 한다. 주운 아이템은 다음 전체 저장 때 NPC 파티션에 기록된다(그 사이 비정상 종료 시 사라질 수 있음을 B5에서는 허용).
- **드랍 제거는 즉시 저장한다**(B5 구현 결정). 바닥에서 사라진 것은 플레이어 줍기처럼 바로 Map(던전 안이면 Dungeons) 파티션에 저장하고, NPC 인벤토리는 위 기본값대로 다음 전체 저장에 맡긴다. 그래서 비정상 종료 시 아이템이 사라질 수는 있어도, 바닥과 NPC 인벤토리 양쪽에 **복제되지는 않는다.** (결투 후 저장처럼 Map이 빠진 부분 저장이 먼저 일어나도 복제가 생기지 않게 하기 위해서다.)
- 가장 가까운 드랍이 인벤토리에 들어가지 않으면 더 먼 드랍을 찾지 않고 거절한다. 두 NPC가 같은 드랍을 노리면 먼저 도착한 쪽이 줍고 나머지는 취소된다.
- 시작하지 않는 조건: 실체화되지 않음·사망, 원정 중 화면 안 대기(`NpcActivityPausedTag` — 사냥 경로 계약 유지), 결투 중, 이미 줍는 중, 던전 전환 중. 동행 중인 NPC는 막지 않는다(C1 배신 유형 1이 이 경로를 쓴다).
- 취소 조건: 대상 드랍이 사라짐(플레이어가 먼저 주운 경우 포함), NPC 소멸, 결투 시작, 원정 대기 전환, 도착 시 인벤토리가 가득 참, 제한 시간 15초 초과, 길찾기 3초 연속 실패. 취소되면 인벤토리·드랍은 그대로이고 AI는 원래 상태로 돌아간다.
- 줍는 동안(최대 15초)은 기존 AI가 멈추므로 동행 NPC라도 교전하지 않는다. C1에서 배신 연출과 함께 다시 검토한다.

## 7. 결투 런타임

> 결투의 **명분 판정·신청 가능 여부·NPC의 수락/거절·드랍 규칙·관계 파장**은 AMBITION §8.8 소관이다. 본 문서는 결투가 **수락된 뒤부터 끝날 때까지**의 진행을 다룬다.

### 7.1 진행 흐름 (플레이어 ↔ NPC)

```
대화 메뉴 "결투 신청" → (B4: 항상 수락)
  → 두 참가자에 DuelComponent + NPC에 전투 허용 태그 → 그 자리에서 전투 (몬스터도 끼어듦)
  → 한쪽 HP 0 → HP 1로 두고 결투 종료 (HP 0이 된 쪽이 패자)
    또는 실제 시간 3분 경과 → 무승부로 종료
  → 결과 처리 훅 → 컴포넌트·태그 제거, 진영·AI 원복 (NPC는 대기 상태)
    동행 중이던 NPC는 동행 종료 → 마을로 귀환
```

### 7.2 진행 규칙 (2026-09-27 결정 반영)

- **신청** [D19]: 플레이어는 어떤 NPC에게든 신청할 수 있다. 부상·원정(화면 안에서 대기 중 포함, §3.1 예외)·동행 예약·동행 중인 NPC와 던전 안도 가리지 않는다. 대화 메뉴로 신청하므로 근처에서만 가능하다. B4에서 NPC는 항상 수락한다(스텁).
- **장소** [D20]: 신청한 자리에서 바로 시작한다. 결투 영역·반경·이탈 기권·영역 표시는 **없다.**
- **몬스터** [D21]: 근처에 몬스터가 있어도 진행한다. 몬스터는 결투 참가자 중 무작위로 타겟을 골라 공격한다(§3.3).
- **적대 전환**: 결투 중에만 두 참가자가 서로 적대가 된다. 끝나면 즉시 원래대로 돌아간다.
- **종료** [D22]: 플레이어든 NPC든 **HP가 0이 되면 사망 경로 대신 HP 1로 두고 결투를 끝낸다.** HP 0이 된 쪽이 패자다.
  - 이 처리는 사망·파괴 파이프라인보다 **먼저** 가로챈다. 던전의 플레이어 사망을 가로채는 `System_HpCheck` → `HandleDeath`와 같은 자리다.
  - 결투로는 **아무도 죽지 않는다.** 결투 중에는 원인과 관계없이(몬스터 공격 포함) HP 0이 되면 같은 규칙으로 끝나고, 그 참가자가 패자다(Q11).
- **시간 제한** [D27]: 결투가 **실제 시간 3분** 안에 끝나지 않으면 **무승부**로 종료한다. 무승부는 HP를 바꾸지 않는다.
  - 게임이 멈춘 시간(던전 ESC 메뉴 등으로 `GameplayPaused`인 동안)은 세지 않는다.
  - 결과 없이 취소하는 다른 조건(거리, 영역 이탈 등)은 두지 않는다.
  - 기술적 정리: 참가자 엔티티가 사라지면(청크 이탈로 비실체화 등) 무승부로 종료한다.
- **종료 후 NPC**: 싸움을 멈추고 대기 상태(기본 AI 상태)로 돌아간다.
- **상태이상 정리**: 결투가 끝나면 플레이어와 NPC 양쪽의 해제 가능한 버프·디버프(`IsDispellable=true`)를 제거한다. 출혈·점화·중독 같은 DoT가 종료 직후 참가자를 실제 사망시키는 경로를 남기지 않는다. 향후 패시브·영구 효과는 `IsDispellable=false`로 등록해 유지한다.
- **동행 NPC와의 결투** [D26]: 동행 중(던전 안)인 NPC와 결투했다면, 결투가 끝나면(승패·무승부 무관) 동행을 끝내고 NPC를 **소속 마을로 귀환**시킨다. 처리는 던전 퇴장 시 귀환(§4.5, `FinishCompanionDungeonExit`)과 같다. 동행 예약만 한 NPC(아직 던전에 들어가지 않음)와 결투한 경우 예약은 유지한다.
- **던전** [D23]: 던전 안 결투를 허용한다. 결투 중에는 E 상호작용 후보와 프롬프트를 숨기고, 던전 입장·퇴장 요청도 상태 변경 전에 거부한다. 보스 완료 트랜잭션은 결투가 끝날 때까지 대기한다.
- **저장 거부**: 결투 중에는 던전 체크포인트를 포함한 **모든 일반 저장 요청을 즉시 거부**하며 나중에 재실행하지 않는다. 결투가 정상 종료되면 결과를 한 번 저장한다.
- **입회인**: 주변 NPC 목록을 결과 처리 훅에 넘긴다(목격 소문은 AMBITION 소관).
- **보호 없음** [D8]: 소망 진행 중인 NPC, 마을의 유일한 NPC도 결투할 수 있다.
- **회복 수단**: 아이템 사용 기능이 아직 없으므로 제한할 대상이 없다(Q1 해소).
- **재신청**: 쿨다운 없이 언제든 다시 신청할 수 있다(Q15).

### 7.3 무릎 꿇기 (요소 6) — 제외 [D22]

- 무릎 꿇기와 처단/자비 선택은 두지 않는다. 결투는 §7.2의 "HP 1로 종료" 규칙으로만 끝난다.
- 결투로 NPC를 죽이는 **처단** 경로는 C2에서 AMBITION §8.8(D6)과 함께 다시 검토한다.

### 7.4 결과 처리 훅

결투가 끝나면 다음 정보를 AMBITION 쪽 규칙에 넘긴다.

| 필드 | 내용 |
|------|------|
| 참가자 | 두 EntityId |
| 결과 | 승자 / 패자 (HP 0이 된 쪽), 또는 무승부 (3분 경과·참가자 소멸) |
| 입회인 | 주변 NPC 목록 |
| 명분 | 시작 시 AMBITION이 판정해 넘긴 값 |

- 종료 사유는 `DuelEndReason`(Defeat / Timeout / ParticipantLost)으로 넘긴다.
- B 단계(B4)에서는 명분 판정과 NPC 응답을 **스텁**으로 둔다(항상 "명분 없음", 항상 수락). 플레이어↔NPC 결투의 관계 파장은 적용하지 않고 NPC Deeds에 결과만 기록한다(`DuelWon`/`DuelLost`/`DuelDrawn`, 참가자에 플레이어 포함). 플레이어 쪽 Deeds 저장소는 두지 않는다(Q12). C2에서 AMBITION 규칙으로 교체한다.

### 7.5 NPC 간 결투 — 화면 안 장면만 ⏸ 나중에 구현 [D24]

화면 안에서 두 NPC가 실제로 싸우는 **장면**은 B4 범위에서 제외하고 나중에 구현한다. 화면 밖 결과 판정(시뮬레이션)은 AMBITION P3에서 구현한다.

- 두 NPC가 **같은 마을에서 둘 다 대기(Idle) 중**일 때만 일어난다 [AMBITION D30].
- **둘 중 하나라도 실체화된 NPC는 참가하지 않는다** [AMBITION D30]. 화면 안 장면이 생기기 전까지, 눈앞의 NPC가 싸우는 모습 없이 부상 상태가 되는 일을 막는다.
- 플레이어와 동행 중이거나 동행 예약된 NPC, 플레이어와 결투 중인 NPC는 참가하지 않는다.
- 계기·빈도, 승패와 관계 변화, 평가 위치는 P3 착수 때 확정한다. 기본안은 §11 Q16~Q18.

### 7.6 구현 위치와 세부 규칙 (B4)

| 역할 | 위치 |
|------|------|
| 결투 상태 | `DuelComponent { OpponentId, ElapsedSeconds, PendingLoserId, Grievance }` — 두 참가자에게 붙고 저장하지 않는다. 명분 등급은 `DuelGrievance`(None/Weak/Strong) |
| 신청·시작·종료 | `NpcManager_Duel.cs` (`CanRequestDuel`, `RequestDuel`, `TryInterceptDuelDefeat`, `EndPlayerDuel`, `ApplyDuelOutcome`) |
| 종료 판정 | `System_Duel` (FixedUpdate, Priority 255 — HP Check 250 직후). 패배 확정 → 참가자 소멸 → 3분 경과 순으로 본다. `GameplayPaused` 동안은 돌지 않으므로 멈춘 시간은 세지 않는다 |
| HP 0 가로채기 | `System_HpCheck` — 사망 처리와 `Dungeon.HandleDeath`보다 먼저 `TryInterceptDuelDefeat` |
| 적대 판정 | `FactionHelper.IsEntityHostile` — 결투 쌍 적대 > 결투 중 NPC는 상대만 > 결투 중 NPC는 몬스터의 적대 대상 > 기존 진영 판정. `IsHostileTo`, `FindNearestEnemy`, `System_Skill`, `System_Projectile`, `System_AreaEffect`, `SkillPropagationTargetSelector`가 이 함수를 거친다 |
| 인식 | `System_AI_Perception` — 결투 중 NPC는 상대 고정, 몬스터는 참가자 중 무작위(§3.4) |
| 저장 거부 | `DataManager.SaveAsync`가 결투 중 일반 저장 요청을 즉시 `false`로 거부한다. 정상 종료 시 `NpcManager.EndPlayerDuel`이 Player·World·NpcState(던전 안이면 Dungeons)를 한 번 저장한다 |
| 던전 트랜잭션 | `DungeonManager.EnterAsync` / `ExitAsync` / `CompleteAsync`는 결투 중이면 상태를 변경하기 전에 `false`를 반환한다. 보스 완료는 결투가 끝난 뒤 재시도한다 |
| 상태이상 정리 | `NpcManager_Duel.ClearDuelParticipantBuffs`가 `BuffHelper.RemoveAllDispellableBuffs`로 두 참가자의 `IsDispellable=true`인 `BuffInstance`와 해당 StatModifier만 제거한다. 패시브·영구 효과는 유지하며, Editor에서는 해제 가능한 잔존 버프를 즉시 검사한다 |
| 동행 NPC 귀환(D26) | `NpcManager_Companion.EndCompanionAfterDuel` — `FinishCompanionDungeonExit`에서 분리한 `ReturnCompanionHome`을 쓴다 |
| 활동 제외 | `System_NpcSim`(결투 중 NPC 활동 판정 보류, 파티원이 결투 중이면 파티 판정 보류), `NpcManager.IsEligibleHuntPartyMember`(결투 중 NPC 제외) |
| Deeds | `NpcDeedKind.DuelWon` / `DuelLost` / `DuelDrawn` (NPC 쪽만, 참가자에 플레이어 "모험가" 포함) |
| 상호작용 | `System_Input`과 `ServiceUIRouter`가 결투 중 E 입력·후보·프롬프트를 차단한다. `UINpcInspect`의 "결투 신청"은 수락 즉시 패널을 닫는다 |
| 디버그 | `NpcCombatDebugMenu` — 결투 신청, 결투 상태 로그, 남은 시간 1초로 빨리 감기, 플레이어 HP 0 |

**구현 세부 규칙** (설계에 없어 B4 구현 때 정함)

- 결투는 한 번에 1건만 진행한다.
- 입회인은 NPC 참가자 기준 10타일 안의 NPC다.
- 몬스터의 참가자 선택은 시야(FOV)를 무시하고 감지 범위만 본다.
- 같은 틱에 두 참가자가 모두 HP 0이 되면 먼저 처리된 쪽이 패자이고, 상대 HP도 1 이상으로 올린다. HP를 보정하기 전에 두 참가자의 해제 가능한 버프·디버프를 제거한다.
- 정상 결투 종료 후 저장 범위는 Player·World·NpcState이며, 던전 안이면 Dungeons를 추가한다. 결투 중 거부된 저장 요청은 나중에 합치거나 재실행하지 않는다. Map은 포함하지 않는다.
- 던전 보스 완료 트랜잭션(`CompleteAsync`)은 결투 중에는 실행하지 않고 완료 대기 상태를 유지한다. 이때 완료 대기만으로는 `GameplayPaused`가 되지 않아 결투가 계속 진행된다. 결투 정상 종료 저장이 `CompleteAsync`를 다시 호출하거나, 던전 체크포인트가 3초 주기로 재시도한다.
- 던전 안에서 D26 귀환 위치는 마을 반경 규칙으로만 정한다(던전 안에서는 월드 충돌 검사를 할 수 없다). 막힌 자리는 청크가 활성화될 때 `SpawnNpc`가 보정한다.
- 원정 중 화면 안 대기 NPC와의 결투는 §3.1 예외를 따른다.

- 토템·장판 등 대리 시전체(`CasterLinkComponent`)는 결투 규칙을 원 시전자 기준으로 판정한다. 플레이어의 토템도 결투 상대를 공격한다. 반대로 결투 중 NPC는 상대의 토템·소환물을 공격하지 않는다(Q10 유지, Q19). (2026-09-27 확정)

**알려진 한계**: 결투 남은 시간 HUD는 없다.

## 8. 전투 사망 연결 (요소 8)

- 동행 중 몬스터에게 죽으면 `MarkNpcDead` 경로로 **영구 사망**을 처리한다(`Fell` Deed, `DeceasedRelationMemory`). 결투에서는 사망하지 않는다(D22). 처단 경로가 C2에서 다시 도입되면 같은 경로를 쓴다.
- `System_EntityDestroy`의 NPC 분기는 지금 `UnregisterNpcByEntityId`만 호출한다. 전투로 인한 파괴와 단순 비실체화(청크 이탈 등)를 구분해서, **전투 사망일 때만** `MarkNpcDead`를 호출한다.
- `MarkNpcDead`의 동작은 바꾸지 않고 **호출만 추가**한다(A 갈래의 NPC 간 결투도 같은 함수를 쓴다).
- (보류) 처단 시 드랍 여부와 내용은 AMBITION §8.8의 규칙을 결과 처리 훅(§7.4)으로 받는다.

## 9. A 갈래(화면 밖 시뮬레이션)와의 접점

본 문서의 작업(B 갈래)은 AMBITION의 P1~P4(A 갈래)와 **독립적으로** 진행한다. 겹치는 곳은 아래뿐이다.

| 접점 | 규칙 |
|------|------|
| `NpcSaveData` | B는 결투(B4) 전까지 저장 필드를 추가하지 않는다. 추가할 때는 A 쪽 변경 뒤에 올린다 |
| `NpcActivityPausedTag` | 이 태그가 붙은 NPC는 전투 허용 대상에서 제외한다. 플레이어와의 결투만 예외로, 결투 동안 태그를 뗐다가 종료 후 활동이 남아 있으면 다시 붙인다(§3.1) |
| `System_NpcSim` | 던전 안에서 동행 중인 NPC는 활동 선택·판정에서 제외하고, 예약 중인 NPC는 Rest만 고른다(§4.5). **최소한의 제외 조건만 추가**하고 기존 판정 로직은 바꾸지 않는다 ✅ B2 |
| `NpcManager` 사냥 파티 모집 | 예약 NPC는 `IsEligibleHuntPartyMember`에서 제외한다(§4.5). 파티 판정 로직 자체는 바꾸지 않는다 ✅ B2 |
| `System_NpcSim` (B4) | 플레이어와 결투 중인 NPC는 활동 선택·판정에서 제외한다. 결투 도중 사냥을 시작하면 `NpcActivityPausedTag`가 붙어 인식이 꺼지기 때문이다. 파티원 중 결투 중인 NPC가 있으면 파티 판정을 결투가 끝날 때까지 미룬다 |
| 동행 상태 저장 | `NpcSaveData`가 아니라 World 파티션에 둔다(§4.5) |
| `NpcManager.MarkNpcDead` | 동작을 바꾸지 않고 호출만 추가한다(§8) |
| `EntityFactory.CreateNpc` | B1이 진영 컴포넌트를 추가한다. A는 이 함수를 거의 건드리지 않는다 |

두 갈래가 만나는 곳은 AMBITION §13의 **C 단계**(동행 제안·정산, 배신, 결투 사회 규칙)다.
