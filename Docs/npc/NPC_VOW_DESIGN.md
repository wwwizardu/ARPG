## 1. 문제와 목표

### 1.1 지금 상태 (2026-10-16 코드 기준)

NPC에게 일어나는 사건은 이미 많다. 그런데 사건이 **기록으로만 남고 다음 행동을 거의 바꾸지 않는다.**

다음 활동은 Idle이 될 때마다 휴식·사냥·거래·던전 원정 중에서 점수 가중 랜덤으로 새로 고른다. 이전 사건이 주는 입력은 골드 부족·가방 가득·회복 직후·유망한 소문 네 가지뿐이다. [src: Assets/Scripts/Npc/NpcActivityResolver.cs `NpcActivityChoiceContext`·`SelectNextActivity`]

| 사건 | 지금 남는 것 | 다음 행동에 주는 영향 |
|---|---|---|
| 동료·가족 사망 | 생존자의 사망 관계 기억, 대화의 사별 화제 [src: Assets/Scripts/Manager/NpcManager.cs `RecordDeceasedRelationMemories`] | 없음 |
| 원정 중상 | 중상 Deed, 마지막 부상 활동·던전(`LastWoundDungeonId`) [src: Assets/Scripts/Npc/NpcSaveData.cs] | 회복 직후 12시간 휴식 ×1.5 |
| 절도 발각 | 호감도 −40, 원한, 가족·친구 −10 (AMBITION D102) | 같은 파티에 안 듦, 소문을 안 나눔 |
| 파티 공동 활동 | 쌍별 공동 활동 통계, 호감도 | 파티 수락 확률 |
| NPC 던전 완료 | 던전 완료 Deed, 완료 소문 | 없음 |

공통 목표인 "강해지기"도 이야기를 끌고 가지 못한다. 추격과 역전 기조 때문에 NPC 전투력은 일부러 거의 평탄하게 만들었다(AMBITION §1.2·§10.1). 그래서 이 목표는 진행되지도 끝나지도 않는다. 성격이 활동 빈도에 주는 영향도 ±20% 이내라(D40) 눈에 잘 띄지 않는다.

→ 이야기는 "A가 일어나서 B를 하기로 했고, 그 결과 C가 벌어졌다"는 사슬이다. 지금은 이 사슬을 잇는 고리가 없다.

### 1.2 목표

1. **사슬**: 사건 → 다짐 → 활동 변화 → 결말 → 다른 NPC의 사건.
2. **성격이 반응을 고른다**: 같은 사건을 겪어도 성격에 따라 다짐을 세우거나 묻어 둔다.
3. **플레이어가 알아볼 수 있다**: 대화와 검사 창에 드러난다. 원하면 끼어들 수 있지만, 끼어들지 않아도 이야기는 굴러간다.
4. **드물고 또렷하게**: NPC 2,400명이 모두 이야기를 들고 다니면 잡음이 된다. 상한을 둔다.

### 1.3 범위

| In | Out |
|---|---|
| 다짐 데이터·생성·단계·결말·연쇄 | 새 활동 종류를 많이 더하기 |
| 활동 선택 배율과 대상(던전·파티) 지정 | 활동 판정 공식(성공률·부상·사망·완료 확률) 변경 |
| 다짐 화제, 검사 창 한 줄, 부탁 칸 연결 | LLM이 줄거리나 결말을 정하는 것 (LLM은 대사만) |
| 1단계: 설욕 / 이후: 복수·라이벌·재기·빚 | 플레이어를 대상으로 한 다짐(플레이어에게 복수 등, AMBITION P5 영역) |
| | 출산·인구 증가(마을 인구는 추상, 경계 문서 §2) |
| | 다짐을 통한 전투력 상승 장치 |

## 2. 핵심 개념

### 2.1 다짐이란

- NPC 한 명이 **최대 1개** 갖는 진행 중인 개인 목표다.
- 담는 것: 종류, 단계, 대상(던전·NPC), 계기(누구의 무슨 일), 시작 시각, 단계 시작 시각, 시도 횟수, 연쇄 깊이.
- 다짐이 하는 일은 세 가지뿐이다.
  1. **활동 점수에 필요 배율**을 곱한다(AMBITION §6.2와 같은 자리, 성향 ±20% 클램프 밖).
  2. **활동 대상**을 정한다(던전 원정 슬롯, 파티 모집 후보).
  3. **대화 화제와 검사 창 표시**를 만든다.
- 활동 판정은 건드리지 않는다. 그래서 전투력 평탄 기조, 사망률 목표(30일 0.5~1%, D48), 개인 상한(§10.1)이 그대로 유지된다.

### 2.2 흐름

```
씨앗 사건 ──▶ 반응 판정(성격·관계) ──▶ 다짐 생김
                  │ 반응 안 함 → 지금처럼 기억·대화로만 남음
                  ▼
            준비 단계 ──▶ 실행 단계 ──▶ 결말
           (사냥·구매↑)   (대상 던전·파티)   ├ 이룸   → 결말 Deed, 결말 화제
                                            ├ 꺾임   → 결말 Deed, (후속) 재기/떠남 씨앗
                                            ├ 사라짐 → 대상이 없어짐, 조용히 끝남
                                            └ 주인 사망 → 관계자에게 같은 씨앗 (연쇄)
```

### 2.3 다짐 종류 한눈에

| 종류 | 씨앗 | 결말 | 단계 |
|---|---|---|---|
| **설욕** | 던전 원정에서 중상을 입거나 동료·가족을 잃음 | 그 던전을 이겨 내거나 닫음 | **1단계(이 문서 §4~§8)** |
| 복수 | 절도·배신으로 생긴 원한 | 결투로 갚음 / 역으로 당함 | 2단계, P3와 묶음(§9.1) |
| 라이벌 | 명예 야망 두 명, 비슷한 실력, 같은 마을 | 서로 인정 / 앙금 | 3단계(§9.2) |
| 재기·떠남 | 중상, 꺾인 다짐 | 다시 일어섬 / 다른 마을로 떠남 | 3단계, 자발적 이주(NS4)와 묶음(§9.3) |
| 빚 | 치료비 부족 | 갚음 / 못 갚아 원한 | 후속(§9.4) |
| 우정 → 부부 | 공동 활동으로 호감이 높은 쌍 | 결혼 / 사별 → 설욕 | 미정(§12 Q1) |

## 4. 설욕 (1단계)

### 4.1 씨앗

| 씨앗 | 언제 | 다짐 주인 후보 | 대상 던전 |
|---|---|---|---|
| **사망형** | 솔로·파티 던전 원정에서 NPC가 죽음 | 죽은 NPC와 **같은 마을**에 사는 생존 관계자. 우선순위: 배우자 > 형제 > 부모·자식 > 친구 > 같은 파티의 생존자 > 호감도 최고(50 이상). 같은 순위면 EntityId가 작은 쪽 | 그 원정의 `DungeonId` |
| **중상형** | 던전 원정에서 중상 | 본인 | 그 원정의 `DungeonId`(= `LastWoundDungeonId`) |

- **같은 마을만**: NPC 던전 원정은 소속 마을 슬롯만 간다(D68·D75). 다른 마을에 사는 형제는 그 던전에 갈 수 없으므로 후보가 아니다.
- **후보는 한 명만**: 판정은 우선순위 순서로 한 명씩 한다. 첫 후보가 반응하지 않으면 다음 후보를 판정하고, 누군가 다짐을 세우면 멈춘다. 다짐을 세우지 않은 관계자도 다짐 주인의 파티 모집에서 수락이 쉬워진다(§5.2).
- **무효 조건**: 대상 던전이 이미 닫혔거나(세대가 바뀜), 후보에게 열린 다짐이 있거나, 마을 상한(D143)이 찼으면 씨앗을 버린다.
- **판정 시점**: 사망형은 원정 결과 처리에서 `MarkNpcDead`를 부르기 **전에** 후보를 고른다. `MarkNpcDead`가 관계를 지우기 때문이다(`RemoveAllRelationsInvolving`). 중상형은 `ApplyExpeditionWound`가 중상을 확정한 직후다. [src: Assets/Scripts/Common/System/System_NpcSim.cs `ResolveDelve`·`ResolvePartyDelve`, Assets/Scripts/Manager/NpcManager.cs `MarkNpcDead`]

### 4.2 반응 판정 — 성격이 고른다

```
반응 확률 = 기본값 × (1 + clamp(성격 항, ±0.5))
  사망형 기본값 0.60 — 성격 항 = 충성(+0.25) + 자존심(+0.15) + 용기(+0.10) − 인내(−0.20)   (각 수치 50을 0으로 둔 ±값)
  중상형 기본값 0.25 — 성격 항 = 자존심(+0.25) + 용기(+0.20) − 안전 야망(주 −0.30 / 보조 −0.15)
```

- 결정론 RNG(소유자 = 후보 EntityId, 시각 = 사건 시각, salt 200).
- 같은 사건이라도 인내가 높은 NPC는 묻어 두고, 충성·자존심이 높은 NPC는 다짐을 세운다. 성격 차이가 지금(활동 빈도 ±20%)보다 훨씬 눈에 띈다.
- 반응하지 않으면 아무 일도 없다. 지금처럼 사별 화제·부상 화제만 남는다.
- (3단계) 안전 야망 NPC가 중상에 반응하지 않으면 재기·떠남 씨앗으로 넘기는 경로를 붙인다(§9.3).

**빈도 추정**: 원정 부상은 30일에 약 25,900건이고 그중 약 10%가 중상이다(D92). 사망은 30일 실행에서 0.42~0.71%(약 2,400명 기준 10~17명)다(GOLD_BALANCE §11.2). 던전 원정의 몫은 아직 따로 집계하지 않았다. [추론] 던전 원정이 중상의 15%라면 30일에 약 390건, 반응 25%면 약 100건이다. 300개 마을로 나누면 마을당 0.3개 정도다. 착수 전에 진단으로 확인한다(§10).

### 4.3 단계

| 단계 | 시작 | 끝 | 효과 |
|---|---|---|---|
| **준비** | 다짐 생성. 부상 중이면 회복이 끝난 시각부터 센다 | 48게임시간 경과 | 사냥 ×1.25, 거래 ×1.5(할 일이 있을 때만), 휴식 ×0.8, 던전 원정 ×0.5 |
| **실행** | 준비 종료 | 결말 | 던전 원정 ×4(대상 = 다짐 던전), 휴식 ×0.8, 파티 모집 시도 항상, 다른 리더의 파티 모집 후보에서 빠짐 |

- 단계 전이는 Idle 전환(활동 선택) 때 시각을 비교해 정한다. 매 틱 검사하지 않는다.
- 준비 단계의 거래 배율은 구매 기회를 늘리지만, 구매 쿨다운 48h(§7.2)와 개인 상한이 있어 전투력은 크게 오르지 않는다. 진단의 "전투력 +10% 이내" 기준으로 확인한다.
- 실행 단계 던전 원정 비중 추정: 기본 점수 합 약 2.35에 던전 원정 0.10 × 4를 넣으면 한 번 고를 때 약 15%다. 활동 평균 길이를 6시간으로 보면 1~2게임일 안에 첫 시도가 나온다. [추론]

### 4.4 결말

| 결말 | 조건 | 남는 것 |
|---|---|---|
| **이룸 — 극복** (중상형) | 실행 단계의 다짐 원정 결과가 성공 | `VowFulfilled` Deed. "그 던전에 다시 가서 이겨 냈다" |
| **이룸 — 직접** (사망형) | 다짐 주인(또는 그 파티)이 대상 던전을 완료 | `VowFulfilled` Deed. NPC 완료는 성공 시 3~8%라 드물다(D55) |
| **이룸 — 함께** (사망형) | 다짐 주인을 동행으로 데려간 플레이어 측이 대상 던전 보스를 처치 | `VowFulfilled` Deed. 플레이어 행적 반응은 부탁한 NPC(×3) 기준 |
| **이룸 — 대신** (사망형) | 플레이어 측이 동행 없이 대상 던전 보스를 처치 | `VowFulfilled` Deed. 부탁했으면 보고·보답 경로(§6.3), 안 했으면 "소문 전 해결"처럼 직접 말하기 대화(보답 없음) |
| **이룸 — 남이** (사망형) | 다른 NPC 파티가 대상 던전을 완료 | `VowFulfilled` Deed. 성격에 따라 안도 또는 허탈 문구 |
| **꺾임** | 생성 뒤 14게임일, 또는 시도 3회가 모두 실패·부상 | `VowAbandoned` Deed. 체념 문구 |
| **사라짐** | 다짐 주인이 이주함, 대상 던전이 위 경우 밖의 이유로 없어짐 | Deed 없음. 다짐만 지운다 |
| **주인 사망** | 다짐 주인이 죽음 | 다짐을 지운다. 다짐 원정 중 사망이면 연쇄(§4.5) |

- 시도 횟수는 다짐 던전으로 간 원정 1회마다 센다. 사망형에서 원정이 성공해도 던전이 닫히지 않으면 이룸이 아니고 시도만 쌓인다.
- 사망형은 NPC 혼자서는 이루기 어렵다. 플레이어가 끼어들 자리가 여기서 생긴다. 꺾임이 너무 많으면 "다짐 원정 성공 2회 = 이룸"을 더하는 안을 검토한다(§12 Q3).
- 던전이 닫혔는지는 저장한 `DungeonId`가 소속 마을 현재 슬롯에 있는지로 판정한다(D68과 같은 방식). 누가 닫았는지는 NPC 완료 경로(`OnNpcDungeonCompleted`)와 플레이어 완료 경로(`StageDungeonCompletion`)에서 알린다.

### 4.5 연쇄

- 다짐 주인이 **다짐 원정에서** 죽으면, 그 죽음을 사망형 씨앗으로 다시 판정한다(대상 던전 같음, 연쇄 깊이 +1).
- 첫 다짐은 깊이 0이고 깊이 2까지만 이어진다. 한 던전에서 비극이 최대 세 번 이어진다.
- 이룸·꺾임은 1단계에서 다른 NPC의 씨앗이 되지 않는다. 3단계에서 꺾임 → 재기·떠남을 붙인다.

### 4.6 예시

| 때 | 일 | 결과 |
|---|---|---|
| 1일 | 철수·영희·민수 파티가 동쪽 던전 원정, 철수 사망 | 철수의 형제 영희(같은 마을)가 반응 판정 → 충성이 높아 **설욕 다짐** |
| 1~3일 | 영희 부상 회복 | 다짐은 있지만 준비 단계 시계는 회복 뒤부터 |
| 3~5일 | 준비 | 사냥·상점 방문이 잦아짐. 영희에게 말을 걸면 "철수를 그렇게 보낼 수는 없소" |
| 5일 | 실행 | 영희가 동쪽 던전 원정을 고름, 민수(같은 파티 생존자)가 쉽게 합류 → 원정 성공, 던전은 안 닫힘(시도 1) |
| 6일 | 플레이어 방문, 영희 호감 35 | 영희가 부탁: "동쪽 던전을 끝내는 걸 도와주겠소?" → 부탁 칸 |
| 7일 | 플레이어가 영희를 동행으로 데려가 보스 처치 | **이룸 — 함께**. 영희 보고 반응·의뢰 보답, `PlayerDeed` 소문이 마을에 퍼짐 |
| 다른 결말 | 7일에 영희가 다짐 원정에서 죽음 | 영희의 배우자에게 같은 던전 사망 씨앗(깊이 1) |

## 5. 활동 선택과의 연결

### 5.1 필요 배율

`NpcActivityChoiceContext`에 다짐 단계를 더하고 `GetActivityScore`가 §4.3 표의 배율을 곱한다. 성향 ±20% 클램프 밖에서 곱한다(D40의 "필요는 성향과 별개" 규칙과 같다). 계산은 정적 순수 규칙(예: `NpcVowRules`)에 두고 게임과 진단이 같은 메서드를 부른다.

### 5.2 대상과 파티

- **던전 대상**: `TryPrepareDelveTarget`은 지금 "유망한 소문 → 균등 선택" 순서다. 그 앞에 "다짐 던전"을 둔다. 다짐 던전이 소속 마을 슬롯에 없으면 다짐이 이미 결말 조건을 만난 것이다. [src: Assets/Scripts/Manager/NpcManager_Delve.cs `TryPrepareDelveTarget`]
- **파티 모집**: 실행 단계 다짐 주인이 던전 원정을 고르면 모집 시도 확률(D86)을 건너뛰고 항상 모집한다. 수락 확률에 "계기가 된 사망자의 관계자이거나 같은 파티 생존자" 보너스 +0.20을 더한다(상한 0.90 유지). [src: Assets/Scripts/Npc/NpcActivityResolver.cs 파티 모집 상수]
- **다른 파티**: 실행 단계 다짐 주인은 다른 리더의 모집 후보에서 빠진다. 준비 단계는 그대로다.

### 5.3 세계 지표 영향

진행 중 다짐이 마을당 최대 2개라서 세계 활동 비중 변화는 작을 것이다. [추론] 그래도 구현 뒤 진단으로 기존 기준을 다시 확인한다 — 던전 원정 비중 4~6%, 사냥 38±5%(D56 개정), 30일 사망 0.5~1%, 전투력 +10% 이내, 개인 상한 초과 0.

## 6. 플레이어가 만나는 길

### 6.1 대화

- 새 화제 3종(가칭): 진행 중 다짐 상태(준비·실행 문구), 다짐 부탁, 결말 이야기.
- 진행 중 상태와 부탁은 **고정(Pinned)** 화제다. 지금 부탁·소망 화제처럼 레퍼토리에 반드시 들되 다른 화제와 번갈아 나온다. 개인 사연 2자리 경쟁(D109 ①)에 끼지 않게 하기 위해서다. [src: Assets/Scripts/Manager/NpcManager_NarrativeDialogue.cs, Assets/Scripts/Manager/NpcManager_NarrativeWish.cs]
- 결말 이야기는 결말 뒤 14게임일 동안 나오는 일반 화제다(행적 반응의 14일과 맞춤).
- 시스템이 사실(계기 인물·던전·단계·결말)을 정하고 LLM은 말투만 입힌다. LLM이 없으면 작성 문구 그대로 나온다.

### 6.2 검사 창

- 성향 탭의 "야망" 줄 아래에 "다짐: 철수의 원수를 갚는다 — 준비 중" 한 줄을 더한다. [src: Assets/Scripts/UI/UINpcInspect.cs 야망 표시]
- 끝난 다짐은 사건 이력에서 결말 Deed로 보인다.

### 6.3 부탁 — 지금 구조를 그대로 쓴다

- 조건: 실행 단계, 플레이어 호감 30 이상(소망과 같은 문턱), 부탁 칸이 빔.
- 부탁 대사가 실제로 표시된 뒤 narrative 원장에 다짐 부탁 인스턴스를 만들고 부탁 칸(`NpcNarrativeRequest`)에 넣는다. 소망처럼 미리 만들지 않는다.
- 해결 = 플레이어 측(동행 포함)이 다짐 던전 보스를 처치. 보고·반응·의뢰 보답·`PlayerDeed` 소문 전파는 NARRATIVE_CONTENT §4.1·§4.5와 같다.
- 같은 던전에 소문 부탁과 다짐 부탁이 함께 걸려 있으면, 의뢰 보답은 행적당 1회·가장 관련 깊은 NPC 1명 규칙(§4.5)을 따른다.
- 다짐이 꺾이거나 사라지면 부탁도 끝난다. 다음 대화에서 알리고 보답·전파는 없다(소문 부탁이 미해결로 끝날 때와 같음).
- 플레이어가 끼어들지 않아도 다짐은 §4.4대로 끝난다.

### 6.4 동행

다짐 주인에게 동행을 요청하면 지금 동행 규칙(던전 전용, D97)대로 함께 간다. 그 던전에서 보스를 처치하면 "이룸 — 함께"다. 동행 수락 조건은 지금 항상 수락이며, 다짐과 묶어 바꿀지는 §12 Q2와 함께 정한다. [src: Assets/Scripts/Manager/NpcManager_Companion.cs `RequestCompanion`]

## 7. 저장

### 7.1 NPC 쪽

```csharp
// 제안 예시. 아직 구현되지 않았다.
public enum NpcVowKind { None = 0, Vengeance = 1 }           // 새 종류는 끝에만 추가
public enum NpcVowStage { None = 0, Preparing = 1, Attempting = 2 }

[Serializable]
public sealed class NpcVow

    public NpcVowKind Kind;
    public NpcVowStage Stage;
    public NpcVowSeed Seed;
    public string TargetDungeonId = string.Empty;   // DungeonLayout.Id(시드, 마을, 슬롯, 세대)
    public int SubjectNpcId = -1;                   // 사망형: 죽은 NPC. 중상형: -1
    public string SubjectName = string.Empty;       // 사망자 이름 스냅샷 (사망 뒤에도 표시)
    public float CreatedGameTime;
    public float StageStartedGameTime;              // 준비: 회복 종료 시각부터
    public int Attempts;
    public int ChainDepth;
}
```

- `NpcSaveData.Vow`는 다짐이 없으면 `null`이고 저장하지 않는다. 다짐이 없는 NPC의 저장 크기는 늘지 않는다.
- 저장 그룹은 새 비트(`NpcSaveGroup.Vow`)를 추천한다. 다짐 변화가 Deeds·Stories 저장을 같이 끌고 가지 않게 하기 위해서다.
- 결말 Deed: `NpcDeedKind` 끝에 `VowFulfilled = 16`, `VowAbandoned = 17`을 더한다. 참가자에 사망자를 넣고, 대상 던전은 표시 문구용으로만 쓴다.
- 로드 보정: 종류·단계가 None이면 지우고, 시도·깊이가 범위를 벗어나면 자른다. 대상 던전이 없어졌으면 다음 활동 선택 때 결말 판정이 처리한다.
- 세이브 버전은 올리지 않는다. 새 필드는 기본값 생략, 새 enum 값은 끝에 추가한다(AMBITION §12 저장 규칙).

### 7.2 narrative 원장

다짐 부탁 인스턴스는 기존 `NarrativeSaveRoot`에 저장한다. `NarrativeContentKind` 끝에 `Vow = 5`를 더하는 안을 추천한다. 대상은 다짐 던전이고 부탁한 NPC는 다짐 주인이다. 부탁 칸·보고 완료·보답 기록은 지금 필드를 그대로 쓴다. [src: Assets/Scripts/Data/NarrativeSaveData.cs, Assets/Scripts/Npc/NpcSaveData.cs `NpcNarrativeRequest`]

## 8. 결정론 · LOD · 코드 배치

- **판정 시점**: 씨앗 반응은 사건 시점 1회, 단계 전이·결말은 Idle 전환 때 시각 비교로 한다. 매 틱 검사하지 않는다. 화면 안과 밖이 같은 규칙이다.
- **RNG salt**: 200 = 설욕 씨앗 반응. 201~209 = 다짐 예비. 구현 때 NPC_SIMULATION §11.1 salt 정본에 등록한다. (190번대는 이주가 쓰고, 200번 이후가 비어 있다.)
- **코드 배치**: 새 System을 만들지 않는다. 상태는 `NpcSaveData.Vow`, 도메인 처리는 `NpcManager_Vow.cs`(partial), 배율·확률 계산은 정적 순수 규칙에 둔다. 게임(`System_NpcSim`)과 진단이 같은 공용 메서드를 부른다(진단 복제 함정, AMBITION P4 기록).
- **던전 안**: 던전 안에서는 월드 시뮬이 멈추므로 다짐 시계도 멈춘다. 기한은 게임 시각 기준이라 따로 보정할 필요가 없다.

## 9. 다른 종류 (2단계 이후 개요)

### 9.1 복수 — 2단계, P3와 묶음

- 씨앗: 절도·배신 발각으로 생긴 원한(방향 있음, D102).
- 진행: 준비 → 같은 마을에서 둘 다 대기 중일 때 NPC 간 결투(추상) 신청.
- 결말: 이기면 원한이 풀리고 "갚아 줬다" Deed, 지면 공격받은 부상 Deed(D96, 지금 호출부 없음) + 역복수 씨앗.
- 의존: NPC 간 결투 판정(AMBITION Q19, COMBAT Q16~Q18). P3를 다시 열 때 "배신 규칙"이 아니라 "배신이 만드는 이야기"로 범위를 잡을 수 있다.
- 주의: 절도 시도는 30일 86~90건이고 장기 실행에서 줄어 480일째엔 거의 0건이다(GOLD_BALANCE §11.2). 절도 원한만으로는 꾸준한 씨앗이 못 되므로 P3 배신 씨앗과 함께 다룬다.

### 9.2 라이벌 — 3단계

- 씨앗: 같은 마을의 명예 야망 두 명, 전투력 차이 10% 이내, 서로 호감 0 이상. 관계 유형 `Rival`이 이미 있다.
- 진행: "라이벌에게 뒤처짐" 필요(AMBITION §6.2, 설계만 있음)로 원정 빈도가 오른다. 누가 먼저 던전을 완료하거나 상점 장비를 바꾸는지 경쟁한다.
- 결말: 서로 인정해 친구가 되거나 앙금이 남는다. 결투로 끝내는 안은 §9.1 결투가 생긴 뒤에 붙인다.

### 9.3 재기 · 떠남 — 3단계, 자발적 이주(NS4)와 묶음

- 씨앗: 중상에 설욕으로 반응하지 않은 안전 야망 NPC, 꺾인 다짐.
- 진행: 휴식이 길어짐 → 일정 기간 뒤 다시 원정(재기) 또는 다른 마을로 이주(떠남).
- 경계: 은퇴해서 마을 일꾼이 되는 결말은 쓰지 않는다(VILLAGE_NPC_BOUNDARY). 떠남은 AMBITION D141의 자발적 이주로 처리한다.

### 9.4 빚 — 후속

- 씨앗: 부상 치료비가 모자람(지금은 예비금 규칙만 있음).
- 진행: 친구에게 빌림 → 다음 판매 대금으로 갚음.
- 결말: 갚으면 호감 상승, 기한 안에 못 갚으면 원한. NPC 사이 골드 이동이므로 닫힌 경제 검산에 포함해야 한다.

| 2단계 | 복수 + P3 재개(NPC 간 결투, 배신 씨앗) | P3 0단계 질문(AMBITION §14 Q14~Q20)부터 |

## 11. 위험과 대응

| 위험 | 대응 |
|---|---|
| 다짐 원정이 늘어 사망률이 목표를 넘음 | 상한 2개·시도 3회·기한 14일. 진단으로 확인하고 넘으면 실행 배율을 낮춘다 |
| 사망형이 거의 다 꺾임으로 끝나 우울함 | 플레이어 부탁이 주 해결 경로다. 꺾임 비율을 보고 Q3 안을 검토한다 |
| 대화가 다짐 이야기로만 채워짐 | 고정 화제는 다른 화제와 번갈아 나오는 기존 순환을 따른다 |
| 연쇄가 끝없이 이어짐 | 깊이 2 상한 |
| 씨앗 판정 시점에 관계가 이미 지워짐 | 사망형 후보를 `MarkNpcDead` 전에 고른다(§4.1) |

| Q8 | 사냥에서 생긴 사망·중상도 씨앗으로 쓰는가 | 1단계는 아님(대상 던전이 없음). 3단계 재기·떠남의 씨앗 후보 |
