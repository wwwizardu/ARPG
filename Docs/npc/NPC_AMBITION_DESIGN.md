## 1. 문제와 목표

### 1.1 현재 상태 (2026-09-24 코드 기준)

- 활동 선택은 `NpcActivityResolver.SelectNextActivity`가 담당한다. **Rest와 Hunt 둘 중 하나**를 인내·용기·호기심 가중치로 랜덤 선택할 뿐이다. [src: Assets/Scripts/Npc/NpcActivityResolver.cs]
- Hunt 전투력(`GetPartyHuntPower`)은 **용기와 SkillLevel만** 본다. **장비가 결과에 영향을 주지 않는다.** 좋은 장비를 구해도 강해지지 않는 구조다. [src: Assets/Scripts/Npc/NpcActivityResolver.cs]
- Hunt 보상은 마을 Food뿐이다. NPC에게는 **골드도 개인 전리품도 없다.** [src: Assets/Scripts/Common/System/System_NpcSim.cs]
- 성격 8수치(`NpcStatComponent`: 친화·정직·탐욕·충성·용기·호기심·자존심·인내)가 있다. 하지만 대화 토픽 가중치와 관계 backfill에만 쓰이고, **행동 동기로는 쓰이지 않는다.** [src: Assets/Scripts/Common/Component/NpcStatComponent.cs, Assets/Scripts/Npc/Narrative/DialogueTopicSelector.cs]

- NPC는 전투용 컴포넌트(Stat·State·Skill·AI)를 갖고 있지만 **평소에는 싸우지 않는다.** 모든 NPC가 중립(`Neutral`) 진영이라 적을 인식하지 않고, 화면 안에서 사냥할 때도 AI를 멈춘 채 경로만 이동한다. 예외는 플레이어가 대화로 요청한 **임시 동행(던전 전용)** 과 플레이어가 신청한 **결투**뿐이다. 동행 중에는 NPC가 플레이어 편으로 던전 몬스터와 싸우고(NPC_COMBAT B2·B3), 결투 중에는 플레이어와 싸운다(B4, 아무도 죽지 않음). NPC가 바닥 드랍을 줍는 동작도 있지만 지금은 디버그 명령으로만 호출한다(B5). 모두 2026-09-27 기준. 상세 내용은 [NPC_COMBAT_DESIGN §1](NPC_COMBAT_DESIGN.md). [src: Assets/Scripts/Factory/EntityFactory.cs, Assets/Scripts/Common/System/System_AI_Perception.cs, Assets/Scripts/Manager/NpcManager_Companion.cs]

→ NPC에게 **강해질 이유도, 강해질 방법도, 강해졌다는 결과도 없다.**

> **P1 이후 (2026-09-28)**: 위 상태는 P1로 바뀌었다. 활동은 성향·야망·필요 기반 효용 선택(Rest/Hunt/Trade)이고, Hunt 전투력은 장비를 반영하며(용기 제외), 성공하면 개인 전리품을 얻는다. 전리품은 상점에 팔려 NPC 골드가 되고, 골드는 장비 구매와 치료에 쓰여 마을 Gold와 순환한다. 상세는 §5.1, §6, §7.1, §7.2, §9.
>
> **이후 구현 (2026-09-29~10-03)**: P2로 DungeonDelve 추상 원정·NPC 던전 완료와 사실만 담은 소문 교환·확인 원정이 붙었다(§5.2, §7.1, §7.4). 원정 파티는 Rest 중 NPC까지 모집 후보로 삼는 자동 구성으로 바뀌었고(D85~D90, §7.5), 원정 부상은 가벼운 부상과 중상으로 나뉘었다(D91~D96, §5.1·§12). P4로 Rest 종료 때 NPC 간 절도·발각·늦은 발각이 생겼다(D98~D115, §7.6). 2026-10-03부터 NPC 장비는 상점 기본 아이템이고 구매로만 바뀐다(D116~D123). 단계별 상태는 §13.

### 1.2 목표

0. **추격과 역전의 재미 (최상위 기조)**: NPC는 시작 시점에 플레이어보다 강하지만 **거의 강해지지 않는다**(운이 좋을 때만 가끔 오른다). 플레이어가 성장하며 NPC를 쫓아가 따라잡는 것이 기본 재미다. 아래 목표는 모두 이 기조 안에서만 성립한다(§10.1).
1. **목적 있는 행동**: 모든 NPC는 더 강해지기 위해 움직인다. 같은 목표라도 성격에 따라 방법이 달라야 한다.
2. **닫힌 루프**: 원정 → 전리품·골드 → 판매·구매·제작 → 전투력 상승 → 더 어려운 원정.
3. **사회적 드라마**: 소문 확인, 협력, 배신, (NPC 간) 절도가 성격과 관계의 결과로 일어난다.
4. **플레이어가 알아볼 수 있을 것**: 화면 밖에서 일어난 일도 상점 재고, 소문, 대화, Deeds로 드러난다.

### 1.3 범위

| In | Out |
|----|-----|
| 야망 도출, 활동 효용 선택, Gold·전투력·소문·평판 자원 | 상주 직업 NPC, 마을 작업자(경계 문서 §8 유지) |
| 상점 거래(재고 변경), Forge 강화, 파티 분배, NPC 간 배신·절도 | **플레이어 대상 절도** [확정: 사용자 답변 2026-09-24] |
| 플레이어와의 임시 동행 + 양방향 배신 + 결투 | 영구 동료 시스템(→ [companionSystem.md](companionSystem.md)) |
| 마을 Gold 약한 유입 | 마을 인구·Tier·건설 후보에 직접 입력 |

## 4. 성격 → 야망

### 4.1 야망 원형

모든 NPC의 공통 목표는 **전투력 상승**이다. 야망은 *왜* 강해지려는지를 정하고, 그 이유가 활동 효용의 가중치가 된다.

| 야망 | 주 성격 | 선호 수단 | 기피 |
|------|---------|----------|------|
| **탐험 (Explorer)** | 호기심↑ 용기↑ | 던전 원정, 소문 확인 | 오래 쉬기 |
| **명예 (Glory)** | 자존심↑ 용기↑ | 강한 목표 사냥, 파티 리더, 라이벌 추월 | 저위험 활동 |
| **부 (Wealth)** | 탐욕↑ 인내↑ | 전리품 되팔기, 강화, 저가 매수 | 손해 보는 분배 |
| **동료 (Comrade)** | 충성↑ 친화↑ | 고정 파티, 공정한 분배, 구조 원정 | 혼자 하는 원정 |
| **기회 (Opportunist)** | 탐욕↑ 정직↓ | 분배 속이기, 거짓 소문, 절도 | 공정한 분배 |
| **안전 (Cautious)** | 용기↓ 인내↑ | 저위험 사냥, 정보 수집, 장비 보강 | 던전, 강한 목표 |

### 4.2 도출 규칙 ✅ P1c

- 원형마다 §4.1 표의 주 성격 두 수치를 더한 선형 점수를 매긴다. 예: `Opportunist = Greed + (100 − Honesty)`, `Cautious = (100 − Courage) + Patience`. [src: Assets/Scripts/Npc/NpcAmbition.cs]
- **최고점 = 주 야망, 차점 = 보조 야망**으로 둔다(동점이면 enum 순서). 보조 야망 항은 주 야망 항의 절반으로 반영하고, 활동 빈도에 대한 영향은 성격 항과 합쳐 ±20% 이내로 제한한다(D40, §6.3).
- NPC 검사 UI(`UINpcInspect`) 성향 탭에 "야망: 명예 (보조: 탐험)"처럼 표시한다.
- 성격 수치에서 결정론적으로 계산하므로 **저장하지 않는다.** 성격이 바뀌면 야망도 따라 바뀐다.
- 같은 탐욕이라도 정직하면 **부**, 정직하지 않으면 **기회**가 된다. 수치의 *조합*이 행동 차이를 만든다는 것이 핵심이다.

### 5.1 전투력 — 장비 반영 ✅ P1a

- `NpcPower = 장비 점수 + 스킬 점수`. 장비 점수는 장착 장비의 스탯을 요약한 값이다(공격·방어·생명력의 가중 합) [D32].
  - `EquipmentData`에는 `ComputedStats`가 없다(`Quality`, `Mods`, `WeaponLocalEnhancements`만 있음). 그래서 `NpcPowerEvaluator`가 화면 밖 NPC의 `NpcSaveData.InventoryEquip`에서 모드를 합산해 점수를 낸다(ECS 없이 동작). 모드 해석은 실체화 때 쓰는 `EquipHelper.ApplyAllEquipmentModifiers`와 같다. 무기 Base는 메인 무기의 `WeaponStats`로만 계산하고, 조건부 모드(OnCalculate/OnEvent)는 점수에서 뺀다. [src: Assets/Scripts/Npc/NpcPowerEvaluator.cs]
  - 가중치: 공격 1.0 / 방어 0.12 / 생명력 0.10(평범한 NPC에서 비중 50/25/25). 스킬 점수는 SkillLevel당 기준 전투력 × 0.05(2026-10-03부터 기준 전투력에 묶음 — 10.75 기준 0.5375, 이전 26 기준 1.3).
  - 복제돼 있던 전투력 식 3곳은 `NpcActivityResolver.GetHuntCapability` 하나로 합쳤다. 솔로·파티 판정과 Food 보상이 모두 이 값을 쓴다.
- **용기는 전투력에서 뺐다** [D31]. 용기는 활동 빈도의 작은 성향 배율(D40)에만 쓴다.
- **재정규화** [D31]: capability = clamp01(0.475 + (NpcPower / `HuntReferencePower` − 1) × 0.5). 기준 전투력은 평범한 NPC 집단의 평균이다 — 처음 26, **2026-10-03 기본 장비 적용(D118·D121) 뒤 10.75**(세이브 생존 2,387명 평균 25.96 → 10.75). 개인 상한(+20%)까지 채우면 capability가 +0.10 오른다. 평균 솔로 성공률 61.8~61.9%, Food/성공 2.22~2.24로 교체 전후가 같고, Food 문턱(0.3925/0.56)은 그대로다. 진단: `ARPG/Npc/Diagnostics/Hunt Power Normalization`.
- **사망 확률** [D48]: 30게임일 사망 0.5~1%가 되도록 기존 곡선의 약 0.375%로 낮췄다. 사망과 부상을 합친 피해 확률은 그대로라 줄인 만큼 부상이 늘고, 성공·실패·Food는 바뀌지 않는다.
- 계산은 장비 변경 시점에만 다시 하고 런타임에 캐시한다(`NpcManager` 소유). 저장하지 않는다.
- ⏸ **보류**: 무기 종류 개념이 없어 근접형 NPC가 이름이 "지팡이"인 무기를 장착할 수 있고, 주문형 NPC의 무기 점수가 과대평가될 수 있다(실제 전투에서는 Attack 태그 스킬만 무기 피해를 쓴다). 무기 체제를 정비할 때 함께 다룬다.

### 5.2 소문 데이터 ✅ P2b

종류는 P2의 **DungeonInfo·ItemOwner**(D50)와 P4의 **ItemSold·Betrayal**(D104·D105)이다. 거짓 소문은 없다(D51). 소문에는 실제로 일어난 사실만 담고, 계산할 수 있는 값은 저장하지 않는다(D70). [src: Assets/Scripts/Npc/NpcRumor.cs]

```csharp
public enum NpcRumorKind { None, DungeonInfo, ItemOwner, ItemSold, Betrayal }   // 새 종류는 끝에만 추가
public enum NpcBetrayalKind { None, TheftCaughtInAct, TheftDiscovered }       // P3 배신 유형은 끝에 추가

[Serializable]
public class NpcRumor
{
    public NpcRumorKind Kind;
    public bool Cleared;           // DungeonInfo: NPC 완료 소문(새 세대 던전을 가리킴)
    public int VillageId;          // DungeonInfo: 던전 소속 마을
    public int SlotIndex;          // DungeonInfo: 슬롯 (DungeonId = DungeonLayout.Id(시드, 마을, 슬롯, 세대)로 계산)
    public int Generation;         // DungeonInfo: 세대
    public int SubjectNpcId;       // DungeonInfo: 원정 당사자(파티면 리더) / ItemOwner: 소유자 / ItemSold: 판매자 / Betrayal: 가해자
    public int EquipSlot;          // ItemOwner: 장비 슬롯
    public int ItemInstanceId;     // ItemOwner·ItemSold: 검증 키 (ItemOwner 이름은 유효할 때 소유자 장비에서 읽음)
    public int Value;              // 실제로 얻은 가치 (BasePrice × 수량)
    public float EventGameTime;    // 사건 시각 (전달돼도 유지)
    public int SourceNpcId;        // 누구에게 들었나 (-1 = 직접 겪음)
    public int Hops;               // 몇 번 건너왔나 (0 = 직접)
    public bool Checked;           // 그 던전에 다녀옴 → 유망에서 제외
    // P4 (기본값이면 저장하지 않음 — 기존 소문의 JSON 크기는 그대로)
    public int VictimNpcId = -1;   // Betrayal: 피해자
    public NpcBetrayalKind BetrayalKind; // Betrayal: 세부 종류
    public int ItemId = -1;        // ItemSold·Betrayal: 표시용 아이템 테이블 Id (물건이 이미 주인을 떠났을 수 있음)
}
```

- **생성**(D71): Delve 성공 참가자(DungeonInfo), NPC 던전 완료(새 세대를 가리키는 완료 소문), 업그레이드 장착 소유자(ItemOwner), 훔친 물건을 판 판매자(ItemSold, D104), 절도가 발각된 순간의 피해자(Betrayal, D105).
- **유효 조건**: DungeonInfo = 슬롯 세대 일치, ItemOwner = 소유자가 그 슬롯에 같은 인스턴스를 장착 중, ItemSold = 판매자 생존, Betrayal = 가해자·피해자 생존. 같은 대상: ItemSold = (판매자, 인스턴스), Betrayal = (가해자, 피해자, 사건 시각).
- **사실 유지**(D72): 쓰거나 보여 주기 직전에 항상 검증한다. NPC 쪽 사건(완료·사망·장비 교체) 때 무효 소문을 지우고, Rest 종료 때 자기 목록을 정리한다.
- NPC마다 **최대 8개**, 대상마다 1개(D73). 가득 차면 무효 → 유망하지 않은 것 중 가장 오래된 것 → 가치 낮은 것 순으로 버린다.
- 대화에서는 기존 연대기 토픽을 대체하지 않고 **새 소문 토픽**의 데이터 소스가 된다(D60, P2c).

## 6. 목표 선택 (Utility)

### 6.1 평가 시점

- NPC가 **Idle로 전환될 때만** 평가한다(현행 `SelectNextActivity` 자리). 매 틱 평가하지 않는다.
- 결정론 RNG(`entityId, startGameTime, worldSeed`) 계약을 유지한다.

### 6.2 필요 (Needs)

| 필요 | 조건 | 올라가는 활동 | 상태 |
|------|------|-------------|------|
| 장비 부족 | 지역 기준 전투력 대비 낮음 | 구매, 강화, 저위험 Hunt | ⏳ 후속(기준 데이터 필요) |
| 골드 부족 | Gold < 치료비 예비금(10G) [D36] | Hunt ×1.25, Trade ×1.5 | ✅ P1c |
| 가방 가득 | 인벤토리 여유 ≤ 1 | Trade ×2.0 | ✅ P1c |
| 부상 회복 직후 | Wounded 종료 후 12시간 | Rest ×1.5 | ✅ P1c |
| 라이벌에게 뒤처짐 | Rival의 전투력·평판이 더 높음 | 강한 목표, 던전 | ⏳ P3 |
| 유망한 소문 보유 | 들은 Delve 성공 소문, 가치 ≥ 20, 72h 이내, 미확인, 유효 (D76) | Delve ×1.5, 그 던전으로 확인 원정 | ✅ P2b |

### 6.3 점수와 선택

```
Score(activity) = 기본값(활동별 상수)
                × 필요 배율(§6.2, 성향과 별개로 곱함)
                × 성향·야망 배율(1 + clamp(성격 항 + 주 야망 항 + 보조 야망 항 × 0.5, ±0.20))   [D40]
                × Opportunity(0이면 후보 제외 — 예: Trade는 할 일이 있을 때만)
                × Risk 적합도(용기 vs 목표 위험)   ← P2 이후 목표가 생기면
```

- **성향·야망이 활동 빈도에 주는 영향은 ±20% 이내**다 [D40]. 겁 많은 NPC도 꾸준히 사냥을 나가야 한다(용기 하위 10%의 Hunt 비중 약 37%). 야망 가중을 "주 1.0 / 보조 0.5로 곱하는" 원안은 성향 차이를 너무 키워 폐기했다.
- P1 상수(`NpcActivityResolver`): 기본값 Rest 1.0 / Hunt 0.85 / Trade 0.5. 성격 항은 Rest 인내 ±0.08, Hunt 용기 ±0.10·호기심 ±0.03, Trade 탐욕 ±0.08. 야망 항은 명예·탐험 Hunt +0.10·Rest −0.05, 부 Trade +0.12, 동료 Hunt +0.05, 기회 Trade +0.08, 안전 Rest +0.10·Hunt −0.05.
- **세계 평균 Hunt 선택 비중은 약 43%**를 기본값 상수로 맞춘다(진단 결과 42.7%). 개발 중 튜닝 목표이며, 실행 중 자동 보정은 두지 않는다 [D40].
- P2a 상수: Rest 기본값 **0.9**로 인하, DungeonDelve 기본값 0.11 → P2b에서 **0.10**(D76)(호기심 ±0.10·용기 ±0.05, 탐험 +0.15·명예 +0.08·안전 −0.10). 소속 마을에 던전 슬롯이 있을 때만 후보다. 세계 평균 Delve 비중 약 5%(진단 5.2%), Hunt 42.3% [D56, D64].
- **최고점을 그대로 고르지 않는다.** **후보 전체 중 점수 가중 랜덤**으로 고른다 [D64]. 같은 성향의 NPC도 행동이 다양하게 나오도록 하기 위해서다. 원안의 "상위 3개"는 활동이 4개가 되자 점수가 가장 낮은 Delve를 거의 항상 잘라 폐기했다.
- GOAP 같은 계획형 AI는 2,400명 규모에서 비용이 커서 채택하지 않는다.

| 활동 | 장소 | 판정 | 비고 | 상태 |
|------|------|------|------|------|

## 7. 활동 상세

### 7.1 사냥 · 던전 원정

- **Hunt 보상 확장** ✅ P1a: 기존 마을 Food에 더해, 성공하면 **개인 전리품을 1회 롤**한다. **골드는 주지 않는다**(D33). NPC 골드는 전리품을 상점에 팔아서만 생긴다.
  - 카테고리 비율은 몬스터 드랍 규칙(DropTable 1번: 장비 15 · 오브 10 · 스킬북 5 · 스킬 페이지 10, Nothing 제외)을 재사용한다. 기준 레벨은 **소속 마을 청크의 `MapManager.GetZone`**(월드 몬스터 레벨과 같은 기준)이다. 모든 선택과 아이템 롤은 결정론 RNG로 한다(D35).
  - 파티 Hunt는 분배 규칙(P3)이 생기기 전까지 **Success를 받은 파티원 각자가 1회씩** 롤한다.
  - 원정 중 가방(5칸)이 가득 차면 **가치(BasePrice)가 가장 낮은 것을 버린다.** 새 전리품도 비교 대상이다(D35).
  - 전리품은 장비여도 **장착하지 않는다.** 가방에 넣었다가 Trade에서 판다. NPC가 강해지는 경로는 상점의 기본 장비 구매뿐이다 [D119, 2026-10-03]. (이전: 업그레이드 문턱 D45를 넘으면 바로 장착, 관측값 Hunt 성공 1회당 약 0.1%.)
  - Delve·던전 완료 보상 전리품도 같다 — 업그레이드 사건은 Trade에서만 생긴다.
- **DungeonDelve** ✅ P2a: 소속 마을의 던전 슬롯(`DungeonId`)을 **추상 대상으로만** 참조하는 **12게임시간** 활동이다 [D55]. [src: Assets/Scripts/Manager/NpcManager_Delve.cs]
  - 파티가 꾸려지면 파티로(기존 자동 구성 재사용), 아니면 솔로로 간다. 대상은 소속 마을 슬롯 중 결정론 균등 선택이고, 입구 배치 여부와 관계없다 [D57, D68].
  - 던전 내부 저장 상태(처치·상자·`DungeonRecord`)를 **바꾸지 않는다.** 던전 난이도는 지금 던전(DungeonTable 1번)을 그대로 쓴다 [D49].
  - 판정: Hunt보다 성공률은 낮고 부상은 많다. 사망은 D48 곡선 [D65].
  - 보상: 성공 시 **`MonsterLevel` 기준 일반 전리품 1회**만. 골드·Food 없음 [D66].
  - 원정 중 대상 던전이 바뀌었으면(그사이 완료되어 세대가 넘어감) 성공을 **실패로 처리**한다. 부상·사망은 그대로다 [D68].
  - 결과는 `DungeonInfo` 소문으로 남아 퍼진다("○○ 던전에서 좋은 걸 건졌다") — P2b.

**NPC 던전 완료 (낮은 확률)** [D5]

NPC 파티가 드물게 보스까지 잡아 던전을 **완료**할 수 있다. 완료되면 플레이어가 완료했을 때와 같이 입구가 사라지고, 같은 마을 주변에 다음 세대 입구가 생긴다([DUNGEON_RUNTIME §3.2](../map/DUNGEON_RUNTIME_DESIGN.md)). 마을마다 던전 2~3개가 유지되므로 **던전 수 자체는 줄지 않는다.** 플레이어가 잃는 것은 "그 던전"뿐이다. 그래서 보호 규칙은 플레이어가 **이미 투자한 던전**을 지키는 데 집중한다.

- **완료 확률** ✅ P2a: DungeonDelve가 성공한 경우에만 따로 굴린다 [D55, D67].
  - capability 0.475(평범한 NPC)에서 **3%** → 1.0에서 **8%** 선형. 0.475 미만이면 0%.
  - 파티는 성공한 파티원들의 판정 capability 평균(동료 지원 반영)을 쓴다.
- **보호 규칙** (하나라도 해당하면 완료 불가) [src: Assets/Scripts/Dungeon/DungeonManager_NpcCompletion.cs]
  - 플레이어가 **입장한 적 있는 던전**(`DungeonRecord`가 존재함). 진행과 상자 상태를 지킨다. 세이브 무결성에도 필요하다 — 세이브 검증은 기록이 있는 던전의 슬롯 DungeonId가 기록과 같은지 확인한다 [D67].
  - 플레이어가 **현재 던전 안에 있음**. 이때는 NPC 시뮬레이션 자체가 멈춘다.
  - 해당 마을에서 **최근 72 게임시간 안에 NPC 완료**가 이미 있었음. 마을당 NPC 완료 쿨다운이다.
  - **이번 완료 뒤 NPC 교체 슬롯 수가 그 마을 던전 슬롯 수의 절반을 넘음**. 한 마을 주변 던전이 전부 NPC 손에 넘어가지 않게 한다. 분모는 입구가 아니라 슬롯 수이고, 2·3슬롯 마을 모두 NPC 교체 세대는 최대 1개다. 이미 교체 세대인 슬롯을 다시 완료하는 것은 허용한다 [D67].
  - 던전 입장·입구 배치 저장이 진행 중, 또는 원정 중 대상 던전의 세대가 이미 넘어감 [D67, D68].
  - `DungeonRecord`는 플레이어가 그 던전에 처음 입장할 때 만들어지고, 플레이어가 완료하고 나오면 지워진다. 따라서 "기록이 있다 = 플레이어가 들어갔고 아직 완료하지 않은 던전"이다. [src: Assets/Scripts/Dungeon/DungeonManager.cs]
- **플레이어가 입장하지 않은 던전**은 발견·입구 배치 여부와 관계없이 같은 확률로 완료할 수 있다. 발견 기록은 두지 않는다 [D29, D57].
- **완료 처리**: 플레이어 보상 경로(`DungeonCompletionTransaction`)는 바꾸지 않고, **슬롯 단위 NPC 완료 진입점**(`DungeonManager.TryCompleteByNpc`)을 따로 둔다 [D58].
  - 슬롯을 제자리에서 바꾼다: `Generation`+1, 새 `DungeonId`, 입구가 있었으면 없애고 그 좌표를 이전 입구로 기록, `PlacementReadyGameTime` = 지금 + 교체 쿨다운, `NpcReplacedGeneration` = 새 세대. 마을의 `LastNpcCompletionGameTime`을 기록한다.
  - 즉시 저장하지 않는다. 다음 저장이 Dungeons 또는 NpcState 중 하나를 실으면 둘을 함께 실어 슬롯 변경과 NPC 보상이 같은 revision에 커밋된다.
  - 플레이어 Gold, `DungeonRecord`, 전역 `CompletedCount`는 건드리지 않는다 [D67].
  - 보상: `BossLevel` 기준 일반 전리품 1회(항상)와 `DungeonCleared` Deed. 골드 없음 [D66].
- **가독성**
  - 입구 자리 흔적은 P2에서 넣지 않는다 [D59]. 월드 피드 알림도 없다.
  - `DungeonCleared` Deed와 자랑 토픽 연결은 P2c [D61]. "큰 Renown 상승"은 P3 [D58].
  - 소문 "○○ 일행이 △△ 던전을 끝냈다"가 퍼진다 — P2b.
- **빈도**: 진단 30일 마을당 0.387회(목표 0.5회 이하, D63), 60일 0.710회. 플레이어 입장 던전(시험용 기록 300개)의 NPC 완료 0건 [D62].

### 7.2 상점 거래 — 재고 변경 + 빈도 제한 [D1] ✅ P1b

NPC 거래는 플레이어와 **같은** `VillageData.MerchantStock`을 쓴다. 구매하면 `RemainingCount`가 줄고, 판매한 전리품 일부는 매물로 진열된다. 트랜잭션은 플레이어 경로와 분리된 NPC 전용 API다(`NpcManager.TradeAtShop` → `VillageManager_NpcTrade`). 한 번의 Trade 활동은 **판매 → 구매** 순서로 진행한다.

**닫힌 경제** [D34]: 판매 대금은 **마을 Gold에서 차감**하고, 마을 Gold가 모자라면 상점은 그 물건을 매입하지 않는다(NPC가 계속 보유). 구매 대금은 **전액 마을 Gold로** 들어간다. 거래 전후 (마을 Gold + NPC Gold) 합계는 보존된다.

**판매 (NPC 쪽)**
- 매각 가능한 인벤토리 아이템을 전부 판다. 가격은 플레이어와 같은 매입가 공식이다. 오브처럼 매각 불가(BasePrice 0)인 것은 보유한다.
- NPC 판매는 자원 환원(`ReturnResourceType`)을 하지 않는다. NPC 골드는 Gold 자원으로만 합류한다(경계 문서 §3.1, D47).

**구매 조건 (NPC 쪽)**
- **기본 아이템 장비만 산다**(`BasicItemId > 0`) [D119, 2026-10-03]. 상점은 기존 재고(무작위 옵션 장비) 뒤에 **기본 장비 칸**(상점 Tier 1~2는 3칸, 3~4는 4칸)을 따로 진열하고, NPC 후보는 사실상 이 칸뿐이다 [D117]. 기존 칸의 무작위 옵션 장비는 전부 플레이어 몫이다. 상세: [NPC_SHOP_EQUIPMENT_DESIGN.md](NPC_SHOP_EQUIPMENT_DESIGN.md) §4·§5.3.
- 교체하면 **NPC 전체 전투력이 +15% 이상** 오를 때만 산다 [D45]. 소소한 교체로 재고를 소모하지 않게 하기 위해서다. 개인 상한의 80%를 넘은 NPC는 +30%가 필요하다(§10.1).
- 사고 나서 자기 **개인 상한**을 넘게 되는 매물은 사지 않는다(§10.1).
- 가격 ≤ Gold − 치료비 예비금(10G) [D36].
- NPC별 쇼핑 쿨다운 **48 게임시간**. 구매 성공에만 적용하고, 판매는 매번 시도한다(D47).
- 조건을 통과한 후보 중 교체 후 전투력이 가장 높은 1개를 산다(동점이면 싼 것). NPC는 모험가 매입품을 사지 않는다(D47).
- Shop 시설이 없는 마을에서는 거래하지 않는다. 그 회차 재고가 아직 롤되지 않았으면 먼저 결정론으로 롤한다.

**상점 보호 (재고 쪽)**
- 한 상점의 NPC 구매는 **재입고 회차당 최대 매물 종류의 25%** 로 제한한다(최소 1, 최대 3).
- 한 상점의 NPC 구매 트랜잭션은 **게임시간 6시간당 1건**으로 제한한다. 여러 NPC가 동시에 귀환해도 재고가 한 번에 비지 않는다.
- ~~**희귀·특수 슬롯**(`RareImport`·`FacilityPool`)은 재입고 간격의 **50%가 지난 뒤에만** NPC가 살 수 있다.~~ — 2026-10-03 삭제. NPC가 그 칸에서 살 물건(기본 아이템)이 없어 결과를 바꾸지 못한다 [D119].
- 회차 한도는 floor(롤된 매물 종류 × 0.25)를 1~3으로 자른 값이다. 모험가 매입품과 **기본 장비 칸**은 종류 수에 넣지 않는다 — 기본 장비 칸을 추가하기 전과 같은 한도다(Tier 1~3 상점 1건, Tier 4 2건) [D117].

**판매 → 매물 추가**
- NPC가 판 전리품 중 가치가 높은 장비·스킬북·스킬 페이지는 **"모험가 매입품" 슬롯**(회차당 최대 2개)으로 진열된다. 모드를 유지한 실제 인스턴스이며, 다음 재입고 때 사라진다. 슬롯이 가득 차면 팔리지 않은 매입품 중 가장 싼 것보다 비쌀 때만 교체한다. NPC가 갈아 끼우고 판 기본 아이템이 여기 진열돼도 NPC는 되사지 않는다(모험가 매입품 제외 규칙).
- 이것이 NPC가 던전에서 가져온 물건이 플레이어 손에 들어오는 주 경로다. 플레이어가 매입품을 살 때는 일반 매물과 같이 처리하며 마을 Gold는 변하지 않는다.

**가독성** [D42]
- ✅ 매입품에 "모험가 매입품" 라벨을 표시한다. 품절 매물은 구매자(플레이어·NPC)와 관계없이 목록에서 숨긴다 — P1의 "○○가 구매함 · 품절" 표시는 P2a에서 제거했다(D53).
- 상인 대사는 넣지 않는다(D52).

**LOD**

- 빈도 제한 덕분에 총 트랜잭션 수는 마을 수 × 소수로 묶인다.

### 7.6 NPC 간 배신 · 절도

**배신** — 파티 결과 판정 시점에 한 번 평가한다.

```
BetrayalScore = Greed×a + (100−Loyalty)×b + (100−Honesty)×c
              + 전리품 가치 비율×d
              − 파티원 호감도×e − 평판 손실 예상×f − 충성 높은 증인 수×g
```

| 유형 | 성향 | 결과 |
|------|------|------|
| 분배 속이기 | 탐욕↑ | 약속보다 많이 가져감 |
| 위기 이탈 | 용기↓ | 원정 실패 시 동료의 부상·사망 확률 상승 |
| 선점 | 정직↓ 호기심↑ | 공유한 소문의 목표를 혼자 먼저 털어감 |

- **발각**: 증인과 피해자 생존 여부로 판정한다. 발각되면 원한 관계가 생기고, 평판이 떨어지고, `Betrayal` 소문이 퍼진다. 피해자는 복수나 파티 기피 성향을 얻는다.

**절도 (NPC 간)** [D4] ✅ P4 2026-10-02 (D98~D115) [src: Assets/Scripts/Manager/NpcManager_Theft.cs] — 마을 체류 중에만, NPC끼리만 일어난다(플레이어 대상 절도 없음, D2).

- **누구의 무엇을**(D99): 소문 조건 없이 같은 마을에서 대기 중인 NPC 중 고른다(원한 관계·가족·친구·호감 50 이상 제외, 부상 중은 대기 조건으로 자동 제외). 훔치는 것은 **가방의 비스택 아이템**뿐이고 장착품은 대상이 아니다. 가중치 = 1 + 가치 / 가방 안 최고 가치(비싼 물건만 노리지 않게).
- **발각**(D101): 증인 없이 피해자 성향으로만 정한다 — 25% + 30%×호기심/100 + 20%×인내/100(평균 약 50%).
  - **현장 적발**: 물건은 주인에게 남는다.
  - **안 들킴**: 물건이 도둑 가방으로 옮겨가 다음 Trade에서 팔린다. 훔친 장비는 업그레이드여도 **장착하지 않는다**(2026-10-03 D119 — 이전에는 전리품 장착 규칙 D45로 장착). 피해자는 도둑맞은 사실만 알고, 도둑 쪽에는 기록이 없다.

## 8. 플레이어와 NPC 사이의 배신 · 결투 [D2, D6, D7]

배신은 양방향이다. NPC가 플레이어를 배신할 수 있고(§8.3~8.7), 플레이어도 NPC를 배신할 수 있다(§8.9). 결투(§8.8)는 양쪽 모두의 해결 수단이다.

### 8.0 선행 조건 — NPC 실전투 기반 → [NPC_COMBAT_DESIGN.md](NPC_COMBAT_DESIGN.md)

동행, 위기 이탈, 결투는 NPC가 **화면 안에서 실제로 싸워야** 성립한다. 현재 NPC는 전투 부품만 있고 싸우지 않는다(적 인식 건너뜀, 진영 없음).

실전투의 **런타임 메커니즘**은 별도 문서 [NPC_COMBAT_DESIGN.md](NPC_COMBAT_DESIGN.md)가 소유한다.
- 진영 명시, 결투 상대 한정 적대, 조건부 인식
- 동행 중 추종·순간이동·아군 피해 없음·던전 동반 [D13, D14]
- 도주 전환, 드랍 줍기, 결투 진행·무릎 꿇기, 전투 사망 연결

본 문서는 *언제, 왜* 싸우는지와 *그 결과*(동행 제안·정산, 배신 판정, 결투의 명분·응답·드랍·관계 파장)를 소유한다. 실전투 기반은 P1~P4와 독립적으로 진행한다(§13 P5-0).

### 8.1 전제 — 임시 동행 (Joint Venture)

배신하려면 먼저 함께 행동해야 한다. **1회성 동행**을 도입한다. 영구 동료는 companionSystem 소관으로 남긴다.

- **시작**: NPC가 소문 목표를 들고 먼저 제안하거나, 호감도 단계가 충분할 때 플레이어가 요청한다.
- **분배 약속 선택**: 균등 / 기여도 / 먼저 줍는 사람. 플레이어가 고르거나 NPC가 제안한다.
- **진행**: NPC는 실체화된 상태로 플레이어를 따라다니며 싸운다. **던전 안에서만** 함께한다(D97) — 필드 동행은 없다.
- **종료**: 목표 달성, 귀환, 또는 **배신**.
- **정산**: 동행이 정상 종료되면 **분배 정산 창**이 뜬다. 동행 중 각자 주운 전리품이 나열되고, 약속에 따라 넘겨야 할 몫이 표시된다. 플레이어가 자기 몫이 아닌 것을 넘겨줄지 **직접 고른다.** 플레이어의 배신은 주로 이 자리에서 일어난다(§8.9).

### 8.2 절대 규칙

- **플레이어 인벤토리·장비·보관함의 아이템은 어떤 경로로도 가져가지 않는다.** [확정: D2]
- 배신은 **아직 누구의 것도 아닌 것**(바닥의 드랍, 보물상자, 공동 목표의 보상)과 **약속·신뢰**를 대상으로만 한다.

### 8.3 배신 유형 (가벼운 것 → 무거운 것)

| # | 유형 | 무엇을 하나 | 성향 | 참고 |
|---|------|-----------|------|------|
| 1 | **전리품 가로채기** | 약속을 어기고 바닥 드랍이나 상자를 먼저 주워 동행을 끝내고 떠남 | 탐욕↑ 용기 보통 | — |
| 2 | **위기 이탈** | 플레이어 HP가 낮거나 보스 페이즈에 들어가면 도주해 혼자 남김 | 용기↓ 충성↓ | Dragon's Dogma. ⏸ 도주 런타임 보류(D25) |
| 3 | **약속 불이행·선점** | 약속한 합류 시각에 나타나지 않고, 함께 얻은 정보로 목표를 먼저 털어감(오프스크린 처리) | 정직↓ 호기심↑ | — |
| 4 | **거짓 정보** | 위험을 줄여 말한 소문으로 플레이어를 강한 몬스터 지역에 유도 | 정직↓ 자존심↑(라이벌 의식) | 네메시스 |
| 5 | **평판 공격** | 동행 후 플레이어를 헐뜯는 거짓 소문을 퍼뜨림 → 다른 NPC들의 Trust 소폭 하락 | 정직↓ 친화 보통 | — |
| 6 | **보상 앞 결투** | 보스 처치 직후 보상 상자 앞에서 "이건 내 몫이다"라며 결투를 걸어옴(§8.8) | 탐욕↑ 용기↑ 충성↓ | 다크소울 패치스 |

유형 6은 **보스급 보상 + 극단적 성격 조합**에서만 열린다. 가장 드물게 나와야 한다. 기습이 아니라 **결투 선언**으로 시작해서 플레이어가 대응할 틈을 준다.

### 8.4 판정

- **시점**: 이벤트로만 평가한다. 드랍 발생, 상자 열기 직전, 보스 처치, 플레이어 HP 임계, 동행 종료. 매 틱 평가하지 않는다.
- **점수**: §7.6 공식에서 NPC 간 호감도를 **플레이어 관계**(`Affinity`, `Trust`)로 바꾼다. 호감 단계가 높으면 사실상 0이 되도록 억제 계수를 크게 둔다.
- **유형 선택**: 점수가 임계를 넘으면 성격으로 유형을 고른다(위 표의 "성향" 열).

### 8.5 복선 — 공정하게 배신하기

배신은 **예측할 수 있었어야** 재미가 있다. 이유 없이 당하면 억울하기만 하다.

- **제안 대사 톤**: 탐욕이 높은 NPC는 보상 얘기를 많이 한다(기존 `PersonalityBias` 활용).
- **동행 중 짧은 말(bark)**: "저 상자… 꽤 값나가 보이는군." 배신 점수가 높을수록 자주 나온다.
- **소문**: 이 NPC의 과거 배신은 `Betrayal` 소문으로 다른 NPC에게서 들을 수 있다.
- **검사 UI**: `UINpcInspect`에 성격 일부를 노출한다. Trust가 높을수록 더 많이 보인다.

### 8.6 결과와 대응

| 결과 | 내용 |
|------|------|
| 관계 | 플레이어 관계 Trust 급락, Affinity 하락. 유형 6이면 Fear도 변동 |
| 평판 | 배신 NPC의 Renown 하락, `Betrayal` 소문 전파 → 다른 NPC가 그 NPC와 파티를 기피 |
| 기록 | 배신 NPC와 플레이어 양쪽 Deeds에 기록 → 이후 대화 토픽 |
| 플레이어 선택지 | **추궁**(대화로 전리품 반환이나 사과 요구 — 자존심이 낮으면 응함), **용서**(Affinity 일부 회복), **결투**(§8.8 — 패배한 배신자를 처단하거나 살려줄 수 있음) |
| 후일담 | 자존심이 낮은 배신자는 나중에 사과하며 보상을 건넬 수 있음(패치스 방식) |

### 8.7 빈도 안전장치

- 같은 NPC가 플레이어를 배신하는 것은 **1회**까지다. 관계가 복구되기 전에는 동행 제안이 불가능하다.
- **세계 전체**에서 플레이어 대상 배신은 게임시간 **7일에 1회**로 제한한다.
- 플레이어의 **첫 동행 2회**에서는 배신하지 않는다. 동행 시스템에 먼저 익숙해지게 하기 위해서다.

### 8.8 결투 (Duel) [D6]

플레이어가 NPC를 죽일 수 있는 **유일한 경로**다. 평소에는 NPC를 공격할 수 없다는 원칙을 유지하고, 결투라는 명시적 절차 안에서만 생사를 건 싸움을 허용한다.

> ⏸ **2026-09-27 결정(D19~D24)으로 현재 범위가 바뀌었다.** 결투는 누구든 HP 0이 되면 HP 1로 끝나며 아무도 죽지 않는다(D22). 아래의 처단·드랍·처단 이후 파장은 **C2에서 처단 경로를 다시 도입할 때의 기준안**으로 남긴다. 런타임 규칙은 [NPC_COMBAT_DESIGN §7](NPC_COMBAT_DESIGN.md)이 정본이다.

결투는 **아무 NPC에게나** 신청할 수 있다 [D7]. 대신 **명분**이 있느냐에 따라 상대의 응답과 세상의 반응이 완전히 달라진다.

**명분 (Grievance)**

| 등급 | 조건 | 예 |
|------|------|----|
| **명분 있음** | 그 NPC가 **플레이어에게 직접** 잘못한 기록(Deed)이 있다 | 배신 유형 1~6을 당함 |
| **약한 명분** | 그 NPC의 잘못을 **소문으로만** 안다(플레이어가 피해자가 아님) | "○○가 동료를 버렸다"는 `Betrayal` 소문 |
| **명분 없음** | 위 둘 다 아님 | 좋은 장비를 가진 NPC, 이유 없는 도발 |

명분은 **플레이어와 목격자가 무엇을 알고 있는가**로 판정한다. 세계의 객관적 진실이 아니다. 소문 기반의 per-NPC 지식 원칙(§7.4)을 그대로 따른다.

**신청 경로**

| 경로 | 조건 |
|------|------|
| 플레이어 → 아무 NPC | 대화 메뉴에 **"결투 신청"** 이 항상 뜬다. 명분이 없으면 확인 창을 한 번 더 띄운다("이유 없이 싸움을 거는 것은 배신으로 여겨질 수 있습니다") |
| NPC → 플레이어 | 배신 유형 6, 또는 **플레이어에게 배신당한 NPC**(§8.9)가 자존심·용기가 높을 때. 플레이어는 받거나 거절할 수 있다 |
| NPC → NPC | 절도나 배신을 당한 NPC 중 자존심·용기가 높은 쪽이 신청한다. 화면 밖 결과 판정은 **P3에서 구현**하고, 화면 안 전투 장면은 ⏸ 나중에 구현한다 [D24]. 같은 마을에서 둘 다 대기 중일 때만 일어나고, 실체화된 NPC는 참가하지 않는다 [D30]. 계기·결과 기본안은 COMBAT Q16~Q18 |

**신청 불가 상태** — 명분과 관계없이 적용한다. 이 상태 외에 **결투에서 보호되는 NPC는 없다** [D8]. 진행 중인 소망이 있는 NPC가 죽으면 그 소망은 실패로 처리한다.
- **플레이어 → NPC: 신청 불가 상태가 없다** [D19]. 부상·원정·동행 중인 NPC에게도, 던전 안에서도 신청할 수 있다. 재신청 쿨다운 여부는 COMBAT Q15(기본안: 없음).
- **NPC → NPC**: 둘 중 하나라도 플레이어와 동행 중이거나 동행 예약된 상태면 일어나지 않는다. 플레이어와 결투 중인 NPC도 참가하지 않는다.
- ~~상대가 부상(Wounded) 상태이거나 원정 중이다 / 동행 중이다 / 72 게임시간 쿨다운~~ → D19로 플레이어 신청에는 적용하지 않는다.

**NPC의 응답 (플레이어가 신청한 경우)**

| 명분 | 응답 |
|------|------|
| 명분 있음 | **수락**(자존심·용기↑) / **배상 제안**(용기↓ — 가로챈 것이나 골드를 내놓으며 빈다. 받으면 결투 취소) / **도주**(용기↓ 정직↓ — 잠적. "비겁자" 소문이 퍼지고 Renown이 크게 떨어진다. 다시 마주치면 거절할 수 없다) |
| 약한 명분 | 해명하거나(정직↑이면 소문이 거짓이었다고 반박할 수 있다) 수락한다. 거절해도 비겁자 소문은 약하게만 퍼진다 |
| 명분 없음 | **명예 야망**이나 자존심이 매우 높은 NPC는 도전으로 여겨 수락한다. 나머지는 **거절**하고, 거절해도 NPC에게 불이익이 없다. 신청했다는 사실만으로 그 NPC의 플레이어 Trust와 Affinity가 떨어진다. 가까운 사이였다면 이것 자체가 **배신**으로 기록된다(§8.9) |

**진행 규칙** — 결투 영역, 1:1 보장, 결투 쌍 적대, 이탈 기권, 무릎 꿇기, 세이브 금지 등 **런타임 진행**은 [NPC_COMBAT_DESIGN §7](NPC_COMBAT_DESIGN.md)이 소유한다. 본 절은 결과 처리 훅(§7.4)이 넘겨준 정보로 아래 결과·드랍·파장을 적용한다. 입회인은 결과를 목격 소문으로 퍼뜨린다.

**결과**

| 결과 | 처리 |
|------|------|
| 플레이어 승리 | **현재(D22)**: NPC의 HP가 0이 되면 HP 1로 두고 결투가 끝난다. NPC는 대기 상태로 돌아간다. **C2 기준안(보류)**: ~~무릎을 꿇으면 처단(`MarkNpcDead`)/자비를 고른다.~~ 자비의 관계 재설정("빚진 사이", 원한)은 C2 관계 규칙에서 다시 검토한다 |
| 플레이어 패배 | 플레이어는 죽지 않고 **HP 1로 쓰러진다**(D22와 일치). 상대의 자존심이 오르고 "모험가를 꺾었다"는 소문이 퍼진다(C2). 명분 있는 결투였다면 배신자는 전리품을 확정적으로 갖는다. 플레이어의 인벤토리와 장비는 가져가지 않는다(§8.2). 재도전 쿨다운은 D19에 따라 두지 않는다(COMBAT Q15) |
| NPC 간 결투 | 화면 밖 판정은 P3, 화면 안 장면은 ⏸ 나중 [D24]. 기준안: 같은 마을에서 둘 다 대기 중일 때만(실체화 NPC 제외, D30), 전투력 비교로 승패, 패자는 부상, 관계 변화(COMBAT Q17) |
| 무승부 | 실제 시간 3분이 지나면 무승부로 끝난다 [D27]. 동행 중이던 NPC는 승패·무승부와 관계없이 동행을 끝내고 마을로 돌아간다 [D26] |

**처단 시 떨어지는 것**

| 명분 | 드랍 |
|------|------|
| 명분 있음 | 가로챈 전리품 전부 + 장비 일부 |
| 약한 명분 | 장비 일부 |
| 명분 없음 | **없음.** 유품은 가족이나 친구에게 넘어간다. 가족이 없으면 마을 상점의 모험가 매입품 슬롯에 나온다 |

명분 없는 처단에서 장비를 얻을 수 없게 하는 이유: 좋은 장비를 가진 NPC를 결투로 사냥하는 것이 최적 전략이 되면 NPC 사회가 무너진다. 명분 없는 결투는 **이익이 아니라 감정과 선택의 수단**으로만 남긴다.

**처단 이후 — 관계의 파장**

| 명분 | 목격자·마을의 반응 |
|------|------------------|
| 명분 있음 + 배신이 소문으로 알려져 있음 | **정당하다**고 본다. 큰 관계 페널티가 없다. 오히려 일부 NPC의 Trust가 오른다 |
| 명분 있음 + 배신이 알려지지 않음 | 목격자들의 플레이어 Fear가 오르고 Affinity가 조금 떨어진다 |
| 약한 명분 | 목격자들의 Fear가 오른다. 소문을 믿지 않던 NPC(정직↑, 죽은 NPC와 친한 사이)는 Affinity가 크게 떨어진다 |
| 명분 없음 | **"살인자" 소문**(`PlayerDeed`)이 퍼진다. 이 소문을 아는 NPC는 플레이어 Fear↑ Affinity↓ Trust↓. 동행 제안을 거절하고, 겁이 많으면 플레이어를 피한다. 반복될수록 소문이 더 멀리 퍼진다 |

- 마을 단위 "악명 수치"는 두지 않는다. 반응은 **소문을 알게 된 NPC 각자**에게서 일어난다. 먼 마을에서는 아직 모를 수 있다.
- 죽은 NPC의 **가족과 친구**는 명분과 관계없이 플레이어에게 원한을 갖는다(기존 `DeceasedRelationMemory` 경로). 이들이 나중에 복수 결투를 신청해 올 수 있다. 명분 없는 처단이었다면 이들의 복수 결투는 **명분 있음**으로 취급한다.

**안전장치**
- 결투 신청 대상은 제한하지 않는다 [D7]. 대신 명분 없는 결투는 드랍 없음(위 표)과 관계 페널티로 억제한다.
- 세이브 금지·회복 수단 사용 등 진행 중 규칙은 [NPC_COMBAT_DESIGN §7.2](NPC_COMBAT_DESIGN.md).

### 8.9 플레이어가 NPC를 배신하기 [D7]

NPC가 플레이어를 배신할 수 있듯이, 플레이어도 NPC를 배신할 수 있다. 시스템은 플레이어의 선택을 막지 않고, **NPC가 그것을 기억하고 반응**하게 한다.

**배신으로 기록되는 행동**

| # | 행동 | 판정 시점 | NPC가 알아채는가 |
|---|------|----------|----------------|
| 1 | **정산 거부** | 동행 종료 정산 창에서 약속된 몫을 넘기지 않음 | 항상 |
| 2 | **약속 불이행** | 합류 약속 시각에 나타나지 않음 | 항상 |
| 3 | **명분 없는 결투 신청** | 가까운 사이(호감 단계 높음)인 NPC에게 명분 없이 결투를 신청함 | 항상 |
| 4 | **동료 처단** | 명분 없이 결투에서 처단함 | 죽은 NPC의 가족·친구·목격자 |

- 배신 1~3의 피해자는 살아 있으므로, 그 NPC가 직접 반응한다. 4는 주변이 반응한다.
- "위기에 버리기"(전투 중 동행 NPC를 두고 멀어짐)는 배신으로 판정하지 않는다 [D9]. 거리·HP 기준이 애매해서, 플레이어가 의도하지 않은 이동까지 배신으로 잡힐 수 있기 때문이다.
- 플레이어의 배신은 §8.7의 빈도 제한을 받지 않는다. 플레이어의 선택이기 때문이다.

**NPC의 반응 — 성격으로 갈린다**

| 성향 | 반응 |
|------|------|
| 자존심↑ 용기↑ | 플레이어에게 **결투를 신청**한다(명분 있음). 거절하면 "비겁한 모험가" 소문을 퍼뜨린다 |
| 정직↓ 탐욕↑ | **되갚기**: 이후 배신 유형 3~5(선점·거짓 정보·평판 공격)를 쓸 확률이 크게 오른다. 이때는 §8.7의 세계 쿨다운을 적용하지 않는다(복수는 정당한 동기다) |
| 용기↓ | 플레이어를 **피한다.** 말을 걸면 짧게 대답하고, 동행 제안을 거절한다 |
| 충성↑ 친화↑ | 크게 상처받는다. Affinity가 매우 크게 떨어지지만, 사과와 선물로 **회복할 여지**를 남긴다 |

**공통 결과**
- 피해 NPC의 플레이어 Trust가 급락하고 Affinity가 떨어진다. `TrustCap`이 낮아져 한동안 신뢰를 완전히 회복할 수 없다.
- `Betrayal` 소문(대상 = 플레이어)이 피해자의 관계망을 타고 퍼진다. 이 소문을 아는 NPC는 동행 제안을 망설이고, 동행하더라도 **먼저 줍는 사람** 분배를 요구한다.
- 피해자와 플레이어 양쪽 Deeds에 기록된다. 이후 대화에서 그 일을 꺼낸다.

**되돌리기**
- **사과**: 대화 메뉴에서 사과하고, 넘기지 않은 몫이나 그에 준하는 골드를 건넨다. 정직과 충성이 높은 NPC일수록 쉽게 받아준다.
- **시간**: 오래 지나면 소문의 영향이 약해진다. 다만 피해자 본인의 기억(Deed)은 사라지지 않는다.

## 9. 골드의 순환 — 닫힌 경제 [D3, D34, D36, D41] ✅ P1b

> 원안(거래세 5%, 여관비 50%, 일일 유입 15% 상한)은 D34·D36으로 폐기했다. 골드 생산처를 마을 하나로 두어 밸런스를 잡기 쉽게 하기 위해서다.

```
          인구 생산 (마을당 하루 1.2~2.4G) — 유일한 골드 생성처
                 │
                 ▼
 ┌──────── 마을 Gold ◀──────────────┐
 │                                  │
 │ NPC 전리품 매입 대금            NPC 장비 구매 대금
 │ (마을 Gold 부족 시 매입 거절)   NPC 치료비
 ▼                                  │
 NPC Gold ──────────────────────────┘   (사망 시 소멸 — D46)
```

- **생성**: 새 골드는 마을 인구 생산에서만 생긴다. Hunt는 골드를 주지 않는다(D33).
- **순환**: 판매 대금은 마을 Gold → NPC, 구매 대금과 치료비는 NPC → 마을 Gold로 **전액** 이동한다.
- **소멸**: NPC가 죽으면 소지 Gold는 사라진다(D46). 유품 규칙(Q3)에서 다시 검토한다.
- **Rest는 무료**다. 골드 소모처로 **추상 치료 서비스**를 둔다(D36): 부상 상태가 될 때 Gold ≥ 10G이고 결정론 판정을 통과하면 10G를 소속 마을에 내고 회복 시간을 24h → 8h로 줄인다. 구매 확률은 탐욕 0에서 95%, 100에서 55%이고, 야망 보정(명예·탐험 +10%p, 안전 +5%p, 부 −10%p, 40~98%로 제한)을 더한다.
- **반영 경로** [D41]: `VillageData.Resources[Gold]`를 쓰되, NPC 전용 `VillageResourceSimulation.DepositNpcGold`(상한 없이 누적)/`TryWithdrawNpcGold`(부족하면 실패)로만 움직인다. `ProduceResource`(상한 50에서 잘림)와 `ConsumeResource`(플레이어 알림)는 쓰지 않는다. `VillageSimulationParity`가 추상·실시간 두 경로의 결과를 비교한다.
- **입력 금지 유지**: NPC 골드는 **Gold 자원으로만** 합류한다. Population, Tier, 건설 후보 점수에는 직접 입력하지 않는다(경계 문서 §3.1, §8).
- **관측(2026-09-28 진단)**: 마을 생산량이 작아 매입 거절이 판매보다 많다(30일 매입 거절 약 36,000건). 지금은 마을 Gold를 쓰는 곳이 없어 게임 영향은 없고, 밸런스는 나중에 조정한다.

## 10. 안전장치 · 밸런스

### 10.1 성장 곡선 — "초반엔 NPC가 강하고, 플레이어가 역전한다" [D10]

**기조**: NPC는 게임 시작 시점에 플레이어보다 강하다. 그리고 **거의 강해지지 않는다.** 운이 좋을 때만 가끔 한 단계 오른다. 플레이어는 꾸준히 성장하므로 **NPC를 쫓아가 따라잡는 맛**이 생긴다. **이 추격과 역전의 체감이 플레이어 재미의 기본**이다. 본 문서의 모든 성장 규칙은 이 기조보다 아래에 있다.

**성장 모델 — 거의 평탄, 가끔 계단** [D11]

```
전투력
  │                               ╱ 플레이어 (꾸준히 성장)
  │                             ╱
  │            ┌──────── 운 좋은 NPC (드물게 한 계단)
  │  ──────────┘─────────╱────── 대부분의 NPC (거의 그대로)
  │  NPC 시작값        ╱ ↑ 따라잡음
  │                  ╱
  │  플레이어 ─────╱
  └──────────────────────────────────▶ 게임 시간
```

- **NPC 전투력을 시간에 따라 강제로 올리지 않는다.** 기준선도, 정해진 성장 속도도 두지 않는다.
- 전투력이 오르는 경로는 **상점에서 다음 단계 기본 아이템을 샀을 때** 하나뿐이다(2026-10-03 D119 — 전리품·장물·던전 보상은 장착하지 않고 판다). 그런 일이 드물게 일어나도록 만든다(아래 장치).
- 대부분의 NPC는 생성 시점의 전투력 근처에 머문다. 오르지 않은 채로 은퇴하거나 죽는 것도 정상이다.
- 초반·중반·후반 같은 구간 목표도 두지 않는다. 플레이어가 언제 누구를 따라잡는지는 **그 NPC의 시작 전투력과 운**이 정한다.

**금지: 고무줄 보정(rubber banding)**
- NPC 성장은 **플레이어 전투력에 연동하지 않는다.** 플레이어가 강해졌다고 NPC도 따라 강해지면 추격하는 맛이 사라진다.
- 세계 경과 시간에 따라 자동으로 강해지는 규칙도 두지 않는다.
- 플레이어 전투력은 튜닝용 진단과 대화 연출(아래)에만 쓰고, NPC 성장 판정에는 넣지 않는다.

**성장을 "드문 행운"으로 만드는 장치**

| 장치 | 내용 |
|------|------|
| **전리품은 판매용** | 원정 전리품의 등급은 **목표 지역·던전 티어**로만 정하고(P1: 소속 마을 청크의 Zone, D35), 전리품은 **장착하지 않고 전부 판다**(2026-10-03 D119). 판 골드가 기본 장비 구매 자금이 된다 |
| **진열 운** | 업그레이드는 상점의 **기본 장비 칸**(회차마다 3~4개만 무작위 진열, D117)에 원하는 슬롯의 다음 단계 장비가 나왔을 때만 일어난다. 이것이 성장 속도를 늦추는 주된 장치다. (이전의 "희귀 드랍·던전 완료 보상 업그레이드" 행운은 일반 NPC에서 사라졌다 — 특수 NPC로 이월, D120) |
| **업그레이드 문턱** | 장비를 바꾸는 조건이 **NPC 전체 전투력** +15% 이상이라(D45), 조금 나은 아이템으로는 전투력이 오르지 않는다. 판단은 결정론이고 운은 무엇이 진열되는가에만 작용한다(§7.2) |
| **개인 상한** | NPC 전투력은 **생성 시점 전투력 × (1 + 개인 편차)** 를 넘지 않는다. 편차는 평범한 NPC가 +20%, 강자(entityId 해시로 10%)가 +35~50%다(D38). 상한의 80%를 넘으면 업그레이드 문턱이 +30%로 올라간다. 아무리 운이 좋아도 한 NPC가 끝없이 강해지지는 않는다 |
| **구매 제한** | NPC는 자기 개인 상한을 넘는 매물을 사지 않는다. 좋은 매물은 플레이어 몫으로 남는다 |
| **스킬 성장** | `SkillLevel` 상승은 주요 사건(던전 완료, 결투 승리)에서만, 드물게 일어난다 |
| **소모처** | 치료비(D36), 사망(장비·골드 소실, D46 — 단 사망은 D48로 드묾), 장비 교체 시 구 장비의 헐값 판매. 후속: 강화 비용·실패, 파티 고용비 |
| **세대 교체** | 전역 총량 보충(`TryReplenishGlobalPopulation`)으로 들어오는 신규 NPC는 **생성 규칙 그대로의 장비**(기본 아이템, D118)로 시작한다. 운 좋게 강해진 NPC가 죽으면 그 자리를 평범한 신참이 채운다 |

- 골드와 전리품을 모으는 루프(§3)는 그대로 돌아간다. 다만 그 결과는 대부분 **생활, 거래, 소문, 관계**로 흘러가고, 전투력으로 이어지는 일은 드물다. NPC가 "강해지려고 애쓰는 모습"은 보이지만 실제로 강해지는 일은 드물다.

**운 좋게 강해진 NPC**
- 계단을 오른 NPC는 그 자체로 **이야기**가 된다. "○○가 던전에서 전설급 검을 얻었다"는 소문이 퍼지고, Renown이 오르고, 자랑 토픽이 생긴다.
- 이들은 플레이어가 한동안 쫓아가야 하는 **목표**이자 결투 상대, 라이벌이 된다. 개인 상한이 있으므로 플레이어가 꾸준히 성장하면 결국 따라잡는다.

**역전을 체감하게 하는 연출**

구간을 나누지 않고 **그 NPC와 플레이어의 전투력을 직접 비교**해서 반응을 바꾼다.

| 비교 | 반응 |
|------|------|
| NPC가 훨씬 강함 | 플레이어를 "풋내기"로 대한다. 동행하면 NPC가 목표를 정하고 이끈다 |
| 비슷함 | 대등한 동료로 대한다. 라이벌 의식이 생긴다 |
| 플레이어가 훨씬 강함 | 존중하거나 경외하고, 겁이 많으면 두려워한다. NPC가 플레이어에게 동행을 부탁한다 |

- 명예 야망 NPC는 자기보다 강해진 플레이어에게 결투를 청해 온다("한 수 배우고 싶다").
- 이 비교는 **연출에만** 쓴다. NPC 성장에는 영향을 주지 않는다(고무줄 보정 금지 원칙).

### 10.2 전투력 인플레이션 · 유품
