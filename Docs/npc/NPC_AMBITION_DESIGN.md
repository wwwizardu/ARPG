## 1. 문제와 목표

### 1.1 현재 상태 (2026-09-24 코드 기준)

- 활동 선택은 `NpcActivityResolver.SelectNextActivity`가 담당한다. **Rest와 Hunt 둘 중 하나**를 인내·용기·호기심 가중치로 랜덤 선택할 뿐이다. [src: Assets/Scripts/Npc/NpcActivityResolver.cs]
- Hunt 전투력(`GetPartyHuntPower`)은 **용기와 SkillLevel만** 본다. **장비가 결과에 영향을 주지 않는다.** 좋은 장비를 구해도 강해지지 않는 구조다. [src: Assets/Scripts/Npc/NpcActivityResolver.cs]
- Hunt 보상은 마을 Food뿐이다. NPC에게는 **골드도 개인 전리품도 없다.** [src: Assets/Scripts/Common/System/System_NpcSim.cs]
- 성격 8수치(`NpcStatComponent`: 친화·정직·탐욕·충성·용기·호기심·자존심·인내)가 있다. 하지만 대화 토픽 가중치와 관계 backfill에만 쓰이고, **행동 동기로는 쓰이지 않는다.** [src: Assets/Scripts/Common/Component/NpcStatComponent.cs, Assets/Scripts/Npc/Narrative/DialogueTopicSelector.cs]

- NPC는 전투용 컴포넌트(Stat·State·Skill·AI)를 갖고 있지만 **실제로 싸우지 않는다.** 적 인식을 건너뛰고, 진영이 없어서 중립으로 취급되며, 화면 안에서 사냥할 때도 AI를 멈춘 채 경로만 이동한다. 상세 내용은 [NPC_COMBAT_DESIGN §1](NPC_COMBAT_DESIGN.md). [src: Assets/Scripts/Factory/EntityFactory.cs, Assets/Scripts/Common/System/System_AI_Perception.cs]

→ NPC에게 **강해질 이유도, 강해질 방법도, 강해졌다는 결과도 없다.**

### 1.2 목표

0. **추격과 역전의 재미 (최상위 기조)**: NPC는 시작 시점에 플레이어보다 강하지만 **거의 강해지지 않는다**(운이 좋을 때만 가끔 오른다). 플레이어가 성장하며 NPC를 쫓아가 따라잡는 것이 기본 재미다. 아래 목표는 모두 이 기조 안에서만 성립한다(§10.1).
1. **목적 있는 행동**: 모든 NPC는 더 강해지기 위해 움직인다. 같은 목표라도 성격에 따라 방법이 달라야 한다.
2. **닫힌 루프**: 원정 → 전리품·골드 → 판매·구매·제작 → 전투력 상승 → 더 어려운 원정.
3. **사회적 드라마**: 소문 확인, 협력, 배신, (NPC 간) 절도가 성격과 관계의 결과로 일어난다.
4. **플레이어가 알아볼 수 있을 것**: 화면 밖에서 일어난 일도 상점 재고, 소문, 대화, Deeds로 드러난다.

### 1.3 범위

| In | Out |
|----|-----|
| 야망 도출, 활동 효용 선택, Gold·전투력·소문·평판 자원 | 상주 직업 NPC, 마을 작업자(경계 문서 §8 유지) |
| 상점 거래(재고 변경), Forge 강화, 파티 분배, NPC 간 배신·절도 | **플레이어 대상 절도** [확정: 사용자 답변 2026-09-24] |
| 플레이어와의 임시 동행 + 양방향 배신 + 결투 | 영구 동료 시스템(→ [companionSystem.md](companionSystem.md)) |
| 마을 Gold 약한 유입 | 마을 인구·Tier·건설 후보에 직접 입력 |

## 4. 성격 → 야망

### 4.1 야망 원형

모든 NPC의 공통 목표는 **전투력 상승**이다. 야망은 *왜* 강해지려는지를 정하고, 그 이유가 활동 효용의 가중치가 된다.

| 야망 | 주 성격 | 선호 수단 | 기피 |
|------|---------|----------|------|
| **탐험 (Explorer)** | 호기심↑ 용기↑ | 던전 원정, 소문 확인 | 오래 쉬기 |
| **명예 (Glory)** | 자존심↑ 용기↑ | 강한 목표 사냥, 파티 리더, 라이벌 추월 | 저위험 활동 |
| **부 (Wealth)** | 탐욕↑ 인내↑ | 전리품 되팔기, 강화, 저가 매수 | 손해 보는 분배 |
| **동료 (Comrade)** | 충성↑ 친화↑ | 고정 파티, 공정한 분배, 구조 원정 | 혼자 하는 원정 |
| **기회 (Opportunist)** | 탐욕↑ 정직↓ | 분배 속이기, 거짓 소문, 절도 | 공정한 분배 |
| **안전 (Cautious)** | 용기↓ 인내↑ | 저위험 사냥, 정보 수집, 장비 보강 | 던전, 강한 목표 |

### 4.2 도출 규칙 [제안]

- 원형마다 성격 수치의 선형 점수를 매긴다. 예: `Opportunist = Greed + (100 − Honesty)`.
- **최고점 = 주 야망, 차점 = 보조 야망**으로 둔다. 가중치는 주 1.0, 보조 0.5.
- 성격 수치에서 결정론적으로 계산하므로 **저장하지 않는다.** 성격이 바뀌면 야망도 따라 바뀐다.
- 같은 탐욕이라도 정직하면 **부**, 정직하지 않으면 **기회**가 된다. 수치의 *조합*이 행동 차이를 만든다는 것이 핵심이다.

## 5. 자원 모델

| 자원 | 소유 | 저장 | 용도 |
|------|------|------|------|
| **Gold** | `NpcSaveData.Gold` (int) | NPC 샤드 | 구매, 강화, 파티 고용, 생활비 |
| **전투력 (Power)** | 계산값 | ✗ | 목표 난이도 판단, 결과 판정, 업그레이드 판단 |
| **전리품** | 기존 `NpcSaveData.Inventory` | NPC 샤드 | 판매, 장비 교체, 선물 |
| **소문 (Rumor)** | `NpcSaveData.Rumors` (상한 8) | NPC 샤드 | 목표 발견, 대화 토픽, 거짓 정보 |
| **평판 (Renown)** | `NpcSaveData.Renown` (int) | NPC 샤드 | 파티 모집력, 소문 신뢰도, 배신 억제 |

### 5.1 전투력 — 장비 반영 (P1 선행 조건)

- `NpcPower = 장비 점수 + 스킬 점수`. 장비 점수는 장착 장비의 `ComputedStats`를 요약한 값이다(공격·방어·생명력의 가중 합). [제안]
- **용기는 전투력에서 뺀다.** 용기는 "얼마나 위험한 목표를 고르는가"(위험 선호)에만 쓴다. 지금 용기가 전투력의 55%를 차지하는 구조로는 장비 업그레이드가 의미를 갖지 못한다.
- `GetPartyHuntPower`를 이 함수로 교체한다. 결과 판정 곡선은 기존 Hunt 밸런스와 맞도록 다시 정규화한다.
- 계산은 장비 변경 시점에만 다시 하고 런타임에 캐시한다. 저장하지 않는다.

### 5.2 소문 데이터 [제안]

```csharp
public enum NpcRumorKind { LootSpot, DungeonInfo, ItemOwner, Betrayal, PlayerDeed }

[Serializable]
public class NpcRumor
{
    public NpcRumorKind Kind;
    public int SubjectId;          // DungeonId / 소유 NpcId / 배신자 NpcId 등
    public float PositionX, PositionY;
    public int ValueEstimate;      // 예상 보상 (Gold 환산)
    public int Danger;             // 예상 위험도
    public bool IsTrue;            // 거짓 소문 여부 (전달자는 모름)
    public int SourceNpcId;        // 누구에게 들었나 (-1 = 직접 겪음)
    public float LearnedGameTime;
}
```

- NPC마다 **최대 8개**를 보관한다. 초과하면 가치가 가장 낮거나 가장 오래된 것부터 버린다.
- 소문은 기존 대화 토픽(`SettlementRumor`/`DangerRumor`/`Gossip`)의 **실제 데이터 소스**가 된다.

## 6. 목표 선택 (Utility)

### 6.1 평가 시점

- NPC가 **Idle로 전환될 때만** 평가한다(현행 `SelectNextActivity` 자리). 매 틱 평가하지 않는다.
- 결정론 RNG(`entityId, startGameTime, worldSeed`) 계약을 유지한다.

### 6.2 필요 (Needs)

| 필요 | 조건 | 올라가는 활동 |
|------|------|-------------|
| 장비 부족 | 지역 기준 전투력 대비 낮음 | 구매, 강화, 저위험 Hunt |
| 골드 부족 | Gold < 생활비 예비금 | Hunt, 전리품 판매 |
| 가방 가득 | 인벤토리 여유 ≤ 1 | 판매 |
| 부상 회복 직후 | Wounded 종료 후 N시간 | Rest, 저위험 활동 |
| 라이벌에게 뒤처짐 | Rival의 전투력·평판이 더 높음 | 강한 목표, 던전 |
| 유망한 소문 보유 | 가치 − 위험이 기준 이상인 Rumor | 해당 목표 원정 |

### 6.3 점수와 선택

```
Score(activity) = Σ Need × 필요 가중
                × Ambition 가중(주 1.0 / 보조 0.5)
                × Opportunity(소문·던전 슬롯·상점 매물 존재)
                × Risk 적합도(용기 vs 목표 위험)
```

- **최고점을 그대로 고르지 않는다.** 상위 3개 중 점수 가중 랜덤으로 고른다. 현행 구현처럼 같은 성향의 NPC도 행동이 다양하게 나오도록 하기 위해서다.
- GOAP 같은 계획형 AI는 2,400명 규모에서 비용이 커서 채택하지 않는다.

### 6.4 활동 카탈로그

## 7. 활동 상세

### 7.1 사냥 · 던전 원정

- **Hunt 보상 확장**: 기존 Food에 더해 **Gold와 전리품 롤**을 준다. 전리품 롤은 목표 지역의 몬스터 등급 × 전투력으로 결정한다. 개인 인벤토리가 가득 차면 가치가 가장 낮은 것은 즉시 판매로 처리한다.
- **DungeonDelve**: 소속 마을의 활성 던전 슬롯(`DungeonId`)을 **추상 대상으로만** 참조한다. [제안]
  - 일반 원정은 던전 내부 저장 상태(처치·상자)를 **바꾸지 않는다.** 보상은 던전 티어 기준의 Gold와 희귀 전리품이며, 위험은 Hunt보다 높다.
  - 결과는 `DungeonInfo` 소문으로 남아 퍼진다("○○ 던전에서 좋은 걸 건졌다").

**NPC 던전 완료 (낮은 확률)** [D5]

NPC 파티가 드물게 보스까지 잡아 던전을 **완료**할 수 있다. 완료되면 플레이어가 완료했을 때와 같이 입구가 사라지고, 같은 마을 주변에 다음 세대 입구가 생긴다([DUNGEON_RUNTIME §3.2](../map/DUNGEON_RUNTIME_DESIGN.md)). 마을마다 던전 2~3개가 유지되므로 **던전 수 자체는 줄지 않는다.** 플레이어가 잃는 것은 "그 던전"뿐이다. 그래서 보호 규칙은 플레이어가 **이미 투자한 던전**을 지키는 데 집중한다.

- **완료 확률**: DungeonDelve가 성공한 경우에만 따로 굴린다.
  - 기본 **3%**. 파티 전투력이 던전 티어 기준을 넘는 만큼 올라가되, 상한은 **8%**.
  - 전투력이 티어 기준에 못 미치면 0%.
- **보호 규칙** (하나라도 해당하면 완료 불가)
  - 플레이어가 **입장한 적 있는 던전**(`DungeonRecord`가 존재함). 진행과 상자 상태를 지킨다.
  - 플레이어가 **현재 던전 안에 있음**.
  - 해당 마을에서 **최근 72 게임시간 안에 NPC 완료**가 이미 있었음. 마을당 NPC 완료 쿨다운이다.
  - 해당 마을의 활성 입구 중 **절반 이상이 이미 NPC 완료로 교체된 세대**임. 한 마을 주변 던전이 전부 NPC 손에 넘어가지 않게 한다.
- **플레이어가 발견만 한 던전**(입장하지 않음)은 완료할 수 있지만, 확률을 절반으로 줄인다.
- **완료 처리**: 플레이어 보상 경로(`DungeonCompletionTransaction.TryStage`)는 플레이어 Gold를 지급하고 보스 처치가 기록된 `DungeonRecord`를 요구하므로 그대로 쓸 수 없다. **슬롯 단위 NPC 완료 진입점**을 따로 만든다.
  - 슬롯 `Generation`을 올리고 `PlacementPending`으로 바꾼다.
  - 이 변경과 NPC 보상을 **같은 저장 revision**에 커밋한다.
  - 플레이어 Gold는 건드리지 않는다.
- **가독성**
  - 사라진 입구 자리에 "누군가 공략을 끝냈다"는 흔적을 잠시 남긴다. [제안]
  - 완료한 NPC는 큰 Renown 상승, `NotableItemAcquired` Deed, 자랑 토픽을 얻는다.
  - 소문 "○○ 일행이 △△ 던전을 끝냈다"가 퍼진다.

### 7.2 상점 거래 — 재고 변경 + 빈도 제한 [D1]

NPC 거래는 플레이어와 **같은** `VillageData.MerchantStock`을 쓴다. 구매하면 `RemainingCount`가 줄고, 판매하면 매물이 늘어난다.

**구매 조건 (NPC 쪽)**
- 업그레이드 폭이 해당 슬롯 현재 점수의 **+15% 이상**일 때만 산다. 소소한 교체로 재고를 소모하지 않게 하기 위해서다. 개인 상한의 80%를 넘은 NPC는 +30%가 필요하다(§10.1).
- 사고 나서 자기 **개인 상한**을 넘게 되는 매물은 사지 않는다(§10.1).
- 가격 ≤ Gold − 생활비 예비금.
- NPC별 쇼핑 쿨다운 **48 게임시간**.

**상점 보호 (재고 쪽)**
- 한 상점의 NPC 구매는 **재입고 회차당 최대 매물 종류의 25%** 로 제한한다(최소 1, 최대 3).
- 한 상점의 NPC 구매 트랜잭션은 **게임시간 6시간당 1건**으로 제한한다. 여러 NPC가 동시에 귀환해도 재고가 한 번에 비지 않는다.
- **희귀·특수 슬롯**은 재입고 간격의 **50%가 지난 뒤에만** NPC가 살 수 있다. 플레이어가 먼저 볼 기회를 보장한다.

**판매 → 매물 추가**
- NPC가 판 전리품 중 가치가 높은 것은 **"모험가 매입품" 슬롯**(회차당 최대 2개)으로 진열된다. 다음 재입고 때 사라진다.
- 이것이 NPC가 던전에서 가져온 물건이 플레이어 손에 들어오는 주 경로다.

**가독성**
- 품절 매물에 "○○가 구매함"을 표시한다. 상인 대사로 "○○가 어제 그 검을 사 갔소"를 넣는다.

**LOD**
- 오프스크린 마을도 같은 트랜잭션을 쓴다. 해당 회차 재고가 아직 롤되지 않았다면 먼저 롤한다(`VillageTradeStockRoller`가 결정론이므로 안전하다).
- 빈도 제한 덕분에 총 트랜잭션 수는 마을 수 × 소수로 묶인다.

### 7.3 강화 · 제작

- 기존 Forge 마법부여(`ItemEnchantmentTransaction`)를 NPC 장비에 적용한다. 비용은 NPC Gold로 낸다.
- **부 · 안전** 야망은 구매보다 강화를 선호하고, **명예 · 탐험** 야망은 구매를 선호한다.
- 마을에 Forge 시설이 없으면 후보에서 뺀다(서비스는 건물이 제공한다는 경계 원칙).

### 7.4 소문

- **획득**: 원정 결과(직접 겪음), 여관 교환(들음), 플레이어 행동 목격.
- **교환**: Rest 판정 때 같은 마을의 Idle NPC 중 최대 2명과 소문을 1개씩 교환한다. 친화력이 높을수록 교환 상대가 늘고, 호기심이 높을수록 받아들이는 비율이 높아진다.
- **거짓 소문**: 정직이 낮은 NPC는 일정 확률로 `ValueEstimate`를 부풀리거나 `Danger`를 줄여 전달한다(`IsTrue = false`). 주로 라이벌이나 원한 관계 상대에게 쓴다.
- **확인**: 호기심이 높은 NPC는 소문 목표로 원정을 간다. 거짓으로 드러나면 출처 NPC와의 호감도가 떨어지고 `Betrayal` 소문이 생긴다.

### 7.5 협력 (파티)

- **모집**: 목표 위험이 개인 전력을 넘으면 Recruit를 실행한다. 후보 점수 = 호감도 + 전투력 + 평판 − 원한.
- **분배 약속**: 출발 전에 리더 성격에 따라 정한다. 이 약속을 지키는지가 배신 판정의 기준점이 된다.
  - 균등 분배: 동료 야망 리더
  - 기여도 분배: 명예·부 야망 리더
  - 리더 우선: 자존심이 높은 리더

### 7.6 NPC 간 배신 · 절도

**배신** — 파티 결과 판정 시점에 한 번 평가한다.

```
BetrayalScore = Greed×a + (100−Loyalty)×b + (100−Honesty)×c
              + 전리품 가치 비율×d
              − 파티원 호감도×e − 평판 손실 예상×f − 충성 높은 증인 수×g
```

| 유형 | 성향 | 결과 |
|------|------|------|
| 분배 속이기 | 탐욕↑ | 약속보다 많이 가져감 |
| 위기 이탈 | 용기↓ | 원정 실패 시 동료의 부상·사망 확률 상승 |
| 선점 | 정직↓ 호기심↑ | 공유한 소문의 목표를 혼자 먼저 털어감 |

- **발각**: 증인과 피해자 생존 여부로 판정한다. 발각되면 원한 관계가 생기고, 평판이 떨어지고, `Betrayal` 소문이 퍼진다. 피해자는 복수나 파티 기피 성향을 얻는다.

**절도 (NPC 간)** [D4] — 마을 체류 중에만 발생한다.
- **조건**: 기회 야망이면서 `ItemOwner` 소문으로 표적 아이템을 알고 있을 때.
- **판정**: 성공하면 아이템이 피해자 인벤토리에서 절도자에게 옮겨간다(장착 중인 장비는 대상이 아니다). 발각 여부는 피해자의 호기심과 인내, 같은 마을의 증인 수로 정한다.
- **발각되면 — 관계가 틀어진다**
  - 피해자와의 호감도가 크게 떨어지고 **원한** 관계가 생긴다.
  - 피해자와 친구·가족 관계인 NPC들도 절도자에 대한 호감도가 조금 떨어진다. 관계망을 타고 번진다.
  - `Betrayal` 소문이 퍼지고, 절도자의 Renown이 떨어진다.
  - 피해자는 절도자와 **같은 파티에 들어가지 않는다.** 복수 성향이 강하면 결투를 신청할 수 있다(§8.8의 NPC 간 결투).
- **발각되지 않으면**: 피해자는 도둑맞은 사실만 알고 범인은 모른다. 이후 `ItemOwner` 소문으로 그 아이템을 가진 NPC를 알게 되면 그때 관계가 틀어진다. 늦게 드러나는 드라마다.
- 추방 같은 제도적 처벌은 두지 않는다. 결과는 **관계** 안에서 일어난다.
- 세계 전체 빈도 상한과 NPC별 쿨다운을 둔다. Oblivion Radiant AI의 연쇄 혼란 사례를 피하기 위해서다.

## 8. 플레이어와 NPC 사이의 배신 · 결투 [D2, D6, D7]

배신은 양방향이다. NPC가 플레이어를 배신할 수 있고(§8.3~8.7), 플레이어도 NPC를 배신할 수 있다(§8.9). 결투(§8.8)는 양쪽 모두의 해결 수단이다.

### 8.0 선행 조건 — NPC 실전투 기반 → [NPC_COMBAT_DESIGN.md](NPC_COMBAT_DESIGN.md)

동행, 위기 이탈, 결투는 NPC가 **화면 안에서 실제로 싸워야** 성립한다. 현재 NPC는 전투 부품만 있고 싸우지 않는다(적 인식 건너뜀, 진영 없음).

실전투의 **런타임 메커니즘**은 별도 문서 [NPC_COMBAT_DESIGN.md](NPC_COMBAT_DESIGN.md)가 소유한다.
- 진영 명시, 결투 상대 한정 적대, 조건부 인식
- 동행 중 추종·순간이동·아군 피해 없음·던전 동반 [D13, D14]
- 도주 전환, 드랍 줍기, 결투 진행·무릎 꿇기, 전투 사망 연결

본 문서는 *언제, 왜* 싸우는지와 *그 결과*(동행 제안·정산, 배신 판정, 결투의 명분·응답·드랍·관계 파장)를 소유한다. 실전투 기반은 P1~P4와 독립적으로 진행한다(§13 P5-0).

### 8.1 전제 — 임시 동행 (Joint Venture)

배신하려면 먼저 함께 행동해야 한다. **1회성 동행**을 도입한다. 영구 동료는 companionSystem 소관으로 남긴다.

- **시작**: NPC가 소문 목표를 들고 먼저 제안하거나, 호감도 단계가 충분할 때 플레이어가 요청한다.
- **분배 약속 선택**: 균등 / 기여도 / 먼저 줍는 사람. 플레이어가 고르거나 NPC가 제안한다.
- **진행**: NPC는 실체화된 상태로 플레이어를 따라다니며 싸운다(사냥 지역 또는 던전).
- **종료**: 목표 달성, 귀환, 또는 **배신**.
- **정산**: 동행이 정상 종료되면 **분배 정산 창**이 뜬다. 동행 중 각자 주운 전리품이 나열되고, 약속에 따라 넘겨야 할 몫이 표시된다. 플레이어가 자기 몫이 아닌 것을 넘겨줄지 **직접 고른다.** 플레이어의 배신은 주로 이 자리에서 일어난다(§8.9).

### 8.2 절대 규칙

- **플레이어 인벤토리·장비·보관함의 아이템은 어떤 경로로도 가져가지 않는다.** [확정: D2]
- 배신은 **아직 누구의 것도 아닌 것**(바닥의 드랍, 보물상자, 공동 목표의 보상)과 **약속·신뢰**를 대상으로만 한다.

### 8.3 배신 유형 (가벼운 것 → 무거운 것)

| # | 유형 | 무엇을 하나 | 성향 | 참고 |
|---|------|-----------|------|------|
| 1 | **전리품 가로채기** | 약속을 어기고 바닥 드랍이나 상자를 먼저 주워 동행을 끝내고 떠남 | 탐욕↑ 용기 보통 | — |
| 2 | **위기 이탈** | 플레이어 HP가 낮거나 보스 페이즈에 들어가면 도주해 혼자 남김 | 용기↓ 충성↓ | Dragon's Dogma |
| 3 | **약속 불이행·선점** | 약속한 합류 시각에 나타나지 않고, 함께 얻은 정보로 목표를 먼저 털어감(오프스크린 처리) | 정직↓ 호기심↑ | — |
| 4 | **거짓 정보** | 위험을 줄여 말한 소문으로 플레이어를 강한 몬스터 지역에 유도 | 정직↓ 자존심↑(라이벌 의식) | 네메시스 |
| 5 | **평판 공격** | 동행 후 플레이어를 헐뜯는 거짓 소문을 퍼뜨림 → 다른 NPC들의 Trust 소폭 하락 | 정직↓ 친화 보통 | — |
| 6 | **보상 앞 결투** | 보스 처치 직후 보상 상자 앞에서 "이건 내 몫이다"라며 결투를 걸어옴(§8.8) | 탐욕↑ 용기↑ 충성↓ | 다크소울 패치스 |

유형 6은 **보스급 보상 + 극단적 성격 조합**에서만 열린다. 가장 드물게 나와야 한다. 기습이 아니라 **결투 선언**으로 시작해서 플레이어가 대응할 틈을 준다.

### 8.4 판정

- **시점**: 이벤트로만 평가한다. 드랍 발생, 상자 열기 직전, 보스 처치, 플레이어 HP 임계, 동행 종료. 매 틱 평가하지 않는다.
- **점수**: §7.6 공식에서 NPC 간 호감도를 **플레이어 관계**(`Affinity`, `Trust`)로 바꾼다. 호감 단계가 높으면 사실상 0이 되도록 억제 계수를 크게 둔다.
- **유형 선택**: 점수가 임계를 넘으면 성격으로 유형을 고른다(위 표의 "성향" 열).

### 8.5 복선 — 공정하게 배신하기

배신은 **예측할 수 있었어야** 재미가 있다. 이유 없이 당하면 억울하기만 하다.

- **제안 대사 톤**: 탐욕이 높은 NPC는 보상 얘기를 많이 한다(기존 `PersonalityBias` 활용).
- **동행 중 짧은 말(bark)**: "저 상자… 꽤 값나가 보이는군." 배신 점수가 높을수록 자주 나온다.
- **소문**: 이 NPC의 과거 배신은 `Betrayal` 소문으로 다른 NPC에게서 들을 수 있다.
- **검사 UI**: `UINpcInspect`에 성격 일부를 노출한다. Trust가 높을수록 더 많이 보인다.

### 8.6 결과와 대응

| 결과 | 내용 |
|------|------|
| 관계 | 플레이어 관계 Trust 급락, Affinity 하락. 유형 6이면 Fear도 변동 |
| 평판 | 배신 NPC의 Renown 하락, `Betrayal` 소문 전파 → 다른 NPC가 그 NPC와 파티를 기피 |
| 기록 | 배신 NPC와 플레이어 양쪽 Deeds에 기록 → 이후 대화 토픽 |
| 플레이어 선택지 | **추궁**(대화로 전리품 반환이나 사과 요구 — 자존심이 낮으면 응함), **용서**(Affinity 일부 회복), **결투**(§8.8 — 패배한 배신자를 처단하거나 살려줄 수 있음) |
| 후일담 | 자존심이 낮은 배신자는 나중에 사과하며 보상을 건넬 수 있음(패치스 방식) |

### 8.7 빈도 안전장치

- 같은 NPC가 플레이어를 배신하는 것은 **1회**까지다. 관계가 복구되기 전에는 동행 제안이 불가능하다.
- **세계 전체**에서 플레이어 대상 배신은 게임시간 **7일에 1회**로 제한한다.
- 플레이어의 **첫 동행 2회**에서는 배신하지 않는다. 동행 시스템에 먼저 익숙해지게 하기 위해서다.

### 8.8 결투 (Duel) [D6]

플레이어가 NPC를 죽일 수 있는 **유일한 경로**다. 평소에는 NPC를 공격할 수 없다는 원칙을 유지하고, 결투라는 명시적 절차 안에서만 생사를 건 싸움을 허용한다.

결투는 **아무 NPC에게나** 신청할 수 있다 [D7]. 대신 **명분**이 있느냐에 따라 상대의 응답과 세상의 반응이 완전히 달라진다.

**명분 (Grievance)**

| 등급 | 조건 | 예 |
|------|------|----|
| **명분 있음** | 그 NPC가 **플레이어에게 직접** 잘못한 기록(Deed)이 있다 | 배신 유형 1~6을 당함 |
| **약한 명분** | 그 NPC의 잘못을 **소문으로만** 안다(플레이어가 피해자가 아님) | "○○가 동료를 버렸다"는 `Betrayal` 소문 |
| **명분 없음** | 위 둘 다 아님 | 좋은 장비를 가진 NPC, 이유 없는 도발 |

명분은 **플레이어와 목격자가 무엇을 알고 있는가**로 판정한다. 세계의 객관적 진실이 아니다. 소문 기반의 per-NPC 지식 원칙(§7.4)을 그대로 따른다.

**신청 경로**

| 경로 | 조건 |
|------|------|
| 플레이어 → 아무 NPC | 대화 메뉴에 **"결투 신청"** 이 항상 뜬다. 명분이 없으면 확인 창을 한 번 더 띄운다("이유 없이 싸움을 거는 것은 배신으로 여겨질 수 있습니다") |
| NPC → 플레이어 | 배신 유형 6, 또는 **플레이어에게 배신당한 NPC**(§8.9)가 자존심·용기가 높을 때. 플레이어는 받거나 거절할 수 있다 |
| NPC → NPC | 절도나 배신을 당한 NPC 중 자존심·용기가 높은 쪽이 신청한다. 오프스크린에서 추상 판정한다 |

**신청 불가 상태** — 명분과 관계없이 적용한다. 이 상태 외에 **결투에서 보호되는 NPC는 없다** [D8]. 진행 중인 소망이 있는 NPC가 죽으면 그 소망은 실패로 처리한다.
- 상대가 부상(Wounded) 상태이거나 원정 중이다.
- 상대가 지금 플레이어와 **동행 중**이다. 동행을 먼저 끝내야 한다.
- 같은 NPC에게 결투를 신청한 지 72 게임시간이 지나지 않았다.

**NPC의 응답 (플레이어가 신청한 경우)**

| 명분 | 응답 |
|------|------|
| 명분 있음 | **수락**(자존심·용기↑) / **배상 제안**(용기↓ — 가로챈 것이나 골드를 내놓으며 빈다. 받으면 결투 취소) / **도주**(용기↓ 정직↓ — 잠적. "비겁자" 소문이 퍼지고 Renown이 크게 떨어진다. 다시 마주치면 거절할 수 없다) |
| 약한 명분 | 해명하거나(정직↑이면 소문이 거짓이었다고 반박할 수 있다) 수락한다. 거절해도 비겁자 소문은 약하게만 퍼진다 |
| 명분 없음 | **명예 야망**이나 자존심이 매우 높은 NPC는 도전으로 여겨 수락한다. 나머지는 **거절**하고, 거절해도 NPC에게 불이익이 없다. 신청했다는 사실만으로 그 NPC의 플레이어 Trust와 Affinity가 떨어진다. 가까운 사이였다면 이것 자체가 **배신**으로 기록된다(§8.9) |

**진행 규칙** — 결투 영역, 1:1 보장, 결투 쌍 적대, 이탈 기권, 무릎 꿇기, 세이브 금지 등 **런타임 진행**은 [NPC_COMBAT_DESIGN §7](NPC_COMBAT_DESIGN.md)이 소유한다. 본 절은 결과 처리 훅(§7.4)이 넘겨준 정보로 아래 결과·드랍·파장을 적용한다. 입회인은 결과를 목격 소문으로 퍼뜨린다.

**결과**

| 결과 | 처리 |
|------|------|
| 플레이어 승리 | 상대의 HP가 0에 가까워지면 **무릎을 꿇는다.** 플레이어가 고른다 → **처단**: `MarkNpcDead` 경로로 사망 처리 / **자비**: 명분이 있었다면 상대가 가로챈 것을 돌려주고 관계가 "빚진 사이"로 재설정된다. 이후 다시 배신할 확률이 크게 낮아진다. 명분이 없었다면 상대는 굴욕을 기억하고 원한을 갖는다 |
| 플레이어 패배 | 플레이어는 죽지 않고 **HP 1로 쓰러진다.** 상대의 자존심이 오르고 "모험가를 꺾었다"는 소문이 퍼진다. 명분 있는 결투였다면 배신자는 전리품을 확정적으로 갖는다. 플레이어의 인벤토리와 장비는 가져가지 않는다(§8.2). 72 게임시간 뒤 재도전할 수 있다 |
| NPC 간 결투 | 전투력으로 추상 판정한다. 패자는 부상을 입고, 드물게(자존심이 높은 승자일 때) 사망한다 |

**처단 시 떨어지는 것**

| 명분 | 드랍 |
|------|------|
| 명분 있음 | 가로챈 전리품 전부 + 장비 일부 |
| 약한 명분 | 장비 일부 |
| 명분 없음 | **없음.** 유품은 가족이나 친구에게 넘어간다. 가족이 없으면 마을 상점의 모험가 매입품 슬롯에 나온다 |

명분 없는 처단에서 장비를 얻을 수 없게 하는 이유: 좋은 장비를 가진 NPC를 결투로 사냥하는 것이 최적 전략이 되면 NPC 사회가 무너진다. 명분 없는 결투는 **이익이 아니라 감정과 선택의 수단**으로만 남긴다.

**처단 이후 — 관계의 파장**

| 명분 | 목격자·마을의 반응 |
|------|------------------|
| 명분 있음 + 배신이 소문으로 알려져 있음 | **정당하다**고 본다. 큰 관계 페널티가 없다. 오히려 일부 NPC의 Trust가 오른다 |
| 명분 있음 + 배신이 알려지지 않음 | 목격자들의 플레이어 Fear가 오르고 Affinity가 조금 떨어진다 |
| 약한 명분 | 목격자들의 Fear가 오른다. 소문을 믿지 않던 NPC(정직↑, 죽은 NPC와 친한 사이)는 Affinity가 크게 떨어진다 |
| 명분 없음 | **"살인자" 소문**(`PlayerDeed`)이 퍼진다. 이 소문을 아는 NPC는 플레이어 Fear↑ Affinity↓ Trust↓. 동행 제안을 거절하고, 겁이 많으면 플레이어를 피한다. 반복될수록 소문이 더 멀리 퍼진다 |

- 마을 단위 "악명 수치"는 두지 않는다. 반응은 **소문을 알게 된 NPC 각자**에게서 일어난다. 먼 마을에서는 아직 모를 수 있다.
- 죽은 NPC의 **가족과 친구**는 명분과 관계없이 플레이어에게 원한을 갖는다(기존 `DeceasedRelationMemory` 경로). 이들이 나중에 복수 결투를 신청해 올 수 있다. 명분 없는 처단이었다면 이들의 복수 결투는 **명분 있음**으로 취급한다.

**안전장치**
- 결투 신청 대상은 제한하지 않는다 [D7]. 대신 명분 없는 결투는 드랍 없음(위 표)과 관계 페널티로 억제한다.
- 세이브 금지·회복 수단 사용 등 진행 중 규칙은 [NPC_COMBAT_DESIGN §7.2](NPC_COMBAT_DESIGN.md).

### 8.9 플레이어가 NPC를 배신하기 [D7]

NPC가 플레이어를 배신할 수 있듯이, 플레이어도 NPC를 배신할 수 있다. 시스템은 플레이어의 선택을 막지 않고, **NPC가 그것을 기억하고 반응**하게 한다.

**배신으로 기록되는 행동**

| # | 행동 | 판정 시점 | NPC가 알아채는가 |
|---|------|----------|----------------|
| 1 | **정산 거부** | 동행 종료 정산 창에서 약속된 몫을 넘기지 않음 | 항상 |
| 2 | **약속 불이행** | 합류 약속 시각에 나타나지 않음 | 항상 |
| 3 | **명분 없는 결투 신청** | 가까운 사이(호감 단계 높음)인 NPC에게 명분 없이 결투를 신청함 | 항상 |
| 4 | **동료 처단** | 명분 없이 결투에서 처단함 | 죽은 NPC의 가족·친구·목격자 |

- 배신 1~3의 피해자는 살아 있으므로, 그 NPC가 직접 반응한다. 4는 주변이 반응한다.
- "위기에 버리기"(전투 중 동행 NPC를 두고 멀어짐)는 배신으로 판정하지 않는다 [D9]. 거리·HP 기준이 애매해서, 플레이어가 의도하지 않은 이동까지 배신으로 잡힐 수 있기 때문이다.
- 플레이어의 배신은 §8.7의 빈도 제한을 받지 않는다. 플레이어의 선택이기 때문이다.

**NPC의 반응 — 성격으로 갈린다**

| 성향 | 반응 |
|------|------|
| 자존심↑ 용기↑ | 플레이어에게 **결투를 신청**한다(명분 있음). 거절하면 "비겁한 모험가" 소문을 퍼뜨린다 |
| 정직↓ 탐욕↑ | **되갚기**: 이후 배신 유형 3~5(선점·거짓 정보·평판 공격)를 쓸 확률이 크게 오른다. 이때는 §8.7의 세계 쿨다운을 적용하지 않는다(복수는 정당한 동기다) |
| 용기↓ | 플레이어를 **피한다.** 말을 걸면 짧게 대답하고, 동행 제안을 거절한다 |
| 충성↑ 친화↑ | 크게 상처받는다. Affinity가 매우 크게 떨어지지만, 사과와 선물로 **회복할 여지**를 남긴다 |

**공통 결과**
- 피해 NPC의 플레이어 Trust가 급락하고 Affinity가 떨어진다. `TrustCap`이 낮아져 한동안 신뢰를 완전히 회복할 수 없다.
- `Betrayal` 소문(대상 = 플레이어)이 피해자의 관계망을 타고 퍼진다. 이 소문을 아는 NPC는 동행 제안을 망설이고, 동행하더라도 **먼저 줍는 사람** 분배를 요구한다.
- 피해자와 플레이어 양쪽 Deeds에 기록된다. 이후 대화에서 그 일을 꺼낸다.

**되돌리기**
- **사과**: 대화 메뉴에서 사과하고, 넘기지 않은 몫이나 그에 준하는 골드를 건넨다. 정직과 충성이 높은 NPC일수록 쉽게 받아준다.
- **시간**: 오래 지나면 소문의 영향이 약해진다. 다만 피해자 본인의 기억(Deed)은 사라지지 않는다.

## 9. 골드의 마을 유입 (약하게) [D3]

- **거래세**: NPC가 상점에서 사고팔 때 거래액의 **5%** 가 그 마을의 Gold 자원으로 들어간다.
- **생활비**: Rest 중 여관비(소액)의 **50%** 가 마을 Gold로 들어간다.
- **상한**: 마을별 게임일(24h)당 NPC 유래 Gold 유입은 **그 마을 인구 기반 Gold 생산량의 15% 이하**로 제한한다(`VillageResourceSimulation` 기준).
- **입력 금지 유지**: NPC 골드는 **Gold 자원으로만** 합류한다. Population, Tier, 건설 후보 점수에는 직접 입력하지 않는다(경계 문서 §8 유지).
- **추상·실시간 일치**: 이 유입은 추상 시뮬레이션과 실시간 경로에 **같은 식**으로 들어가야 한다(`VillageSimulationParity` 대상에 추가).
- **참고**: 현재 코드에서 마을 Gold는 누적(상한 없음)만 확인되고, 건설 규칙에서 Gold 소비처는 찾지 못했다. 당장의 실질 영향은 작다. 앞으로 Gold 소비처가 생기면 15% 상한을 다시 검토한다. [src: Assets/Scripts/Village/VillageResourceSimulation.cs]

## 10. 안전장치 · 밸런스

### 10.1 성장 곡선 — "초반엔 NPC가 강하고, 플레이어가 역전한다" [D10]

**기조**: NPC는 게임 시작 시점에 플레이어보다 강하다. 그리고 **거의 강해지지 않는다.** 운이 좋을 때만 가끔 한 단계 오른다. 플레이어는 꾸준히 성장하므로 **NPC를 쫓아가 따라잡는 맛**이 생긴다. **이 추격과 역전의 체감이 플레이어 재미의 기본**이다. 본 문서의 모든 성장 규칙은 이 기조보다 아래에 있다.

**성장 모델 — 거의 평탄, 가끔 계단** [D11]

```
전투력
  │                               ╱ 플레이어 (꾸준히 성장)
  │                             ╱
  │            ┌──────── 운 좋은 NPC (드물게 한 계단)
  │  ──────────┘─────────╱────── 대부분의 NPC (거의 그대로)
  │  NPC 시작값        ╱ ↑ 따라잡음
  │                  ╱
  │  플레이어 ─────╱
  └──────────────────────────────────▶ 게임 시간
```

- **NPC 전투력을 시간에 따라 강제로 올리지 않는다.** 기준선도, 정해진 성장 속도도 두지 않는다.
- 전투력이 오르는 경로는 **실제로 좋은 아이템을 손에 넣었을 때** 하나뿐이다. 그런 일이 드물게 일어나도록 만든다(아래 장치).
- 대부분의 NPC는 생성 시점의 전투력 근처에 머문다. 오르지 않은 채로 은퇴하거나 죽는 것도 정상이다.
- 초반·중반·후반 같은 구간 목표도 두지 않는다. 플레이어가 언제 누구를 따라잡는지는 **그 NPC의 시작 전투력과 운**이 정한다.

**금지: 고무줄 보정(rubber banding)**
- NPC 성장은 **플레이어 전투력에 연동하지 않는다.** 플레이어가 강해졌다고 NPC도 따라 강해지면 추격하는 맛이 사라진다.
- 세계 경과 시간에 따라 자동으로 강해지는 규칙도 두지 않는다.
- 플레이어 전투력은 튜닝용 진단과 대화 연출(아래)에만 쓰고, NPC 성장 판정에는 넣지 않는다.

**성장을 "드문 행운"으로 만드는 장치**

| 장치 | 내용 |
|------|------|
| **보상은 지역 기준** | 원정 전리품의 등급은 **목표 지역·던전 티어**로만 정한다. NPC는 생성될 때 이미 주변 지역에 맞는 장비를 갖고 있으므로, 평소 전리품은 대부분 업그레이드가 아니라 **판매용**이 된다 |
| **희귀 행운** | 업그레이드가 되는 전리품은 희귀 드랍, 던전 완료 보상(§7.1, 3~8%), 상점의 좋은 매물을 싸게 만났을 때처럼 **운이 따른 사건**에서만 나온다 |
| **업그레이드 문턱** | 장비를 바꾸는 조건이 +15% 이상이라, 조금 나은 아이템으로는 전투력이 오르지 않는다(§7.2) |
| **개인 상한** | NPC 전투력은 **생성 시점 전투력 × (1 + 개인 편차)** 를 넘지 않는다. 편차는 평범한 NPC가 +20%, 강자가 최대 +50%다. 상한의 80%를 넘으면 업그레이드 문턱이 +30%로 올라간다. 아무리 운이 좋아도 한 NPC가 끝없이 강해지지는 않는다 |
| **구매 제한** | NPC는 자기 개인 상한을 넘는 매물을 사지 않는다. 좋은 매물은 플레이어 몫으로 남는다 |
| **스킬 성장** | `SkillLevel` 상승은 주요 사건(던전 완료, 결투 승리)에서만, 드물게 일어난다 |
| **소모처** | 사망(장비 소실), 강화 비용·실패, 생활비, 파티 고용비, 장비 교체 시 구 장비의 헐값 판매 |
| **세대 교체** | 전역 총량 보충(`TryReplenishGlobalPopulation`)으로 들어오는 신규 NPC는 **생성 규칙 그대로의 장비**로 시작한다. 운 좋게 강해진 NPC가 죽으면 그 자리를 평범한 신참이 채운다 |

- 골드와 전리품을 모으는 루프(§3)는 그대로 돌아간다. 다만 그 결과는 대부분 **생활, 거래, 소문, 관계**로 흘러가고, 전투력으로 이어지는 일은 드물다. NPC가 "강해지려고 애쓰는 모습"은 보이지만 실제로 강해지는 일은 드물다.

**운 좋게 강해진 NPC**
- 계단을 오른 NPC는 그 자체로 **이야기**가 된다. "○○가 던전에서 전설급 검을 얻었다"는 소문이 퍼지고, Renown이 오르고, 자랑 토픽이 생긴다.
- 이들은 플레이어가 한동안 쫓아가야 하는 **목표**이자 결투 상대, 라이벌이 된다. 개인 상한이 있으므로 플레이어가 꾸준히 성장하면 결국 따라잡는다.

**역전을 체감하게 하는 연출**

구간을 나누지 않고 **그 NPC와 플레이어의 전투력을 직접 비교**해서 반응을 바꾼다.

| 비교 | 반응 |
|------|------|
| NPC가 훨씬 강함 | 플레이어를 "풋내기"로 대한다. 동행하면 NPC가 목표를 정하고 이끈다 |
| 비슷함 | 대등한 동료로 대한다. 라이벌 의식이 생긴다 |
| 플레이어가 훨씬 강함 | 존중하거나 경외하고, 겁이 많으면 두려워한다. NPC가 플레이어에게 동행을 부탁한다 |

- 명예 야망 NPC는 자기보다 강해진 플레이어에게 결투를 청해 온다("한 수 배우고 싶다").
- 이 비교는 **연출에만** 쓴다. NPC 성장에는 영향을 주지 않는다(고무줄 보정 금지 원칙).

**튜닝 진단** [제안]
- 에디터 진단 도구로 게임 시간 경과에 따른 세계 NPC 평균 전투력, 상위 2% 전투력, **업그레이드 사건 발생 수**를 기록한다.
- 확인할 것: 평균이 **거의 평탄**한가(예: 게임 30일 동안 평균 상승 +10% 이내 [제안]). 업그레이드 사건이 드문가. 어떤 NPC도 개인 상한을 넘지 않는가.
- NPC 기능을 추가하는 각 단계는 **이 평탄함을 깨지 않는 것**을 완료 조건에 포함한다(§13).

### 10.2 전투력 인플레이션 · 유품

- **자연 상한**: NPC가 살 수 있는 매물 티어는 **그 마을 상점의 티어**가 제한한다. 더 강해지려면 더 큰 마을로 이주해야 한다(NS4와 연결).
- **유품** [제안]: NPC가 사망한 원정 목표 지점에 장비 일부를 월드 드랍으로 남긴다. 플레이어가 "쓰러진 모험가의 검"을 발견하는 경로가 된다 → 열린 질문 Q3.

### 10.3 가독성

화면 밖 사건은 **최소 1개의 관측 경로**를 가져야 한다. 관측 경로가 없는 사건은 만들지 않는다.

| 사건 | 관측 경로 |
|------|----------|
| NPC 구매·판매 | 상점 품절 표시, 모험가 매입품 슬롯, 상인 대사 |
| 원정 성과 | 장비 외형 변화, `NotableItemAcquired` Deed, 자랑 토픽(`Boast`) |
| 배신·절도 | `Betrayal` 소문, 관계 변화, Deeds, 검사 UI |
| 거짓 소문 | 확인 원정 실패 후 원한 대사 |

## 12. 저장 · LOD · 성능

- **NpcSaveData 추가**: `Gold`, `Renown`, `Rumors`(≤8), `LastTradeGameTime`, `PlayerBetrayalDone`, `DuelState`(없음/도주 중/자비 받음), `LastDuelGameTime`. 모두 NPC 샤드에 저장한다.
- **VillageData 추가**: 회차별 `NpcPurchaseCount`, `LastNpcTradeGameTime`, 일별 `NpcGoldInflowToday`, 모험가 매입품 슬롯.
- **Dungeon 파티션 추가**: 마을별 `LastNpcCompletionGameTime`, 슬롯별 "NPC 완료로 교체된 세대" 표시.
- **세계 상태**: 플레이어 대상 배신 쿨다운, 동행 횟수, NPC별 결투 신청 쿨다운. World 파티션에 저장한다.
- **플레이어 관련 기억**: 플레이어의 배신과 명분 없는 처단은 별도 전역 수치 없이 NPC별 `Rumors`(`Betrayal`/`PlayerDeed`)와 Deeds, `PlayerRelation`에만 남는다.
- **LOD**: 동행, 배신 연출(유형 1, 2, 6), 플레이어 결투는 실체화 상태에서만 일어난다. NPC 간 결투와 나머지는 모두 오프스크린에서 종료 시점 1회 판정한다.
- **성능**: 평가는 Idle 전환 때만, 소문 교환은 NPC당 최대 2명, 상점 트랜잭션은 빈도 제한으로 묶인다. 2,400명 규모에서 틱당 추가 비용은 상수 수준을 목표로 한다.
