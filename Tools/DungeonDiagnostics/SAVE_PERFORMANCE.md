# 저장 성능 최적화 결과 — 2026-09-19

저장 경계는 다음과 같이 정리됐다.

- 메인 스레드: Unity/ECS 상태 캡처, 독립 DTO 복사, manifest 원자 교체와 상태 확정
- 백그라운드: JSON 직렬화, UTF-8 변환, SHA-256, 파티션/manifest 임시 파일 쓰기,
  이전 revision 및 미완성 임시 파일 정리
- 저장 준비와 정리는 하나의 파일 작업 lane을 사용하므로 이전 정리와 다음 저장이 겹치지 않는다.
- 정리 실패는 커밋된 저장을 실패로 바꾸지 않으며 다음 성공 저장에서 다시 정리한다.
- Reset과 Load는 진행 중인 저장·정리를 생명주기와 파일 작업 경계에서 기다리거나 취소한다.

2026-09-19 Unity Editor 합성 진단의 단일 표본은 다음과 같았다. 9개 방 던전과
합성 NPC 2,400개를 사용했으며 실제 플레이 데이터 분포나 ECS 매니저 캡처 비용을
대표하지 않는다.

| 범위 | 메인 캡처 | 백그라운드 준비 | 메인 커밋 |
| --- | ---: | ---: | ---: |
| `SaveScope.All` | 230.70 ms | 994.74 ms | 3.08 ms |
| Player + World + Dungeons | 0.68 ms | 9.24 ms | 2.14 ms |

일반 던전 체크포인트의 메인 스레드 저장 작업은 작아졌지만, `SaveScope.All`의 독립 DTO
복사는 여전히 메인 스레드 hitch가 될 수 있다. 던전 완료의 `_busy`도 보상·완료·슬롯
rollback 경계를 보호하기 위해 저장 완료까지 유지한다. 실제 월드 규모의 프레임 시간과
체감 정지는 Play Mode Profiler로 확인해야 한다.

반복 진단은 `ARPG > Dungeon > Run Storage and Generation Diagnostics` 메뉴에서 수행한다.
진단 사용법과 범위는 같은 폴더의 `README.md`를 따른다.
